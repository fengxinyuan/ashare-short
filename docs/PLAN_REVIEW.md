# Plan Review — 六处必须避开的设计错误

这份文档固化一次方案评审的结论。AI 生成的「终极实盘闭环版」方案里有六处错误，其中两处是 A 股交易规则层面的**逻辑不成立**，不是参数调优问题。写在这里是为了防止后续再被同类方案带偏。

---

## 1. 09:20-09:25 不接受撤单，撤单率公式不成立（致命）

错误写法：

```text
R_withdraw = (BidAmount_09:24:30 - BidAmount_09:24:58) / BidAmount_09:24:30
```

A 股集合竞价 **09:20-09:25 期间交易所不接受撤单**。该窗口内买盘挂单量不会因撤单下降，这个比值恒约等于 0，或只反映价格档位漂移，**无法识别诱多**。

**正确做法**：撤单率只能定义在 **09:15-09:19:59** 这个可撤单窗口，且需要数据源提供逐笔委托或撤单记录。

- 规范：`docs/L2_SIGNAL_SPEC.md`
- 字段：`AuctionFeatures.cancel_pre920_ratio`
- 阈值：`AuctionRiskConfig.cancel_pre920_warn` / `cancel_pre920_block`

## 2. 「09:25:02 推送卡片 → 1.5 秒点击下单」在时序上是事后动作（致命）

09:25 集合竞价已经撮合完毕、开盘价已定。09:25:02 才推送，此时下单**无法参与集合竞价**：沪市 09:25-09:30 不接受申报，深市虽接受但订单只进缓冲区、开盘后才进连续竞价。

这条链路实际产出的是一张 **09:30 的开盘单**，却按「竞价成交」的盈亏比在算，会系统性高估收益。

**正确做法**：要参与竞价，决策必须在 **09:24:58 之前**完成。见 `engines/auction.py` 的 `entry_window="09:24:56-09:24:58"`，以及盘前简报里的纪律提醒。

## 3. `R_unmatched` 无上界

错误写法 `R_unmatched = Unmatched / Matched`：当 Matched 很小时该值可以是几十、几百，`> 60%` 的阈值失去意义。

**正确做法**：用归一化形式，值域锁死在 `[0, 1]`：

```text
R_imbalance = Unmatched / (Matched + Unmatched)
```

见 `AuctionRiskEngine._imbalance()`。

## 4. `R_tail` 在净流出时符号翻转

错误写法 `R_tail = NetInflow_last30m / NetInflow_total`：当全天净流出（分母为负）时比值符号翻转——尾盘也在流出的票会算出正的大比例，尾盘拉升的票反而算出负值。这个判据在下跌市（恰恰最需要它的时候）会系统性误判。

**正确做法**：加方向门槛，仅当 `NetInflow_total > 0` 时才判定；否则标记为未定义、不参与打分。

## 5. `F_market_emotion` 在 N=50 处不连续

分段函数在 `N_down = 50` 处从 `1.0 - 35/50 = 0.3` 直接跳到 `0.1`。跌停 50 家和 51 家的市场状态几乎相同，仓位上限却差 3 倍；盘中跌停家数在 50 上下反复穿越时，仓位指令会来回翻转。

**正确做法**：连续段保持线性平滑，熔断做成**带滞回的独立开关**（如进入阈值 55、退出阈值 45），不要让熔断以断点形式混在连续函数里。

另外 15 / 50 这两个阈值需要用历史跌停家数分布标定，不能拍脑袋。

## 6. C++/Cython 极速引擎 + 盘后冷编译 = 过度工程

方案要求「30ms 内纯原生算术校验」并配套「15:30 冷编译 C++ 引擎」。瓶颈从来不在算术：几百只标的的比值运算在 CPython 里是亚毫秒级。真正的延迟在数据源——TickFlow 是 REST 快照（百毫秒级往返），券商 L2 推送也在几十毫秒。

为占比不到 1% 的环节引入 C++ 工具链和每日编译流程，换来的是运维负担和一条无法热修的关键路径。

**正确做法**：保持纯 Python。`docs/TDD.md` 的端到端 P99 ≤ 50ms 目标完全够用。

---

## 附：数据源能力边界

方案第二层（L2 竞价秒级引擎）在 TickFlow 上**任何档位都无法实现**——它不提供逐笔委托，也不提供竞价未匹配量。真正的竞价微观结构需要券商侧通道（QMT / CTP）。

在没有 L2 之前，竞价相关字段一律置空并标 `data_stale`，**不要用日线数据凑数**：把全天成交额填进 `matched_amount`，会让日线数字轻松通过为竞价设计的三千万门槛。见 `docs/TICKFLOW_LOCAL_SETUP.md` 的能力矩阵。
