# 设计决策与被否决的方案

这份文档记录**为什么是现在这样**，以及**哪些看起来合理的方案被否决了、依据是什么**。
写在这里是为了防止后续再被同类方案带偏——被否决的方案通常还会以新的包装回来。

---

## 一、集合竞价拦截：这条路封死了，不是钱的问题

某版「终极实盘闭环」方案的第二层是「09:20–09:25 竞价秒级引擎」。其中两处是
**A 股交易规则层面的逻辑不成立**，不是参数调优问题。

### 1.1 09:20–09:25 不接受撤单，撤单率公式恒等于 0（致命）

错误写法：

```text
R_withdraw = (BidAmount_09:24:30 - BidAmount_09:24:58) / BidAmount_09:24:30
```

A 股集合竞价 **09:20–09:25 期间交易所不接受撤单**。该窗口内买盘挂单量不会因撤单
下降，这个比值恒约等于 0，或只反映价格档位漂移，**无法识别诱多**。

撤单率只能定义在 **09:15–09:19:59** 这个可撤单窗口，且需要数据源提供逐笔委托或
撤单记录——**任何档位、任何数据源都不提供**。

### 1.2 「09:25:02 推送卡片 → 1.5 秒点击下单」在时序上是事后动作（致命）

09:25 集合竞价已经撮合完毕、开盘价已定。09:25:02 才推送，此时下单**无法参与集合竞价**：
沪市 09:25–09:30 不接受申报，深市虽接受但订单只进缓冲区、开盘后才进连续竞价。

这条链路实际产出的是一张 **09:30 的开盘单**，却按「竞价成交」的盈亏比在算，
**会系统性高估收益**。要参与竞价，决策必须在 **09:24:58 之前**完成。

### 1.3 结论：删掉，而不是留着等数据

`engines/auction.py`（221 行）与相关状态机（`AUC_FOCUS` / `AVOID_NOFILL` /
`AVOID_FAKE_STRENGTH`）已一并删除。它实现的是一个**用不存在的数据、在来不及的时刻
做出的决策**。

即使接上 QMT 也补不上：QMT 给的是券商侧五档与逐笔成交，**不是交易所的竞价撮合量与
未匹配量**。那个数据交易所根本不发布。

> **留下的教训**：在没有 L2 之前，竞价相关字段一律置空并标 `data_stale`，
> **不要用日线数据凑数**——把全天成交额填进 `matched_amount`，会让日线数字轻松通过
> 为竞价设计的三千万门槛。

## 二、四个会静默出错的公式

这些不是「不够精确」，是**在最需要它们的时候方向反号**。

### 2.1 `R_unmatched = Unmatched / Matched` 无上界

Matched 很小时该值可以是几十、几百，`> 60%` 的阈值失去意义。

正确形式，值域锁死在 `[0, 1]`：

```text
R_imbalance = Unmatched / (Matched + Unmatched)
```

### 2.2 `R_tail = NetInflow_last30m / NetInflow_total` 在净流出时符号翻转

全天净流出（分母为负）时比值符号翻转——**尾盘也在流出的票会算出正的大比例，
尾盘拉升的票反而算出负值**。这个判据在下跌市（恰恰最需要它的时候）会系统性误判。

正确做法：加方向门槛，仅当 `NetInflow_total > 0` 时才判定；否则标记为未定义、
不参与打分。

### 2.3 `F_market_emotion` 在 N=50 处不连续

分段函数在 `N_down = 50` 处从 `1.0 - 35/50 = 0.3` 直接跳到 `0.1`。**跌停 50 家和
51 家的市场状态几乎相同，仓位上限却差 3 倍**；盘中跌停家数在 50 上下反复穿越时，
仓位指令会来回翻转。

正确做法：连续段保持线性平滑，熔断做成**带滞回的独立开关**（进入阈值 55、退出阈值 45），
不要让熔断以断点形式混在连续函数里。

**这条已经推广成全系统的原则**：阶跃函数在阈值两侧给出差很多的分，而阈值本身是
拍脑袋定的，读数在附近来回穿越时排序就会抖。现在大盘层与个股层都用斜坡
（`_ramp(value, onset, full)`）。

### 2.4 `强度 = 命中密度` 在小样本上方向反了

板块舆情用 `intensity`（命中密度）加权时，**样本越小平均密度越高**。实测出现过
基础化工靠 2 条快讯拿满 +12、计算机 22 条只拿 +2.0。

正确做法：文档数不足 8 条时按 `条数/8` 折权。密度是密度，证据量是证据量。

## 三、C++/Cython 极速引擎 + 盘后冷编译：过度工程

方案要求「30ms 内纯原生算术校验」并配套「15:30 冷编译 C++ 引擎」。

**瓶颈从来不在算术**：几百只标的的比值运算在 CPython 里是亚毫秒级。真正的延迟在
数据源——TickFlow 是 REST 快照（百毫秒级往返），券商 L2 推送也在几十毫秒。

为占比不到 1% 的环节引入 C++ 工具链和每日编译流程，换来的是运维负担和一条**无法热修
的关键路径**。

**保持纯 Python。**

## 四、威科夫：借概念，不借体系

这个项目借用威科夫的**结构概念**作为一层轻量覆盖，不是完整的自由裁量交易体系。

**保留**：吸筹/派发倾向、Spring 与 Upthrust 识别、SOS/LPS 确认、
effort vs result、压缩后扩张。

**丢弃**：重量级 agent 编排、策略膨胀、把不透明的 prompt 当主决策层。

**在本项目里**：

- `WyckoffAnalyzer` 把历史 bar 打成结构倾向
- `DailyTechnicalAnalyzer` 抽支撑、压力、趋势状态、形态提示
- 结果只用于研究，不下单

**转向低吸口径之后，威科夫的权重重排过一次**：

| 事件 | 原权重 | 现权重 | 理由 |
|---|---|---|---|
| MARKUP（主升段） | +12 | **+7** | 主升段是**追高**的位置 |
| ACCUMULATION（吸筹末端） | +10 | +10 | 低吸该待的地方 |
| Spring（假跌破收回） | +6 | **+8** | **就是低吸信号** |
| LPS（回踩承接） | +4 | **+7** | **就是低吸信号** |
| SOS（放量上推突破） | +5 | **+3** | 强势确认，对追涨有用，对低吸是「已经晚了」 |

**阶段本身只说明「趋势没坏」，真正的进场信号是事件。** 原来的排序把追高排在了回踩前面。

用法：当交叉验证，不当唯一真相来源。

## 五、「持续学习」不做成在线学习

样本量不够时的在线学习就是过拟合。

**不做的**：拿几十个样本拟合出来的、看起来在学习的东西。

**做的**：记账 → 对照组 → 兑现核对 → 统计，**只到这里为止**。上模型的触发条件是
台账里有 **200 条已兑现记录**（`journal/stats.py:MODEL_READY_SAMPLES`），
不是「攒了两周」。在那之前统计只报告、不回写任何权重。

### 为什么必须有对照组

没有负样本就永远回答不了「**筛选规则本身有没有用**」。入选组次日涨 1.2% 听起来不错，
但若对照组涨 1.4%，这套规则就是**负价值**。

对照组取**紧邻落选**而不是全市场垫底——后者差出来的是「好票 vs 烂票」，不是规则的价值。
等量是为了让两组的统计噪声量级可比。

### 为什么必须存当时的大盘状态

同一套规则在退潮期和启动期的期望值可以是**反号**的。不把炸板率、最高连板、涨跌停家数
和大盘读数存进每条记录，事后就无法按情绪周期分层。

**冗余存储是刻意的**：台账是 JSONL，每条多带七八个数比事后按日期 join 便宜得多，
而且**记录自带分层维度**意味着任何一段区间的数据都能独立分析，不依赖别的文件还在不在。

### 为什么两套持有期口径并存

`next_open/high/low/close` 对应「次日就卖」，五日 MFE/MAE 对应低吸的自然持有期。
**哪种更合适现在拍板都是猜，两个都记让数据回答。**

隔夜跳空单独记，是因为持仓过夜的收益里它常常比日内择时贡献更大，混在 MFE 里就归因不出来。

### 特征必须在采集之前定好

台账字段一旦漏了，之前的样本就**永久失去分层能力**——两个月后才有足够样本回答
「回撤 5% 买和回撤 8% 买哪个次日溢价高」，那时再想补字段已经晚了。

所以 `signals/dipbuy.py` 只负责**算出这些数**，不负责打分：打分口径还在观察期、随时会调，
特征定义不该跟着抖。

## 六、买卖点：为什么是「候选集 + 裁决」而不是两个极端

### 全部写死是错的

那些阈值——回调 5% 算深、量比 1.0 算放量、盈亏比 2.0 达标、买入区间 = VWAP ± 12%
日振幅——**没有一个是拟合出来的**。它们看起来精确，实际是一组从未被验证的猜测，
而且用一个数掩盖了「这里本来有多个合理答案」这个事实。

### 全交给模型也是错的

同一份数据两次调用会给出不同的价，而且回答不了「为什么是 22.95 不是 22.80」。
台账里记下来的东西因此无法归因，整个持续学习的链条断掉。

### 所以分界线画在「谁能产生数字」和「谁能做取舍」之间

- **规则产生所有数字，并给出一组带出处的候选**（含自己的默认排序）
- **模型只在候选集内做取舍**，必须引用 L1 读数说明理由，可以弃权，**不能造价**
- **数字闸门比通用闸门更严**：价格必须**恰好等于**某个候选，不接受近似匹配
  ——22.95 和 22.96 在文本比对里都能过，但那是两个不同的挂单价
- **LLM 挂了就取默认排序**，链路照跑

### 这个决定本身也要被验证

台账**同时记录规则默认与模型裁决两套结论**，兑现核对对两套各算一遍。
「加了裁量权有没有用」因此是一个**有数据能回答**的问题。

在样本够之前，这条记录在文档里：**给模型裁量权是因为写死的阈值同样没有依据，
不是因为有证据说模型更好。**

## 七、其余已固化的决定

| 决定 | 理由 |
|---|---|
| **筛选与打分分离** | ST、退市、立案调查这类风险无法被好走势补偿，做成扣分迟早被其他因子的正分盖过 |
| **没数据 ≠ 中性** | 给中性默认分会让「无知」压过「测量出的走弱」 |
| **数据缺失时放行而非拦截** | 用「没测到」当否决理由，等于让数据缺失冒充风险判断 |
| **越紧急的输出越不经过 LLM** | 盘中告警秒级时效，LLM 增加 2–5 秒延迟与一次失败可能 |
| **合规文本程序化追加** | 实测 Qwen 在被明确要求保留时，仍会在概括中整段丢掉风险提示 |
| **按跃迁告警而非按状态** | 145 轮/天，按状态告警到中午就被静音了 |
| **止损每日只发一次** | 反复穿越止损位时连发五条，人只会把通知静音 |
| **止损与目标开盘 15 分钟后钉死** | 每轮重算的止损永远在当前最低价下方，`stop_break` 结构上无法触发——跟着价格往下走的止损不是止损 |
| **自选股/候选池/热门股三个列表分开**（热门股 ⬜ 未建） | 混在一起就分不清哪些是自己决定要盯的、哪些是机器刚塞进来的 |
| **热门股不进台账**（⬜ 未建） | 入选条件随盘中情绪变，混进去会污染「盘前筛选有没有用」的样本 |
| **同花顺行业指数不参与打分** | 90 个行业 ≈ 申万二级粒度，硬映到一级只会造出假精度 |
| **五档只做有界旁证**（⬜ 未接入） | 挂单可撤可假挂且只有五档；当主判据等于把仓位押在别人随时能撤的单上 |
| **分片取数失败就抛错且不写缓存** | 宁可跑不出来，也不留一份不知道完不完整的分类 |
| **语料库用 SQLite，其余用 JSON/JSONL** | 它是唯一需要按板块/标的/时间窗**查询**且长期累积的数据 |
| **不产出概率/胜率/预期收益率** | 没有拟合模型能支撑它们 |

### `screening/` 的移除与它留下的那个读数

该模块用三档口径拆解「昨日低点到次日高点差 2%，就在低点买」这类筛选条件：
`oracle`（T 日最低买 / T+1 日最高卖，**上帝视角，做不到**）、`neutral`（收盘买 /
次日均价卖，不择时）、`strict`（收盘买 / 次日开盘卖，完全机械）。

2026-08-01 取 25 只两年日线、成本按 0.202% 往返扣除：

| 读数 | 结果 |
|---|---|
| `oracle` 中位数的中位数 | **1.91%** |
| `neutral` 中位数的中位数 | **-0.20%** |

**那 2% 几乎全部是择时溢价，不择时的话是负的。** 模块本身已移除，但这个读数
必须留下来——它是对「找波动大的票就能赚」这个直觉最直接的反驳，而且它解释了
为什么这套系统把力气花在**判断买卖点**而不是**筛选标的**上。
