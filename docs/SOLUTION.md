# 方案总览

A 股超短线 **分析辅助** 系统。硬约束：**不下单、不撤单、不接管证券账户。**

如果你想先看“怎么用”，先读 [`USAGE.md`](USAGE.md)；本文还是总览、需求拆解和设计约束。

系统做四件事，对应使用者的四个实际动作：

| 你想做的事 | 系统提供 | 时段 |
|---|---|---|
| 知道市场上在发生什么 | 舆情持续采集并**沉淀成语料库**，可按板块/标的/时间窗回查 | 全天 |
| 开盘前判断大盘与板块，并拿到对应的个股 | 盘前主链路：舆情 → 大盘 → 板块排序 → 板块内选股 → 当日候选 | 08:00–09:15 |
| 盘中知道该在哪买、哪卖 | 后台自动算买卖点并按跃迁告警；也可以随时开口问 | 09:30–15:00 |
| 追问、复盘、验证这套东西到底有没有用 | 多轮对话 + 台账兑现核对 + 筛选价值统计 | 全天 / 盘后 |

架构与模块见 [`ARCHITECTURE.md`](ARCHITECTURE.md)　数据源实测见 [`DATA_SOURCES.md`](DATA_SOURCES.md)
链路详解见 [`PIPELINE.md`](PIPELINE.md)　为什么这么定见 [`DECISIONS.md`](DECISIONS.md)

> **实现状态约定。** 本文同时描述**已建成**与**已定但未建**的部分。凡是未建的
> 一律用「⬜ 未建」明确标出——把设计当现状，正是这套文档上一次需要整体重写的
> 直接原因。**当前没有「已定未建」的部分**——热门股池那一项已经随自选股与候选池
> 一起放弃（§二）。情绪周期闸门与打法分支（§二b）、
> 买卖点三层裁决（§三）、五档进买卖点、`ask` 单入口问答均已建成。

## 一、全天链路

```text
08:00  舆情采集    财联社 · 东财快讯 · 新闻联播 · 华尔街见闻 · 全量公告 · 龙虎榜
                   → 写入语料库（去重、记 first_seen、不再跑完即弃）
08:20  盘前主链路  舆情 → 大盘趋势 → 板块排序 → 板块内选股 → 当日候选 → 台账
09:15  执行卡      持仓的价位、止损、情景
09:35  盘中监控    每 2 分钟：时效闸门 → 买卖点重算 → 跃迁触发 → 告警   ┐ 跑到
       ⋮           每 5 轮加一次板块截面（与名单无关）                    ┘ 14:55
15:10  盘后复盘    持仓打分、次日决策矩阵
15:40  兑现核对    T-1..T-5 的建议对照实际走势，写回台账
```

```bash
ashare-ds daemon                      # 全天自动
ashare-ds daemon --dry-run            # 只看时间表
ashare-ds daemon --only morning       # 只跑某一段
ashare-ds daemon --feishu             # 同时推飞书
```

非交易日整张表跳过。判定顺序：周末 → 节假日表 → 未配置时明说「未经假期校验」。
任务失败只重试三次并推一条通知，不影响其余任务；进程中途重启不会重发已完成的推送。

## 二、只剩一份名单：持仓

**这里曾经有三份。** 自选股（人维护、永不自动删除）、候选池（`morning` 每早生成、
隔日失效）、以及一份没建成的热门股池。三份都删了，判据是**使用方式变了**：标的由
你在提问时直接给出——`ashare-ds advise 600519.SH`、`ask "600519 现在怎么看"`——
而不是让系统替你维护一份名单，再在每条命令里默默把它展开成十几只票。

一份没人维护却仍被当默认输入的清单，比没有清单更糟：每条命令都多算十几只你今天
根本没在看的票，几十次取数，而结论看起来一样正常。

留下的只有**持仓**，因为它回答的是另一个问题。持仓不是「想看什么」，是已经承担了
风险的那几只：止损、目标、结构破坏、时间止损、浮盈回吐这五类判断只对它们成立，
而且必须在盘中被盯着——那不能靠你每次手输代码来触发。

| | 命令行传进来的标的 | 持仓 `positions` |
|---|---|---|
| 谁维护 | 你，当场 | 你，`position open` |
| 生命周期 | 这一条命令 | 持久，直到 `position close` |
| 买卖点依据 | 日线结构 + 分时 + 五档 | 同左，外加成本价与建仓日 |
| 盯的是 | 买点（进入区间 → 止跌确认） | **卖点**（止损/目标/结构破坏/时间止损/浮盈回吐） |
| 告警级别 | 全部 | 全部，且排在最前 |
| 进台账 | `advise` 走的那次进 | 进 |

盘前候选仍然每天产出，只是它现在**只是晨报的一节结论**：进 facts、进简报、进台账
（含对照组），但不再写成一份名单让后面的命令默认去读。

```bash
ashare-ds position open 600519 --cost 1350.6 --stop 1330 --target 1430
ashare-ds position list
ashare-ds position close 600519      # 平仓即删除；历史留在台账里
```

`--stop` 与 `--target` **优先于系统算出来的那两个数**：手工填的是决定，系统算的是
建议，冲突时听你的——你可能知道系统不知道的事（别处的敞口、税、仓位安排）。它们
也**不受开盘 15 分钟的钉死约束**：那道约束是为了等当日结构成型，而你填的是绝对
价位，第一分钟跌破/摸到就该报。

这些字段全部手工维护——系统**不下单、不撤单、不接管账户**，它不可能自己知道你买了什么。

## 二b、先决定今天做不做：情绪周期闸门与打法分支

> 已建成：`strategy/regime.py`（闸门）· `strategy/playbook.py`（趋势分支）。
> 盘前主链路已接入，`advise` 单票分析走不带周期约束的那条路。

**改造前这一层是不存在的**，而它的缺席是这套系统最大的结构问题：六路读数
（舆情、板块动量、威科夫、五档、龙虎榜、涨停池）全部汇进一个 0–100 分和一道
「回调过没有」的门槛，代码里没有任何一处在决定**今天该干什么**。两个后果：

**1. 情绪周期读出来了却不接管决策。** 2026-08-03 实测：炸板率 51.94%
（系统自己在 `journal/stats.py` 的定义里 ≥50% 就是退潮），当天照常输出 60 条
低吸建议、仓位系数 0.68。炸板率过半意味着昨天冲板的票一半没守住——这正是超短
最该收手的信号。它被读到了、写进了台账，然后被忽略。

**2. 只有一套打法。** 低吸门槛 + `advice/candidates.py` 里「高于现价的买入价
直接不生成」，两处合起来让系统在**结构上不可能**产出一个突破买点。趋势只是权重
（UPTREND +12 / DOWNTREND −15），而权重可以被别的项买回来——所以「下跌趋势
什么样的可以买」这个问题从来没有被回答，它只是被打了个折。

**低吸不是默认打法，它是退潮期的打法。** 把一个特定周期的战术当成全天候策略，
是选股结果长期对不上口径的根因。

### 两个正交的判断，取交集

```text
情绪周期（全市场）→ 今天允许哪些打法 + 仓位上限      regime.py
趋势状态（单只票）→ 这只票能用哪些打法              playbook.py
                  ↓
              取交集，空集就是不买
```

| 情绪周期 | 判据（涨停池） | 允许的打法 | 仓位上限 |
|---|---|---|---|
| 冰点 | 跌停 ≥15 家 ∣ 炸板 ≥60% 且连板 ≤2 ∣ 涨停 ≤15 家 | **无——不出手** | 0 |
| 启动 | 炸板 <30%，连板 <5 | 突破 · 回踩 | 0.50 |
| 发酵 | 炸板 <30%，连板 ≥5 | 突破 · 回踩 · 区间下沿 | 0.80 |
| 高潮 | 炸板 <30%，连板 ≥7 且涨停 ≥80 家 | 回踩（只减不加） | 0.40 |
| 分歧 | 炸板 30%–50% | 回踩 · 区间下沿 | 0.50 |
| 退潮 | 炸板 ≥50% | 回踩 · 超跌反转（**只做龙头**） | 0.30 |
| 未知 | 涨停池取不到 | 回踩 | 0.30 |

未知档**不等于中性**：压到与退潮同级并只留最保守的一条打法。给中性默认值会让
「无知」压过「测量出的走弱」，这与 §四.4 是同一条原则。

### 每种趋势走不同的判据链

| 趋势 | 允许 | 入场判据 |
|---|---|---|
| UPTREND | 突破 · 回踩 | 见下 |
| REBOUND | 回踩 | 同回踩 |
| RANGE | 区间下沿 | 60 日分位 ≤0.35、下方有支撑、未放量破位 |
| DOWNTREND | 超跌反转 | 见下 |

**回踩**：回调档位 shallow/ideal × **缩量 ≤0.90** × 收盘仍在 MA20 上方。
三个都是门槛。改造前只有第一个是门槛，后两个是权重——这正是选出的票 87%
在放量回调的原因（`signals/dipbuy.py` 自己写着「回调放量意味着出货」）。

0.90 标定自 2026-08-03 当日 120 只入围票的分布（中位数 **1.066**，即中位候选
其实是放量的）：≤0.75 剩 13%、≤0.90 剩 25%、≤1.0 剩 38%。取 0.90 挡掉明确
放量的那 31%，同时留下够填满当日候选的样本。**先验校准，不是收益验证。**

**突破**：60 日分位 ≥0.85 × 量比 1.2–4.0 × 未从高点回落到 ideal/deep。
上限是必要的——量比 5.0 是情绪透支，不是突破确认。

**超跌反转**：这是「下跌趋势什么样的可以买」的答案。必须 deep 档 **且**
有一个反转触发，三选一：Spring（假跌破收回）· 放量反包（当日收阳且量比 ≥1.2）·
踩回 30 日成交成本后收回。**跌得多本身不是买入理由**，没有触发就明确拒绝并
把「属于接刀」写进理由。命中时仓位减半、目标只看前高的一半。

### 拿 2026-08-03 的真实数据重放

| | 改造前 | 改造后 |
|---|---|---|
| 情绪周期 | 未判定 | **退潮**（炸板 51.9%） |
| 仓位系数 | 0.68 | **0.30**（周期上限压下来） |
| 候选（去重后） | 21 只 | **5 只**，其余 16 只全部因「回调放量」被挡 |

### 已知的不一致，留给下一轮

`advice/candidates.py` 仍然拒绝生成高于现价的买入价。**突破打法因此能被选中、
但拿不到与之匹配的买点**——`advise` 对一只突破候选会给出低吸口径的价位。选股层
和买卖点层的口径要在下一轮对齐。

## 三、买卖点怎么产生：三层，模型有裁量权但造不出价

> 已建成：`advice/candidates.py`（L2）· `advice/adjudicate.py`（L3）·
> `signals/orderflow.py`（五档读数）。裁决层默认关闭，`advise --adjudicate` 打开；
> 关掉时走的就是规则默认排序，也就是改造前那套行为。

这是整个系统最容易做错的地方，所以单独说清楚。

**两种极端都是错的。** 全部写死成规则，那些阈值（回调 5% 算深、量比 1.0 算放量、
盈亏比 2.0 达标）没有一个是拟合出来的，它们只是看起来精确；把事实整包丢给模型让它
自由发挥，同一份数据两次调用会给出不同的价，而且回答不了「为什么是 22.95 不是 22.80」。

**所以拆成三层，分界线是「谁能产生数字」和「谁能做取舍」：**

```text
┌─ L1 事实层 ─────────────────────────────────────────── 无模型 · 带校验 ─┐
│  现价 23.16   VWAP 23.04   ATR% 2.1%   量比 0.62                        │
│  日线支撑 22.80 / 22.15    五档买盘墙 22.95（1.2 万手）                  │
│  20 日高 25.40   回撤 -3.2 个日波幅   近 3 日缩量 0.62                   │
│  → 每个数都出自确定性算子，且过跨源/量纲/时效校验                        │
└────────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─ L2 候选层 ────────────────────────── 规则生成 · 每个候选必须带出处 ─────┐
│  买 22.95  五档买盘墙          买 23.04  分时均价回踩                     │
│  买 22.80  日线支撑            卖 25.40  20 日高                         │
│  止 22.15  次级支撑（距现价 1.8 个日波幅）                               │
│  → 规则不再直接给"那一个价"，而是给一组带依据的价                        │
└────────────────────────────────────────────────────────────────────────┘
                                  ↓
┌─ L3 裁决层 ─────────────────── 模型 · 只能从 L2 里选 · 必须引用 L1 ──────┐
│  「取 22.95：买盘墙和日线支撑之间只差 0.6%，但墙先到且缩量到 0.62，       │
│    回调质量成立。若跌破 22.80 则两条依据同时失效 → 止 22.15」            │
│  → 可以推翻规则的默认排序，可以说「今天不该买」，不能凭空造价            │
└────────────────────────────────────────────────────────────────────────┘
                                  ↓
        数字闸门：L3 输出的每个价必须在 L2 ∪ L1 里，否则整段丢弃回退 L2 默认
```

**这一层的自主权是真的，不是装饰。** 模型可以：

- 选择规则默认排序之外的候选（规则默认取最近的支撑，模型可以取买盘墙）
- 给出「本轮不建议进场」，哪怕规则算出了一个可用价位
- 指出两个候选互为条件（跌破 A 则 B 失效）

**模型不可以**：说出一个 L2 与 L1 里都没有的价、给出概率或胜率、说「建议买入」。

### 为什么这样能验证，而不是只能相信

**台账同时记录两套结论**：规则默认会给什么价、模型最终给了什么价、模型的理由，
以及每个价的**出处类别**（`journal/records.py:adjudication`）。T+1..T+5 的兑现
核对把这几样原样带进兑现记录。攒够样本后，「模型裁决比规则默认好吗」是一个
**有数据能回答**的问题，而不是一句感觉——`journal/stats.py` 里的
`adjudication_edge` 就是那个答案的位置。

统计上有一处特意做的区分：**模型选了和规则同一个候选的记录，两组都不进。**
算进模型那一组，会掺进大量「模型其实没做决定」的样本，把差值稀释向零——那正好是
最容易得出「加了也没变化」这种错误结论的方式。它自成一档（`模型认可规则`）。

弃权的记录也单独计数：它们没有买入价，兑现流程里根本不算入场，和有价位的记录
不可比。弃权的价值要单独看。

在样本够之前，两套都只是排序辅助，不参与任何加权。见 §六。

### 硬编码的阈值怎么办

能按标的自身分布归一的一律归一，不能的移进配置：

| 原来 | 问题 | 现在 |
|---|---|---|
| 回调 5%~12% 算理想 | 长江电力（日振幅 1.82%）一年碰不到一次 deep；计算机题材（6.23%）49% 的交易日都是 deep | 除以标的自身 ATR%，档位 0.8 / 2.0 / 4.0 **个日波幅** |
| 量比 ≥ 1.0 一律 +8 | 4.0 处有 13 分悬崖，1.02 和 3.99 同分 | 斜坡取代阶跃，且**回调段与启动段符号相反** |
| 止损取最近支撑 | 实测 603508.SH 止损距离 0.04%，盈亏比算出 172.84 直接满分 | 止损距离下限 1 个 ATR、上限 3 个 ATR |
| 各项权重写在模块常量里 | 改一个数要改代码、发版、且没人知道上次为什么是这个数 | ⬜ **未做**。目标是移进配置文件，带注释与标定日期 |

## 四、四条不可让步的设计约束

### 1. 数据时效是自动化的总开关

人工跑 `advise` 看到「非当日数据」横幅会自己判断；自动推送没有这个环节。
**一条基于昨天数据的实时告警比没有告警糟糕得多。**

监控每轮第一步是验时效，不是取数：

```text
滞后 ≤ 5 分钟    → 正常告警
滞后 5-15 分钟   → 告警照发，每条附时间戳与滞后量
非当日 / >15 分钟 / 两轮不推进
                 → 推一条「数据源停更、监控已挂起」，停止产出信号
                   循环继续运行，恢复后自动通知
```

每条推送都带数据 as-of 时间戳，没有例外。

### 2. 数字只在确定性层产生

L1 的算子（舆情、板块动量、日线结构、威科夫、分时、盘口、龙虎榜、风险筛除）
**不含模型**，系统里所有数字都出自这一层。L3 只做取舍与论证，越界整段丢弃。

**越紧急的输出越不经过 LLM**——盘中告警纯模板，简报和买卖点裁决才上 LLM。
Qwen 挂了整条链路照跑，买卖点退回 L2 的规则默认排序。

### 3. 价格口径必须显式

| 数据 | 复权 | 用途 |
|---|---|---|
| TickFlow 日线 | **比例前复权** | 均线、趋势、威科夫、支撑压力 |
| 新浪 / TickFlow 分钟线 | **不复权** | 买卖点、止损、目标——所有要挂单的价格 |

比例前复权锚定**最新**一根：它不动今天，只重算历史。所以两条序列本来就共用今天的
价格尺度——2026-08-02 实测 400 只，前复权最新一根与不复权最新一根**无一例外完全相同**
（茅台两边都是 1350.60），而 60 天前那根差 2.3%，差的正是该差的部分。

因此 `advice/engine.py` 里那个比值**恒等于 1.0，这正是它的价值**：一旦不等于 1.0，
就说明两份数据对不上（取错标的、日线停在昨天而分钟线是今天、某一路退化成默认值），
此时宁可不给价。窗口开在 `[0.2, 5.0]` 是因为它要抓的是「根本对不上」，不是微小误差。

台账用**相对百分比**记录价位——百分比对复权免疫，这是唯一能跨两种口径正确核对的方式。

### 4. 没数据 ≠ 中性

覆盖率不足的板块 `trusted=False`，排序永远垫底且不出候选；大盘方向直接返回
「数据不足」而不是「中性」。给中性默认分会让「无知」压过「测量出的走弱」。

## 五、盘中监控：按跃迁告警

每 2 分钟一轮，四小时约 145 轮。按状态告警会直接刷屏，所以只在**跃迁**时发。

| 级别 | 触发 | 重发规则 |
|---|---|---|
| ACTION | 进入买入区间 / 止跌确认 / 跌破止损 / 触及目标 / 跌破结构支撑ᴴ / 浮盈回吐ᴴ | 前两条 30 分钟冷却，其余每日一次 |
| WARN | 进入买入区间（未止跌 · 封涨停买不进）/ 跌破分时均价 / 情景切换 / 量比 > 3 / 持有到期未兑现ᴴ / 突发风险公告 | 15–30 分钟冷却；后两条每日一次 |
| INFO | 站上分时均价 / 创当日新高 | 默认关闭 |

ᴴ 只对持仓触发。未持仓的票没有成本价，这五类卖点里有三类根本算不出来。

被盯的每一只要么是你当场输入的，要么在持仓表里，所以告警不再按名单来源降级。

**「到位了」和「动得了」是两个问题，只有五档能回答后一个。** 规则层只有分钟线，
它算得出价格进了买入区间，看不出这一刻根本买不进。所以封死涨停时「进入买入区间」
降成 WARN 而不是照发 ACTION（区间是真的进了，但挂单只能排队等开板），封死跌停时
「跌破止损」照发——你必须知道——但会写明此刻卖不出、封死就只能等次日。
拿不到涨跌停价时这一层什么都不做：**未知不算封板**，否则一个缺失的字段会悄悄
压掉本该发的告警。

**止损与目标在开盘 15 分钟后钉死，买入区间继续跟随分时均价。** 每轮重算的止损永远
在当前最低价下方，价格因此永远跌不破它，`stop_break` 结构上无法触发——跟着价格往下
走的止损不是止损。而「现在该在哪买」本来就该随均价动。

## 六、持续学习：五步只做前四步

样本量不够时的在线学习就是过拟合。

1. **记账**——每条建议落台账：标的、日期、分数、买入区间、止损、目标、板块、理由、
   facts 快照哈希。哈希让「当时到底看到了什么」可复现。此外还记四组事后无法补的：
   - **低吸画像**（`signals/dipbuy.py`）：距 20 日高的回撤、缩量程度、距支撑距离、
     中期趋势。低吸和打板要的读数是反的，两者不能共用一套特征。
   - **当时的大盘状态**：炸板率、最高连板、涨停/跌停家数、大盘读数、仓位系数，
     以及周度/月度轮动标签、全场成交额变化、等权与加权是否背离。
     没有它就无法按情绪周期分层，而同一套规则在退潮期和启动期的期望值可以是**反号**的。
   - **规则默认 vs 模型裁决**：两套价位、各自的出处类别、模型给的理由。
     这是回答「加了裁量权有没有用」的唯一途径。
   - **上一交易日的逐笔摘要**：主动买占比、大单净额、尾盘净额。

   后两组与业绩裁决、逐笔旁证遵循同一条：**凡是刻意不进分数的读数，台账就是它
   唯一的可验证出口**。不落台账的话，它要么永远停在「旁证」状态无法被检验，
   要么某天凭感觉被提成因子——两条路都不该走。
2. **对照组**——每天额外记录**等量的紧邻落选样本**（`kind=control`，不推送、不进
   当日候选），走同一套兑现流程。没有负样本就永远回答不了「筛选规则本身有没有用」：
   入选组次日涨 1.2% 听起来不错，但若对照组涨 1.4%，这套规则就是负价值。
   取紧邻落选而不是全市场垫底——后者差出来的是「好票 vs 烂票」，不是规则的价值。
3. **兑现核对**——T+1..T+5 拉实际日线算：有没有进入买入区间？先碰止损还是先碰目标？
   最大有利偏移 MFE / 最大不利偏移 MAE 各是多少？**两套持有期口径并存**：
   `next_open/high/low/close` 对应「次日就卖」，五日 MFE/MAE 对应低吸的自然持有期。
   哪种更合适现在拍板都是猜，两个都记让数据回答。隔夜跳空单独记，是因为持仓过夜的
   收益里它常常比日内择时贡献更大，混在 MFE 里就归因不出来。
4. **统计**——按分数桶、板块、趋势状态、情绪周期、回调深度、打法、**入选 vs 对照**、
   **规则默认 vs 模型裁决**、以及买入位的**出处类别**分组报兑现率，并直接给出
   `selection_edge`（入选中位 − 对照中位）与 `adjudication_edge`（模型推翻规则的
   那些次 − 规则默认那些次）。
   样本不足的分组照列但标注 `trusted=False`——「样本太少」本身就是结论的一部分。

   另有三组是**「只出读数、不进打分」那几层的验收位**：周度轮动方向、全场成交额
   （存量 / 增量）、等权与市值加权是否背离。它们回答的是同一个问题的三个版本——
   **那一层报出来的东西，事后看有没有区分度**。没有区分度就该撤掉，而不是留着
   当装饰；有区分度才谈得上要不要让它影响仓位。

   这三组能存在的前提是建议发出当时把**判定标签**（不只是原始读数）写进了
   `market_state`。存标签而不是现算：阈值以后一定会调，而调完之后历史记录必须
   仍按当天生效的那个判定分组，否则分层统计描述的是一个从未存在过的过去。
   这一层上线之前的老记录一律落进「未记录」，不混进任何真实档位——把它们混进去
   等于用一段没测过的历史去支持一个结论。
5. **标定**——触发条件是台账里有 **200 条已兑现记录**（`journal/stats.py`），不是
   「攒了两周」。在那之前统计只报告、不回写任何权重。

```bash
ashare-ds review                      # 核对 + 出统计（含筛选价值差值）
ashare-ds journal --symbol 600519.SH  # 某只票的历史建议与兑现
```

## 七、诚实边界

- **板块打分、个股打分、买卖点位的权重全部人工设定，未经回测。** 它们解决「先看哪里、
  哪个价位重要」，不是方向预测。台账建起来就是为了终有一天能回答这个问题。
  付费档的 12 个月分钟历史是这件事第一次具备的前提条件——但前提条件不是结论。

- **情绪周期的切点与打法的入场判据同样未经回测。** 炸板率 30%/50%/60%、连板
  5/7、缩量 0.90、60 日分位 0.85——每一个都是先验设定或单日分布标定，没有一个
  是拿收益验证出来的。它们解决的是「今天该不该出手、这只票该用哪条判据链」，
  在此之前系统对这两个问题**根本没有表达能力**。有表达能力不等于表达对了。

- **打法分支引入了一个已知的保守偏置。** 收盘跌破 MA20 即判出回踩，哪怕只跌破
  0.5%——其中一部分次日会收回。放宽多少合适是实证问题，回测框架建起来之后才有
  资格调。现在宁可漏，不愿在结构已破的位置给买点。

- **样本量门槛按「条」计是不够的。** 60–90 条/天，5 个交易日就能凑够 200 条，但
  那是 5 天的市场、不是 200 个独立样本——A 股日内截面相关极高，同一天几十只票
  的涨跌基本由大盘和板块 beta 决定。`journal/stats.py` 因此加了两道：覆盖
  **60 个交易日**、且至少见过 **3 种情绪周期**，三个条件都满足才叫样本够。

- **台账里存在同日重复记录。** `record_many` 无条件追加，`morning` 当天跑几次
  就写几份。核对流程（`store.pending`）按 `symbol|date|source` 去重所以兑现记录
  不受影响，但任何直接统计 `recommendations()` 的分析都会重复计数——2026-08-03
  的 60 条建议实际只有 21 只唯一标的。写入侧去重尚未做。

- **模型裁决同样未经验证。** 给它裁量权是因为写死的阈值同样没有依据，不是因为
  有证据说模型更好。台账两套都记，就是为了让这句话在几个月后能被数据替换掉。

- **大模型归因会错，而且错得像对的。** 实测两个真实缺陷：模型自报的序号整体偏一位，
  导致整批标签错行（「法国森林火灾」拿到了「动画电影票房超预期」的归因）；以及模型
  会给海外灾害硬凑 A 股板块。现在的防线是——对齐只认模型回抄的标题前缀（可拿原文
  核对），核不上就丢；归了板块却说不出传导机制的按未归因处理；半数以上对不上则整批
  作废。实测 180 条快讯里 95 条归到板块，其余模型主动弃权。

- **五档盘口是挂单快照，不是成交意图。** 它可以被撤、可以是假挂，而且只有五档。
  所以它**完全不进打分**，只做三件事：给 L2 候选价位提供出处（「这个价现在有人
  挂着」）、给要求下单动作的告警附旁证、以及回答「此刻这笔单挂不挂得进」（封板
  时买不进）。真正的委托流（逐笔委托、撤单记录）**任何档位都拿不到**。

- 舆情是关键词匹配或模型标签，都会误归因，所以板块级上限 ±12 分、个股级 ±6 分，
  都压不动量价。样本量另有一道闸：文档数不足 8 条时按 `条数/8` 折权。**没有这道闸时
  实测出现过基础化工靠 2 条快讯拿满 +12、计算机 22 条只拿 +2.0**——`intensity` 是
  命中密度而非证据量，样本越小平均密度越高，方向正好反了。

- 舆情按发布时间做 12 小时半衰期折减，超过 72 小时整条丢弃；跨源同标题合并，保留
  最早发布的那条。无法解析时间戳的不折减（否则只给日期的源会被整体抹掉），但会计数
  并写进简报。

- `strong_count` 目前用涨幅 ≥ 9.5% 代替真实涨停判定——前复权价无法识别涨停板，且
  10% 与 20% 板区分不了。数据侧限制已解除（付费档 `instruments.batch` 涨跌停价
  100% 覆盖），但换判据会让历史板块分数不可比，必须连同阈值重标定一起做。

- 龙虎榜是 T+1 数据，反映昨天的资金。

- **盘中时效仍未实测**——非交易时段测不出来，对免费档和付费档都还是未知数。
  用 `ashare-ds intraday-check` 在交易时段实测。

- 系统不产出概率、胜率、预期收益率——没有拟合模型能支撑它们。

- 仓位系数是**建议值**，封顶 0.80，普涨末段连续折减（最多 -30%）；实际仓位以你的
  手工设定为准。

- **集合竞价拦截这条路是封死的**，不是钱的问题：09:20–09:25 交易所不接受撤单，
  且撮合量/未匹配量任何数据源都不提供。见 [`DECISIONS.md`](DECISIONS.md)。
