# 方案总览

A 股超短线 **分析辅助** 系统。硬约束：**不下单、不撤单、不接管证券账户**。

系统有两种用法：

- **自动运行**（主体）——`daemon` 按时间表跑全天，结果推到控制台/文件/飞书。
- **手工插问**——单独跑某一段，或用 `chat` 追问。

架构与运行细节见 [`docs/AUTOMATION.md`](AUTOMATION.md)，本文是总览。

---

## 一、全天链路

```text
08:00 舆情采集     财联社 · 东财快讯 · 新闻联播 · 全量公告 · 龙虎榜
08:20 盘前主链路   舆情 → 大盘趋势 → 板块排序 → 板块内选股 → 候选池 → 台账
09:15 执行卡       自选股 + 候选池的价位、止损、情景
09:35 盘中监控     每 2 分钟：时效闸门 → 跃迁触发 → 告警        ┐ 跑到
      ⋮                                                          ┘ 14:55
15:10 盘后复盘     自选股打分、次日决策矩阵
15:40 兑现核对     T-1..T-5 的建议对照实际走势，写回台账
```

```bash
ashare-ds daemon                      # 全天自动
ashare-ds daemon --dry-run            # 只看时间表
ashare-ds daemon --only morning       # 只跑某一段
ashare-ds daemon --feishu             # 同时推飞书
```

非交易日整张表跳过。判定顺序：周末 → 节假日表 → 未配置时明说「未经假期校验」。

## 三、四条不可让步的设计约束

### 1. 数据时效是自动化的总开关

人工跑 `advise` 看到「非当日数据」横幅会自己判断；自动推送没有这个环节。
**一条基于昨天数据的实时告警比没有告警糟糕得多。**

监控每轮第一步是验时效，不是取数：

```text
滞后 ≤ 5 分钟    → 正常告警
滞后 5-15 分钟   → 告警照发，每条附时间戳与滞后量
非当日 / >15 分钟 / 两轮不推进
                 → 推一条「数据源停更、监控已挂起」，停止产出信号
                   循环继续运行，恢复后自动通知
```

每条推送都带数据 as-of 时间戳，没有例外。

### 2. 数字只在确定性层产生

`agents/collectors.py` 里的算子（舆情、板块动量、日线结构、威科夫、分时、龙虎榜、
风险筛除）**不含模型**，系统里所有数字都出自这一层。

`agents/debate.py` 的三个 LLM 角色（多头举证 / 空头举证 / 裁判指出分歧点）只能引用
这些数字，输出过 `writer/llm.py:unverified_numbers` 闸门，越界整段丢弃。

为什么要拆成对立两方：单个总结器天然会把反面证据埋进从句。「量比 3.2 倍」既能读成
放量突破、也能读成情绪透支，强制辩论会把这种双面读数顶到台面上。

**越紧急的输出越不经过 LLM**——盘中告警纯模板，简报才上 LLM。Qwen 挂了整条链路照跑。

### 3. 价格口径必须显式

| 数据 | 复权 | 用途 |
|---|---|---|
| TickFlow 日线 | **前复权** | 均线、趋势、威科夫、支撑压力的**相对**关系 |
| 新浪分钟线 | **不复权** | 买卖点、止损、目标——所有要挂单的价格 |

前复权序列里的「支撑位 60 元」直接挂单是错的（只要分过红）。`advice/engine.py` 用两条
序列同一交易日的收盘价之比反推复权因子换算回真实价格空间；比值落在 `[0.2, 5.0]` 外就
判定对不上，宁可不给也不给错的。

台账用**相对百分比**记录价位（`journal/records.py`），核对时套到前复权序列上——百分比
对复权免疫，这是唯一能跨两种口径正确核对的方式。

### 4. 没数据 ≠ 中性

覆盖率不足的板块 `trusted=False`，排序永远垫底且不进候选池；大盘方向直接返回
「数据不足」而不是「中性」。给中性默认分会让「无知」压过「测量出的走弱」。

## 四、盘中监控：按跃迁告警

每 2 分钟一轮，四小时约 145 轮。按状态告警会直接刷屏，所以只在**跃迁**时发。

| 级别 | 触发 | 重发规则 |
|---|---|---|
| ACTION | 进入买入区间 / 跌破止损 / 触及目标 | 买入区间 30 分钟冷却；止损与目标每日一次 |
| WARN | 跌破分时均价 / 情景切换 / 量比 > 3 / 突发风险公告 | 15-30 分钟冷却 |
| INFO | 站上分时均价 / 创当日新高 | 默认关闭 |

候选池只推 ACTION——那是机器的选股，不是你决定要盯的。

**止损与目标在开盘 15 分钟后钉死，买入区间继续跟随分时均价。** 每轮重算的止损永远
在当前最低价下方，价格因此永远跌不破它，`stop_break` 结构上无法触发——跟着价格往下
走的止损不是止损。而「现在该在哪买」本来就该随均价动。

## 五、持续学习：四步只做前三步

样本量不够时的在线学习就是过拟合。

1. **记账**——每条建议落台账：标的、日期、分数、买入区间、止损、目标、板块、理由、
   facts 快照哈希。哈希让「当时到底看到了什么」可复现。
2. **兑现核对**——T+1..T+5 拉实际日线算：有没有进入买入区间？先碰止损还是先碰目标？
   最大有利偏移 MFE / 最大不利偏移 MAE 各是多少？
3. **统计**——按分数分桶、板块、趋势状态分组报兑现率。样本不足的分组照列但标注
   `trusted=False`——「样本太少」本身就是结论的一部分。
4. **标定**——触发条件是台账里有 **200 条已兑现记录**（`journal/stats.py`），不是
   「攒了两周」。在那之前统计只报告、不回写任何权重。

前两步无论最后走不走模型都不白做，而且顺带回答一个现在根本答不上来的问题：
**这套规则打分到底有没有用。**

```bash
ashare-ds review                      # 核对 + 出统计
ashare-ds journal --symbol 600519.SH  # 某只票的历史建议与兑现
```

## 七、付费档能买到什么

实测把这个问题的答案改小了很多。

| 付费档提供 | 免费替代 | 值不值 |
|---|---|---|
| `quotes` 实时报价 | 新浪/腾讯批量快照，5 只 171ms | ❌ 不值 |
| `depth` 五档盘口 | 新浪 `hq.sinajs.cn` 全带五档 | ❌ 不值 |
| `klines.intraday` 分钟线 | 新浪 `stock_zh_a_minute` | ⚠️ 看周一盘中时效 |
| `stream` **websocket 推送** | **无免费替代**（只能轮询） | ⚠️ 唯一真差异 |

**唯一买得到的真差异是推送 vs 轮询。** 免费档已经能拿到实时报价和五档，早先「五档只能
付费」的判断是错的——那条结论只测了东财 `stock_bid_ask_em`（在本机不可达的 `push2` 上），
没测新浪的行情主机。

**付费也买不到的**：集合竞价撮合量/未匹配量。任何档位都没有，加上 09:20–09:25 交易所
不接受撤单，竞价拦截这条路走不通。见 [`docs/PLAN_REVIEW.md`](PLAN_REVIEW.md)。

## 九、诚实边界

- 大模型归因**会错，而且错得像对的**。实测两个真实缺陷：模型自报的序号整体偏一位，
  导致整批标签错行（「法国森林火灾」拿到了「动画电影票房超预期」的归因）；以及模型
  会给海外灾害硬凑 A 股板块。现在的防线是——对齐只认模型回抄的标题前缀（可拿原文
  核对），核不上就丢；归了板块却说不出传导机制的按未归因处理；半数以上对不上则整批
  作废。实测 180 条快讯里 95 条归到板块，其余模型主动弃权。

- 板块打分、个股打分、买卖点位的权重**全部人工设定，未经回测**。它们解决「先看哪里、
  哪个价位重要」，不是方向预测。台账建起来就是为了终有一天能回答这个问题。
- 板块归因默认走**大模型**（`news/llm_classifier.py`），模型只输出标签（属于哪些板块、
  方向、事件类型、传导机制），**不输出任何数字**；标签到分值仍是规则层的固定映射。
  没配 key、调用失败、或对齐核不上，整批退回关键词词典，简报里写明本轮走了哪条路。
- 舆情是关键词匹配或模型标签，都会误归因，所以板块级上限 ±12 分、个股级 ±6 分，都压不动量价。
  样本量另有一道闸：文档数不足 8 条时按 `条数/8` 折权。**没有这道闸时实测出现过
  基础化工靠 2 条快讯拿满 +12、计算机 22 条只拿 +2.0**——`intensity` 是命中密度而非
  证据量，样本越小平均密度越高，方向正好反了。
- 舆情按发布时间做 12 小时半衰期折减，超过 72 小时整条丢弃；跨源同标题合并，保留
  最早发布的那条。无法解析时间戳的不折减（否则只给日期的源会被整体抹掉），但会计数
  并写进简报。
- `strong_count` 目前用涨幅 ≥ 9.5% 代替真实涨停判定——前复权价无法识别涨停板，且
  10% 与 20% 板区分不了。**`adapters/snapshot.py` 已能拿到真实涨停价/跌停价，但尚未
  接入板块动量**，见下方待办。
- 龙虎榜是 T+1 数据，反映昨天的资金。
- 免费档分钟线**盘中时效未验证**，收盘后取到的是最后一个交易日的完整数据。
- 系统不产出概率、胜率、预期收益率——没有拟合模型能支撑它们。
- 仓位系数是**建议值**，封顶 0.80，普涨末段连续折减（最多 -30%）；实际仓位以你的
  手工设定为准。

## 十、已具备但尚未接入

`adapters/snapshot.py` 已经实测可用，下面三项是它解锁的、代码还没吃掉的红利：

1. **买卖点落到真实挂单档位**——监控现在按标的轮询分钟线（0.19 秒/只），改用批量快照
   后是一次请求拿全部，并且带五档。
2. **真实涨停判定**——用腾讯的涨停价替掉 `strong_count` 的 9.5% 近似。
3. ~~涨停池 / 炸板池~~ —— 已接入，见下。

已从本节移出（现已接入主链路）：

- **涨停池 / 炸板池情绪读数**（东财 `push2ex`，214ms 取三个池）。炸板率
  `炸板 / (涨停 + 炸板)` 与最高连板进 `MarketOutlook`，上限 ±10 分。实测当日
  指数口径大盘 79.7 偏多，而炸板率 52%、107 只炸板——**指数全线上涨与封板意愿崩塌
  是同一天发生的两件事**，此前链路里一个读数都看不到后者。
  服务端对周末/盘前日期返回最近交易日，所以以响应里的 `qdate` 标注数据日期，
  而不是以请求日期。

- **个股舆情进打分**。`fetch_for_symbols` 此前实现了、测试了、无人调用，舆情只影响板块
  排序，完全不影响选出哪只票。现在走两段：量价粗排 → 每板块取 `per_sector × 3`（全局
  封顶 40 只）→ 拉个股新闻与该票当日公告 → 精排。被截掉多少会写进简报。
- **突发风险公告告警**。`MonitorSession.refresh_risk` 同样从无调用点，`risk_notice` 这条
