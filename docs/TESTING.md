# 测试与验收

## 统一检查

在项目根目录安装开发依赖后运行：

```bash
python3 -m pip install -e ".[dev]"
python3 scripts/check.py
```

入口依次运行 Ruff 静态检查、Ruff 格式检查、接线审计、文档审计、pytest；
任一失败，最终退出码非零。
各检查独立执行，静态检查失败后仍会运行功能测试。只需快速静态检查时：

```bash
python3 scripts/check.py --fast
```

`--fast` 不包含功能测试。测试数量与通过情况以当次命令输出为准。
检查以脚本所在仓库为根目录；从其他目录启动时，传入 `scripts/check.py` 的绝对路径即可。

统一格式使用：

```bash
python3 -m ruff format src tests scripts
```

开发依赖限定 Ruff 的次版本范围，避免安装时自动升级改变格式和规则。

## 构建与持续集成

```bash
python3 -m build
```

构建结果在 `dist/`，包括源码包和 wheel。`MANIFEST.in` 保证源码包包含文档、检查脚本、
测试及其公共夹具、JSON 样本、配置示例；wheel 只安装运行包与命令入口。构建默认使用隔离环境，
需要能下载构建依赖。

统一检查通过 `python3 scripts/check.py` 运行静态检查、接线审计、文档审计与全量单测，
构建源码包及 wheel 时在仓库外验证安装后的 CLI 帮助、MCP 握手与工具列表。
MCP 检查同时核对包版本和通知无回复，整个过程不调用行情工具。回归只安装开发依赖，
行情 SDK 通过测试替身注入，避免把可选依赖变成基础安装要求。

## 接线审计与清理

```bash
python3 scripts/inventory_audit.py
python3 scripts/inventory_audit.py --fields --strict-fields
```

审计共用一次 AST 快照，检查 CLI / MCP 入口、源码、脚本和测试中的消费关系：

| 口径 | 检查内容 | 退出码 |
|---|---|---|
| 模块 | 从 CLI / MCP 的导入图是否可达，含包初始化和相对导入 | 功能模块不可达计失败 |
| 公开函数与类 | 是否有转出口之外的引用，区分生产调用与仅测试调用 | 零引用或仅转出口计失败；仅测试调用单独报告 |
| dataclass 字段 | 是否有属性或字面量读取；整体序列化的字段另行核对 | 默认报告，`--strict-fields` 时计失败 |
| 公开方法 | 是否零引用或仅测试调用 | 零引用计失败，仅测试调用单独报告 |
| 私有函数与方法 | 是否还有调用方，逐层识别删除后孤立的辅助函数 | 零引用计失败，仅测试调用单独报告 |
| 模块级常量 | 是否有名称、属性或精确字面量引用 | 零引用计失败 |

可用 `--modules`、`--symbols`、`--fields`、`--methods`、`--private`、`--constants`
分别检查。文件读取或语法错误直接失败，注释不算消费者，脚本属于生产调用方。

只有测试调用的实现应核对实际用途，不能把测试覆盖当作已接入业务。
确认停用后同时删除实现、专用测试、转出口、辅助函数、配置及文档引用；仍有用途的接口
应接入消费者，或在定义处说明保留原因。历史状态的读取兼容与已有用户数据不按死代码处理。

## 手动离线检查

帮助入口只解析参数：

```bash
ashare-ds --help
ashare-ds review --help
```

手动检查持仓和 facts 时，先把 `ASHARE_DS_HOME` 指向测试目录，并为输出指定单独目录。
临时全市场试跑也使用系统临时目录作为状态和输出目录；不要把多轮试跑的日线缓存写进
`briefs/`。确认不再用于复查后，可直接清理对应临时目录。
`facts --no-live` 读取本地事实，不触发实时行情采集；空目录应明确报告缺失/降级。
可复核以下行为：

1. 登记带股数、建仓日、止损和目标的持仓，再只改成本，其他字段应保留。
2. 输入 `nan` 或非正成本应退出 2，原文件保持不变。
3. 导出离线 facts 后确认顶层 `data_status` 是状态字符串，详细状态在 `facts.数据健康`。
4. 空台账核对给出“没有待核对的建议”；坏日线或窗口不足保留待核对，并给出原因。
5. 用简写与标准代码重复平仓同一标的，`closed` 只返回一次标准代码，`not_found` 不包含已平仓代码。

## 自动检查的边界

- 文档审计读取 README 与 `docs/**/*.md` 的 shell 示例和内联命令：CLI 只验证参数解析，
  Python 脚本只检查字面量 `.py` 路径是否存在，路径以项目根目录为基准；两者都不执行。
  脚本参数、`-m` 模块调用、`-c` 内联代码、标准输入、动态路径与仓库外脚本不在检查范围内。
  本地链接只验证目标文件存在，不验证外链及页内锚点；全部现存文档都检查命令和链接。
- 接线审计按名称近似匹配，同名符号、递归引用和动态分派需要人工核对；通过扫描不能替代 CLI、调度和 MCP 行为测试。
- 并发回归包括 `spawn` 方式启动的独立进程；Linux 运行这些用例不等于验证了 Windows 文件锁，
  Windows 部署仍需在本机运行同组测试。文件锁只覆盖使用同一协议的本机写入者。
- 离线通过不代表外部接口当前可达、盘中数据足够新或策略有效。接口审计会联网和消耗配额，
  使用方法及历史结果见 [DATA_SOURCES.md](DATA_SOURCES.md)。
