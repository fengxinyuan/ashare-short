# 舆情与板块链路

盘前 top-down 链路的设计与数据边界：**舆情 → 板块排序 → 板块内选股**。

对应实现：`news/`、`sectors/`、`screens/`、`writer/`、`jobs/sector_scan.py`。

### 宏观快讯补的是一个实测出来的缺口

2026-08-02 实测：原有三路舆情在全市场 200 条里的关键词命中——

| 关键词 | 命中 |
|---|---|
| 伊朗 / 中东 | 66 / 26 ✅ 地缘覆盖得很好 |
| **PMI / 统计局 / 制造业** | **0 / 0 / 0** |
| **美债 / 收益率 / 降准 / 关税** | **0 / 0 / 0 / 0** |

也就是说**宏观数据发布对系统完全不可见**。同一天 07-31 09:30 公布的「中国 7 月官方
制造业 PMI 49.2（前值 50.3）、非制造业 49.0、综合 49.3」三个全线跌破荣枯线——链路里
一个字都没有。这不是权重问题，是这类消息压根没进来。

对盘前研判是硬缺口：板块方向可以靠量价推，**风格切换不行**。PMI 破荣枯线直接对应
「宽松预期升温 → 红利/消费占优、顺周期走弱」，而这条推理链的输入端是空的。

接入后实测：舆情从 200 条 → **324 条（去重后）**，归到板块的从 81 条 → **146 条**。

**翻页按时间窗而不是页数**：两个频道流量差一个数量级，固定页数会让高流量频道只翻到
几小时前——07-31 09:30 的 PMI 恰好落在那个盲区里。窗口锚在 `trade_date`，所以同一个
交易日无论几点跑，取回的输入都一样。

## 链路

```text
1. 板块定义   TickFlow universes  →  31 个申万一级行业（335 个分片按名合并）
2. 板块动量   成分股日线（批量）  →  中位涨幅 / 上涨占比 / 量比 / 站上 MA20 占比
2b. 板块指数  同花顺 90 个行业指数 →  收盘日内位置 / 距 20 日高 / 量比（**并列读数，不参与打分**）
3. 舆情       财联社+东财+联播+华尔街见闻 →  词典打分  →  按行业关键词归因
4. 资金       龙虎榜净买额        →  按成分股汇总到板块
5. 板块排序   动量(±30) + 舆情(±12) + 资金(±8) + 基准 50
6. 硬筛       ST/退市/非可交易板块 → **可交易性（流通市值/成交额）** → 致命公告否决
7. 个股打分   已有的日线技术面 + 威科夫 + RuleBasedScoreProvider
8. 出稿       模板渲染 →（可选）LLM 改写 → 数字校验 → 合规文本追加
```

### 2b：为什么要第二套板块读数

申万成分股聚合（步骤 2）拿不到两样东西：

1. **市值加权的板块指数本身**——所有人嘴里的「半导体今天跌了多少」说的是这个，不是
   成分股涨跌幅的中位数。两者不一样的时候恰恰是信息：指数涨、宽度弱 = 权重股拉抬。
2. **板块级的日内位置**——收盘落在当日区间的哪个分位。2026-07-31 实测：半导体
   **+4.23% 却收在当日最低**（收位 0%），同日白酒 +0.63% 收在当日最高（收位 97%）。
   「涨了多少」两者都是正的，「谁在被卖」只有收位看得见。

它**刻意不参与打分**：同花顺 90 个行业 ≈ 申万二级粒度，硬映到申万一级 31 个只会造出
一个看起来精确的错数。两套读数并列呈现，由人（或写稿层）去读它们的分歧。

数据源无限流，90 个板块不占 TickFlow 60 次/分钟的配额（申万聚合要吃掉 45 次）。

### 6：可交易性这一层此前是空的

候选池原来只过 ST 与致命公告——一只 15 亿流通、日成交 3000 万的票和茅台在筛选层面
完全等价。**超短线的核心风险不是买错，是卖不掉**，而此前没有任何一层看这件事。

现在按流通市值 ≥ 20 亿、日成交额 ≥ 0.8 亿过滤（`screens/liquidity.py`，阈值可传参）。
实测一次盘前扫描剔除 **242 只**。取值偏松是刻意的：这一层的职责是**排除不可交易**，
不是替使用者选票。

拿不到行情的标的**一律放行**并单独计数——用「没测到」当否决理由，等于让数据缺失冒充
风险判断。

## 三个刻意的设计决定

### 覆盖率不够的板块被排除，而不是给默认分

一个成分股拿不到日线的板块，`trusted=False`，倾向显示「数据不足」，**永远不会被选中**。

原因：如果给它中性 50 分，那么「没数据」会压过「有数据但走弱」（走弱的板块会低于 50）。排序里最不该出现的就是无知胜过测量。

### 仓位建议系数封顶 0.80，且在普涨末段下调

映射不是 `宽度 → 仓位` 的线性放大：

- 基准 `0.15 + 宽度 × 0.75`，封顶 **0.80**——任何未经回测的单一读数都不该建议满仓；
- 若宽度 ≥ 85% **且** 板块 5 日中位涨幅 ≥ 6%，乘 0.75 并写明理由。

原因：对超短线来说，「83% 个股上涨、5 日已涨 7~10%」的那天是**你来晚了**，不是起涨点。朴素的宽度映射会在情绪最热时给最大仓位，顺周期，恰好错在最贵的地方。

该系数始终是**建议值**，`--position-factor` 手工值优先，且两者都会打印出来供对照。

### LLM 不能引入任何数字

`writer/llm.py` 的闸门：生成文本中的每个数字，必须能追溯到输入 facts——逐字命中、按书写精度四舍五入命中、或经 `万/亿/%` 换算命中。否则整段丢弃，回退模板。

已知会被误判的三类格式（都已放行，有测试覆盖）：

| 形式 | 例子 | 处理 |
|---|---|---|
| 补尾零 | facts `8.1` → 输出 `8.10` | 数值比对放行 |
| 长浮点四舍五入 | facts `12198154.379999977` → 输出 `12198154.38` | 按精度比对放行 |
| 千分位逗号 | 输出 `12,198,154.38` | 正则整体识别为一个数 |
| 单位换算 | facts `0.6667` → 输出 `67%` | 按后缀 scale 放行 |

**合规文本（纪律提醒、免责声明）在生成之后程序化追加，不交给模型**。实测 Qwen 在被明确要求「保留全部风险提示」时，仍然会在概括过程中整段丢掉。

## 词典与关键词的维护

- `news/lexicon.py`：利好/利空词表 + 程度副词 + 否定词。加词是一行改动，不需要动打分逻辑。
- `sectors/keywords.py`：申万行业名 → 新闻实际用词（「电力设备」→ 光伏/储能/锂电/风电…）。**没有这张表，舆情项会全为 0**，因为新闻里从不出现「申万电力设备」这种说法。

两张表都是人工整理、未经拟合。权重是相对量级，不是概率。

## 缓存

- 舆情按「交易日 + 源」缓存到 `<output-dir>/news_cache/`，默认 TTL 1 小时；
- 板块分类缓存到 `<output-dir>/sector_taxonomy_sw1.json`，避免每次重拉 335 个分片。

缓存写入失败（磁盘满、类型不可序列化）只降速，不影响正确性——调用方此时已经拿到了实时数据。

### 分类缓存的两条完整性约定

335 个分片要打 335 次 TickFlow，而免费档闸门是 **60 次/滚动 60 秒**（见
`DATA_SOURCE_AUDIT.md` §2.1）。撞墙后如果把异常吞成「这个分片没有成分股」，写出来
的就是一份**缺片但外观正常**的分类——2026-08-01 现场那份少了 469/4430 只，31 个行业
一个不缺，链路照跑不误。缓存是永久的，一次限流会污染之后每一次盘前扫描。

所以：

1. **有任何分片取数失败就抛 `SectorTaxonomyError`，且不写缓存。** 宁可这次跑不出来，
   也不留一份不知道完不完整的分类。`_universe_get` 返回 `None` 表示取数失败，与
   「成分股确实为空」区分开——后者是合法读数，不该触发告警。
2. **缓存带 `schema` 戳，无戳的一律重建。** 修复之前写下的缓存没有戳，会自动失效。

**冷启动耗时取决于档位**：免费档逐个取 335 个分片、被节流到 55/分钟，重建一次约
**6 分钟**；付费档走 `universes.batch(ids)`，两次调用 **1.58 秒**（实测输出完全一致：
31 个行业 / 4430 只成分股 / 0 个失败分片）。`--output-dir` 默认是固定的 `briefs`，所以
这个代价只付一次；用按日期命名的输出目录会每天重付——在免费档上这一点很要命，付费档
之后基本无所谓了。

批量接口不可用（老 SDK 或免费档不放行）时自动退回逐个取，完整性约定不变。

## 已知边界

- 板块打分**未经回测**，只用于决定「今天先看哪里」，不是方向预测；
- 舆情归因是关键词匹配，会有误归因，因此舆情项上限只有 ±12 分，压不动量价；
- `strong_count` 用的是涨幅 ≥ 9.5% 而非真实涨停判定，因此分不清主板 10% 与创业板/科创板
  20%。**数据侧这条限制已经解除**——付费档 `instruments.batch` 对全 A 5534 只的涨跌停价
  100% 覆盖、一次 0.97 秒（实测宁德时代 482.26 = 20%、平安银行 12.77 = 10%）。没有立刻改用
  是因为 `strong_count` 直接喂板块打分，换判据会让历史板块分数不可比，必须连同阈值重标定
  一起做，见 `sectors/momentum.py` 注释；
- 龙虎榜是 T+1 数据，反映的是昨天的资金，不是今天的；
- **公告风险否决用的是上一个有公告的自然日**：盘前 08:30 跑时当日公告尚未披露，周末与
  节假日更是一条都没有（akshare 在空结果上抛 `KeyError: '代码'`，不是返回空表）。所以
  按自然日回退最多 5 天，实际用的日期会写进 note。回溯 5 天还取不到就明说「本次没有公告
  风险否决」——这一层静默消失比缺一条候选危险；
- **新闻联播同理**：盘前跑时今晚的联播还没播，硬取「今天」的结果是政策主线源每天早上
  静默缺席（实测 2026-08-02 返回 0 条，而 07-31 有 15 条）。已改为回退最近一期有稿的日子；
- 同花顺行业指数**不参与打分**，只并列呈现，理由见上文 §2b；
- 可交易性阈值（流通 20 亿 / 成交额 0.8 亿）**未经回测**，是行业惯例量级不是拟合结果；
  它只排除「进出困难」，不代表通过的票就流动性充足；
- 涨停池的「连板高度」只认东财 `lbc`。同一行里的 `zttj` 是**「N 天 M 板」统计窗口**，
  不是连板数（爱丽家居 `{'days':20,'ct':10}` + `lbc=9` = 20 天 10 板、当前连 9 板）。
  读错字段会把统计窗口当高度，而这个数直接进情绪打分（≥5 加分、≤2 减分），一只
  「10 天 5 板」的**首板**股会把减分翻成加分；
- 免费档没有分钟线与实时行情，本链路只能用于**盘前研判**；付费档（Pro）已补上分钟线与
  实时行情，盘中监控与做 T 提示因此可跑，但 **盘中时效仍未实测**——非交易时段测不出来，
  见 `DATA_SOURCE_AUDIT.md` §六；
- **两家的分钟线并不逐根相同。** 量纲对齐之后，TickFlow 与新浪重叠的 1970 根 1 分钟线
  里完全一致的只有 **39%~61%**，相对差中位 ~1e-4、最大 **0.15%~0.31%**（不同厂商把逐笔
  归并到分钟的边界处理不同，不是谁错了）。含义是：换一条路会让价位漂移最多约 0.3%，
  所以不要把两条路的读数混进同一次计算，也不要拿一条路的历史去回测另一条路要跑的规则；
- **回测仍然没做。** 板块打分权重、`advise` 的价位规则、仓位系数映射全部是人工设定。
  付费档的 12 个月分钟历史（`adapters/tickflow_intraday.fetch_minute_history`）是这件事
  第一次具备的前提条件，但前提条件不是结论——在跑出回测之前，上面每一处「未经回测」
  都仍然成立。
