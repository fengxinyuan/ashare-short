# 系统架构

系统负责 A 股事实采集、条件分析、提醒和复盘，用户维护持仓并自行判断、执行交易。
默认输出确定性事实和模板报告；各命令的模型默认行为见 [模型开关](USAGE.md#模型开关)。

操作见 [使用指南](USAGE.md)，计算细节见 [链路详解](PIPELINE.md)，
验证方法见 [测试指南](TESTING.md)。

## 全天工作流

| 阶段 | 入口与实现 | 输出 |
|---|---|---|
| 舆情采集 | `jobs/daily_cycle.py`、`news/` | 当日缓存、来源与首次观察时点 |
| 盘前计划 | `morning`、`jobs/morning*.py` | 大盘情绪、行业/概念排序、候选、计划版本和建议台账 |
| 盘前执行卡 | `pre-open-brief`、`jobs/pre_open.py` | 持仓价位依据、触发条件和次日复查事项 |
| 盘中监控 | `monitor`、`monitor/` | 持仓风险、显式标的观察、板块方向确认或否决 |
| 盘后整理 | `post-close-brief`、`jobs/post_close.py` | 个股执行卡、每日过程复盘、次日交接与候选台账 |
| 兑现核对 | `review`、`journal/` | 完整窗口的后续行情、对照统计和规则复查提示 |

`daemon` 复用任务入口，其中盘前执行卡时段运行 `advise`；手动 `pre-open-brief` 读取并复述盘后卡。
时间表只在
[schedule/timetable.py](../src/ashare_decision_support/schedule/timetable.py) 维护，
可用 `ashare-ds daemon --dry-run` 查看。任务依赖在执行时构造，单个任务失败不阻断其他任务。

交易日历决定是否执行；缺少节假日资料时按工作日近似并说明限制。任务状态支持重启恢复，
失败重试和业务去重各自处理，不提供跨进程严格一次执行保证。

## 标的与持仓

接受个股代码的命令优先使用本次输入，省略时读取持仓。盘前候选进入简报、事实包与台账，
不自动转为后续默认名单；空仓且未指定代码时，`monitor` 仍能监控板块。

持仓成本、股数、建仓日、止损和目标由用户维护。修改时省略的字段保留，手工止损和目标
优先于系统候选；平仓只移除持仓记录，建议历史仍留在台账。组合读数描述登记持仓内部的
集中度，股数缺失时说明等权口径；系统没有账户现金和总资产，不能据此推断账户总仓位。

## 模块职责

| 位置 | 职责 |
|---|---|
| `cli.py`、`mcp_server.py`、`tool_api.py` | 参数解析、依赖构造、工具契约与结果输出 |
| `jobs/`、`schedule/` | 任务编排、时间表、交易日历和失败重试 |
| `adapters/` | 行情、分类、日历、历史数据；字段归一化、缓存与时效检查 |
| `news/` | 新闻采集、去重、归因、语料存储和主题历史 |
| `agents/` | 可独立失败的事实采集器及可选多空辩论 |
| `signals/` | 日线、分时、量价、形态、盘口等确定性读数 |
| `sectors/` | 分类、动量、轮动、主题簇、历史基线与确认台账 |
| `screens/`、`scoring/`、`strategy/` | 风险门槛、打法、评分、仓位约束和组合观察 |
| `advice/` | 个股事实、价位候选、可选模型裁决与外部裁决校验 |
| `research/` | 板块、盘前和月度研究资料，以及每日过程复盘 |
| `ask/`、`chat/`、`facts.py` | 共用事实装配、研究式问答与交互查看 |
| `writer/`、`notify/` | 模板或模型写稿、控制台/文件/飞书通知 |
| `journal/`、`state/` | 建议核对、统计反馈、持仓、锁、计划和事件归档 |
| `numeric.py`、`tabular.py`、`signals/series.py` | 有限数、表格和交易日序列的共用口径 |
| `jsoncache.py`、`artifacts.py`、`runhealth.py` | JSON 校验与原子写入、产物名称、事实健康状态 |

独立取数通过 `fanout.gather` 并行执行，结果保持输入顺序；异常和空结果分别表示失败与无内容。
数字解析拒绝 NaN、Infinity、布尔值和溢出。跨时区时间先转换为北京时间，再按交易日比较。

## 事实、规则与模型

| 层 | 负责 | 约束 |
|---|---|---|
| L1 事实 | 行情、日线结构、分时、量能、盘口与历史统计 | 数字由代码计算，保留来源、数据时点和缺失状态 |
| L2 候选 | 从已有支撑压力、分时和盘口生成价位 | 候选带依据、证据和规则默认排序 |
| L3 裁决 | 显式开启时，从候选中取舍并解释 | 只能返回已有候选键，可弃权，不能创造价格 |

规则默认价位必须进入候选集合，额外候选的距离护栏不能排除默认结果。突破候选可高于现价，
表示等待满足的条件。模型不可用或输出越界时回退规则；有效弃权保留风险管理所需的止损信息。

### 输出闸门

模型文本统一经过 `factcheck.review_output`，核对数字、措辞与已确定的立场。
缺少时段、周期或仓位依据时保留未知，不补默认值参与校验。

| 输出 | 校验标准 |
|---|---|
| 散文改写 | 数字可追溯，允许按精度舍入及万、亿、百分比换算 |
| 价位裁决 | 数值必须属于已有候选集合 |
| 外部裁决包 | 候选键和数字 token 必须可追溯到输入，并检查时效 |

越界文本丢弃并说明原因，回退确定性结果；未来概率、胜率或预期收益不能由模型补造。
纪律文本由程序追加。盘中紧急告警直接使用模板，裁决器不进入监控循环。

`ask --deep` 先解析问题、生成规则决策卡和研究计划，再分步组织论证与报告。
结论、排序和 ASCII 价位轴由规则产生；显式开启模型后，模型只解释各步骤已有的事实。

## 筛选与监控

`strategy/select.py` 统一盘前、盘后与个股分析：先计算技术结构，再按条件选择和排序。
盘前粗排与舆情精排共用已算好的日线读数。情绪周期和个股趋势先决定可用打法，
条件未通过不能被其他因子的加分抵消。

| 链路 | 标的来源 | 打法处理 |
|---|---|---|
| `morning` | 行业与概念成分股的并集 | 施加情绪周期约束，未通过则过滤 |
| `post-close-brief` | 显式输入或持仓 | 施加周期约束，未通过仍保留分析并标注 |
| `advise` | 显式输入或持仓 | 分析用户指定标的，未通过仍说明原因 |

行业与概念分别排序和分配名额，概念不重复计入全市场宽度。主题重叠由研究链路按当前
数据判断。分类统一为同花顺行业与概念；行业指数与成分股中位数、宽度分别呈现，
指数涨跌不替代成分股的普涨或普跌程度。

个股与板块监控共用循环、通知通道和状态跃迁机制，各自保留会话与状态文件。
个股每轮读取分钟线，板块按 `sector_every` 采样；具体频率和触发条件见 [使用指南](USAGE.md)。

- 持仓风险优先；手工止损/目标按登记价位判断，系统结构止损/目标形成后固定。
- 告警按状态变化触发，通过冷却、合并和小时/日额度限制重复推送。
- 当前数据缺失、来自未来、陈旧或停止推进时挂起实时信号，循环继续检测恢复。
- 分钟线卖点在 `monitor/holdings.py`，日线退出依据在 `strategy/exits.py`，两者分别标明时点。

## 状态与归档

状态默认保存在 `~/.ashare-ds/`，可由 `ASHARE_DS_HOME` 覆盖：

| 路径 | 内容 |
|---|---|
| `positions.json` | 用户登记的持仓 |
| `cache/daily_bars/` | 按标的保存、按交易日合并的个股日线 |
| `sector_index/`、`overseas_index/` | 板块及海外指数历史 |
| `alerts/<date>.json`、`alerts/sector-<date>.json` | 个股、板块告警与观测状态 |
| `market/` | 板块截面、轮动记忆、主题兑现、预测兑现和确认台账 |
| `events/<date>.jsonl` | 盘中轮询、告警及采样价位 |
| `runtime/`、`daemon_state.json` | 进程互斥锁和任务完成/重试状态 |
| `journal/<month>.jsonl` | 判断版本与兑现台账 |
| `news/corpus.sqlite3` | 跨日新闻正文、来源与首次/最近观察时点 |
| `taxonomy/ths_profiles.json`、`holidays.json` | 分类缓存与交易日历 |

合并型存储在 `state.store.file_lock` 内完成读取最新状态、合并和原子替换。
只锁写入或只做原子替换都不足以防止丢更新。同目录的固定锁文件应保留。
坏状态按记录隔离，写入失败保留旧文件；缓存可读与本次刷新保存成功分别报告。

`state.runtime.exclusive_run` 限制同一状态目录中的同类 monitor / daemon 实例。
第二个实例立即报告占用，任务结束或进程退出后可重试；daemon 内部监控也需取得 monitor 锁。
告警写入失败仍返回本轮结果，调度写入失败仍维护内存进度，同时说明重启恢复的限制。

`--output-dir` 与状态目录分开，默认 `briefs/`。`plans/<date>.jsonl` 保存不可变计划版本；
`daily-reviews/<date>.json` 和同名 Markdown 保存复盘，`daily_review_latest.json` 指向最新结果。
同日改判追加版本，较早截止时点的回放不覆盖较晚档案，最新索引也不倒退。

新闻响应缓存用于避免重复请求，SQLite 语料库用于按标的、板块和时间检索原始证据。
新闻发布时间与首次采集时间分开保存；转发不增加新事件数量，事后补录标签只用于检索对照。

## 台账与复盘

入选、紧邻落选对照和被否决样本分别保存。核对要求建议日价格及完整后续交易日窗口，
缺失时保留待核对并说明原因；未来行情、更晚日期或重复日线不能补足缺失窗口。

统计按共同交易日、相同兑现窗口比较。总体取同股票、日期、来源的首次判断，
策略版本分组各取该版本首次判断；重复运行不扩大样本，旧记录保留原关联口径。
普通核对不自动重算已有兑现结果，也不自动修改权重或门槛。

百分比价位锚定在参考价所在的交易日（盘前晨报为上一交易日），核对窗口从计划日开始。
每条兑现记录并存两套口径：信号口径从参考收盘起算、不管有没有买到；执行口径先成交
（无买入区间按计划日开盘价，有区间按限价）、成交当日不可卖、跳空穿越止损或目标按开盘价
成交，开盘已在止损下方或已越过目标的计划不进场，一字涨停不成交、一字跌停不能止损并顺延。
统计侧扣一笔来回成本，按成交计划日归集入选与对照的逐日收益，并另按盈亏比和止损距离分桶。

每日复盘按截止时点连接计划、盘中过程、新闻首次采集时点和价格证据，产出次日复查项。
事件关联发生时已归档的计划背景，不代表监控已重新加载该计划。
原始计划或过程缺失时标明部分覆盖，不事后补造判断、成交或消息因果。

## 失败与降级

| 情况 | 行为 |
|---|---|
| 单个数据源失败 | 保留其他结果，标明缺失来源与影响 |
| 分钟线缺失 | 只给日线结构，明确前复权价格口径 |
| 日线缺失或与分钟线尺度不符 | 不引用对应历史位置，保留可用分时事实 |
| 五档缺失 | 缺少挂单墙候选，封板状态保持未知 |
| 全部舆情源失败 | 板块排序依赖可用量价，说明舆情缺失 |
| 全市场扫描失败 | 标明可交易性未测到，不把缺失数据当作已确认风险 |
| 分类分片失败 | 报告分类不可用，不把缺片结果写为完整缓存 |
| 模型不可用或输出越界 | 回退模板或规则默认值 |
| 飞书推送失败 | 返回失败，控制台和文件通道继续处理 |

## 能力边界

- 排序分数和情景不等同于未来胜率或收益预测。固定板块价格基线不代表整条选股、裁决和执行链路的表现。
- 板块相关性按共同交易日配对，检查分窗稳定性与多重比较；历史关系不保证样本外稳定，未入榜仅表示证据不足。
- 五档挂单可以撤销，逐笔方向为行情方推断，本地筹码为估算；这些数据不等于真实委托意图或账户持仓分布。
- 日线无法确定同根 K 线内止损和目标的先后，条件触发不等于成交；系统不提供集合竞价拦截或证券交易执行。
- 每日复盘的跨日汇总只描述近期过程覆盖，尚无实际成交与通知回执，不能据此计算真实收益、漏报率或消息因果。
- 一个判断的多个兑现核对版本、显式迁移和完整错因追踪尚未实现；买入与止损候选也尚未逐项配对失效关系。
- 文件锁只协调采用同一协议的本机写入者。Linux 并发测试不能替代 Windows 本机验收，不提供跨主机事务。
- 离线测试不验证接口当前可达性或盘中延迟；接口结论需带测量日期与条件，见 [数据源说明](DATA_SOURCES.md)。
