# 架构

总览见 [`SOLUTION.md`](SOLUTION.md)。本文写模块职责、层次边界、调度与状态、失败模式。

如果你是来找命令和场景对应，先看 [`USAGE.md`](USAGE.md)。

> **实现状态约定**同 `SOLUTION.md`：未建的一律标「⬜ 未建」。

```text
                    ┌──────────────┐
                    │  scheduler   │  时间表 · 交易日历 · 幂等 · 失败隔离
                    └──────┬───────┘
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
     jobs/*.py        monitor/loop      journal/*
     （纯函数）        （盘中循环）      （台账与兑现）
          └────────┬───────┴────────┬───────┘
                   ▼                ▼
              state/            notify/
       持仓·告警·台账          控制台 · 文件 · 飞书
```

`jobs/*.py` 全是纯函数：给参数、返回结果、不碰全局状态。调度层因此可以任意重排、
重试、单跑某一段，而不需要 job 知道自己是被谁调用的。

## 一、三层自主度：数字与取舍的分界

系统里最需要划清的一条线。`SOLUTION.md` §三给了买卖点的例子，这里是通用契约。

### L1 事实层 —— 确定性算子，不是 LLM

统一接口，并行执行，各自独立失败：

```python
@dataclass(frozen=True)
class Finding:
    agent: str
    ok: bool
    data: dict
    notes: list[str]

class Agent(Protocol):
    name: str
    def run(self, ctx: AgentContext) -> Finding: ...
```

| agent | 职责 | 实现 |
|---|---|---|
| `NewsAgent` | 市场级舆情采集 → 跨源去重 → 12 小时半衰期折权 → 按板块归因 | `news/` |
| `SymbolNewsAgent` | 个股新闻 + 当日公告 → 逐票情绪读数（进 `ScoreInput.news`，封顶 ±6） | `news/` |
| `LlmNewsClassifier` | 大模型舆情归因：板块 · 方向 · 事件 · 传导机制。**只出标签不出数字**，失败退回词典 | `news/llm_classifier.py` |
| `LimitPoolAdapter` | 涨停池 / 炸板池 / 跌停池 → 炸板率与最高连板，进大盘情绪 | `adapters/limit_pool.py` |
| `SectorMetricsAgent` | 成分股日线聚合成板块动量 | `sectors/momentum.py` |
| `RotationRead` | 板块轮动：相对强弱排名变化 · **两个窗口**的高低切换 · 主线持续度 | `sectors/rotation.py` |
| `TurnoverMigration` | 成交额占比迁移 × 价格方向 → 四象限；另出全场总量与绝对额榜 | `sectors/turnover.py` |
| `BroadIndexAdapter` | 8 个宽基指数（**市值加权**），与等权宽度对照出背离 | `adapters/broad_index.py` |
| `TencentDetailAdapter` | 成交逐笔 → 主动买占比 · 大单净额 · 尾盘净额（旁证，不进打分） | `adapters/tencent_detail.py` |
| `PriceAgent` | 日线结构：趋势、均线、支撑压力 | `signals/daily_technical.py` |
| `StructureAgent` | 威科夫阶段 | `signals/wyckoff.py` |
| `IntradayAgent` | 分时结构：VWAP、日内位置、量能 | `signals/intraday.py` |
| `OrderBookAgent` | 五档：委比、挂单墙价位、spread、真实涨跌停 | `signals/orderflow.py` + `adapters/snapshot.py` |
| `CapitalAgent` | 龙虎榜净额归因 | `news/akshare_source.py` |
| `FactorContext` | 板块关系、个股资金归一化、持续量价、业绩与政策/事件催化，统一传给评分器 | `scoring/context.py` |
| `FactorLedger` | 保存分项贡献与上下文，支持后续按因子复盘 | `strategy/select.py` + `journal/records.py` |
| `RiskAgent` | 否决性公告/可交易性/业绩风险 | `screens/` |

叫 agent 是因为它们**自治、可并行、可单独失败、输出同一种结构**——不是因为里面有模型。
**系统里所有数字都只在这一层产生。**

并行是实打实的收益：分钟线是每标的一次 HTTP、串行 1.0 秒/只，8 线程降到 0.19 秒/只
（20 只 3.8 秒，实测）。这是监控循环可行的前提。

### L2 候选层 —— 规则生成带出处的选项

`advice/candidates.py`。L2 不输出「那一个答案」，输出的是**一组带依据的候选**：

```python
@dataclass(frozen=True)
class PriceCandidate:
    side: str          # entry | stop | target
    price: float
    basis: str         # "五档买盘墙" / "分时均价回踩" / "日线支撑" / "20日高"
    evidence: dict     # 支撑这个价的 L1 读数，供 L3 引用
    default_rank: int  # 规则自己的排序，L3 可以推翻
```

规则仍然给出 `default_rank`——LLM 不可用时直接取 rank 0，链路照跑。

**规则自己的默认值无条件进候选集。** 候选集另有两道距离护栏（买入位现价下方 6%
以内、止损位 9% 以内），它们只作用于**额外**候选，不作用于 rank 0。原因是一条
不变量：`advice.entry_low` / `advice.stop` 必须永远出现在自己的候选集里。护栏
把 rank 0 筛掉的话，L3 的闸门会把引擎自己报的价判成越界，台账里的 `rule_stop`
也会和 `stop_price` 对不上——两处都不报错。第一版就是这么写的，只在跌得够深的
那些日子里破，而那恰好是最需要止损位的时候。

### L3 裁决层 —— 模型做取舍，不做算术

`advice/adjudicate.py` 与 `agents/debate.py`。

| 角色 | 职责 |
|---|---|
| `LevelAdjudicator` | 从 L2 候选里选价、说明依据、可弃权（"今天不该买"） |
| `BullAgent` | 从 facts 里找支持做多的证据，逐条引用 |
| `BearAgent` | 从同一份 facts 里找反对的证据 |
| `JudgeAgent` | 对比两方，指出关键分歧点和它取决于哪个价位 |

为什么多空要拆成对立两方：单个总结器天然会把反面证据埋进从句。「量比 3.2 倍」
既能读成放量突破、也能读成情绪透支，强制辩论会把这种双面读数顶到台面上。

**裁决器凭什么造不出新价位。** 不是靠提示词说「不许编」——那是请求，不是约束。
是靠两件事：它输出的是候选的 **key**（`entry:五档买盘墙:22.800`），要么能查到
要么查不到，它没有「写一个数」的通道；说明文字再过一道精确相等的闸门。

**弃权是一等公民。** 规则层永远能算出一组价位，但「今天这只票不该买」是一个真实
且常见的结论，规则层表达不了它（它没有「不给答案」这个输出）。这是裁决层相对
规则层最有价值的增量。弃权只清买入侧，止损位保留——「今天不该买」和「今天不该
拿」是两个问题。

**裁决器不进盘中循环。** 它是每标的一次 LLM 调用；20 只票的一轮监控会变成 20 次
网络往返、几十秒延迟、二十个失败机会，而告警要的是秒级时效。它的位置在
`advise`（你主动问）和盘前执行卡（一天一次）。见 §五。

### 数字闸门

全部 L3 输出过 `factcheck.py:review_output`（数字 + 措辞 + 立场三条）。买卖点裁决另有一道更严的：

```text
通用闸门（简报、对话）：数字必须能追溯到 facts —— 逐字 / 按精度舍入 / 万亿% 换算　✅ 已建
买卖点闸门（裁决）    ：价格必须**恰好等于**某个 L2 候选或 L1 读数　　　　　　　　 ✅ 已建
```

后者更严是因为「近似匹配」在价位上是危险的：22.95 和 22.96 在文本比对里都能过，
但那是两个不同的挂单价。越界即整段丢弃，回退 L2 的 `default_rank == 0`。

合规文本在生成之后**程序化追加**，不交给模型——实测 Qwen 在被明确要求「保留全部
风险提示」时，仍然会在概括过程中整段丢掉。

### 选股段只有一份代码

`strategy/select.py`。盘前扫描、盘后打分、个股问答三条链路走同一段：

```text
日线 → 技术快照 + 威科夫 + 低吸画像 → 打法门槛 → 打分 → SelectedSymbol.to_row()
       └─ analyze_universe（贵，算一次）  └─ select_from（便宜，可多次）
```

拆成两步是因为 morning 要打两遍分：先用量价粗排收窄范围，再只对入围的那批拉个股
舆情精排。两遍共用同一份结构读数——合成一个函数就意味着精排时把日线分析、威科夫、
低吸画像全部重算一遍，而那是这条链上最贵的三样纯计算。

调用方的差别只剩两处，都由参数表达：

| 链路 | 标的从哪来 | 情绪周期 | 打法门槛 |
|---|---|---|---|
| `morning` | 板块成分股（自上而下） | 施加 | **过滤** |
| `post_close` | 传进来的标的，省略即持仓 | 施加 | **只标注**（`require_playbook=False`） |
| `advise` | 手工指定 | 不施加（`allowed=None`） | 只标注 |

后两条只标注不过滤，是因为**这批票是你自己点名的**：「今天没有可用打法，因为
……」是一个要说出口的结论，不是让它从结果里消失的理由。拒绝理由本身就是
「这只跌了很多的票为什么不买」的答案，它随 `setup.rejected` 进台账与执行卡。

「不能买」有两种，数据里长得不一样，两种都要能读出来：

```text
判据不过    setup.rejected           「超跌但无反转触发……只是跌得多，属于接刀」
周期挡掉    setup.blocked_by_regime  一条判据都不会被验，因为交集本来就是空的
```

改造前 `post_close` 走的是另一条管线（`research.py:ResearchPipeline` →
`DecisionMatrix`），自带一套阶跃式仓位算法与四档市场状态字符串，与 `EmotionCycle`
七档互不映射——**盘后给出的次日候选，用的正是盘前明确否定过的逻辑**，而两边没有
任何地方对账。那条管线已删除，见 [`REWORK.md`](REWORK.md) §三。

### 卖点分两处，按数据口径分

| 判据 | 在哪 | 口径 | 什么时候算 |
|---|---|---|---|
| 止损 · 目标 · 结构破坏 · 时间止损 · 浮盈回吐 | `monitor/holdings.py` | **分钟线** | 盘中每一轮 |
| 天量滞涨 · 放量跌破 MA20 · 顶背离 · 情绪周期降档 | `strategy/exits.py` | **日线** | `post_close` · `advise` · `morning` |

分开不是为了模块整齐，是因为**盘中拿到的日线最后一根通常还是昨天那根**（当日那根
要收盘才完整）。把日线口径的「天量滞涨」当成盘中告警发出去，说的是昨天的事，却带着
此刻的时间戳——那比不报更糟。

环境类那条（情绪周期切到退潮/冰点）补的是一个真实缺口：`strategy/regime.py` 此前只在
盘前选股时生效，仓位上限管的是「今天能买多少」，管不了「手上这些该不该减」。它是
**降仓提示不是清仓信号**，所以永远带上判定当时的炸板率、最高连板、跌停家数——标签是
结论，读数才是能被复核的东西。

### 盘中告警有两条并行链路

个股回答「买不买、卖不卖」，板块回答「先看哪里」。它们共用 `monitor/loop.py` 的节奏
与 `state/alerts.py` 的跃迁机制，其余全部分开：

| | 个股 | 板块 |
|---|---|---|
| 取数 | 分钟线适配器，按名单 | 全市场扫描（56 页并发），不依赖名单 |
| 频率 | 每轮（默认 120 秒） | 每 `SECTOR_EVERY`(5) 轮，约 10 分钟 |
| 触发器 | `monitor/triggers.py` 18 条 | `monitor/sector_triggers.py` 7 条 |
| 状态文件 | `alerts/<date>.json` | `alerts/sector-<date>.json` |
| 名单为空时 | 不跑 | **照跑**——空仓的日子最需要「现在该看哪个方向」 |

三处刻意的分开：

1. **状态文件必须分开。** `AlertState` 是「读进来 → 改 → 整份写回」，两个实例指向
   同一路径时后写的会把前一个的记录整片抹掉——而那正是「这条今天已经发过了」的
   唯一凭证。代价是 `chat` / `ask` / `state` 三处要**多读一次**
   （`fired_sectors_today`）：只读个股那一份的话，问「今天板块有什么异动」会答
   「今天没有任何告警」，而实际上推过。
2. **板块不受个股时效闸门约束。** 两者读的是完全不同的源；分钟线停更不代表全市场
   快照也停了，用前者否决后者会在最该看板块的那天把它关掉。
3. **板块 pass 的任何失败只落一条 note。** 板块是旁证，让它有资格中断个股那一轮，
   等于用旁证决定主线跑不跑。

板块告警的噪声预算是它能不能用的关键：377 个板块里，普涨的早盘会有几十个同时
「转强」。四道闸——只看各层前 15 名、**同一板块一轮只发一条**（四条规则同时命中时
折成一条正文）、每轮最多 5 条、**每小时最多 4 条 + 全天最多 20 条**。截断永远写进
notes：静默截断会让「只推了 3 条」读起来像「只发生了 3 件事」。

「每小时」那一层是实测补的：只有全天上限时，30 轮模拟里早盘半小时的排名 churn 会把
当天额度一次吃光，于是 13:00 一个九家涨停的真涨停潮一条都推不出来——**一个用来挡
噪声的机制反过来变成了漏报机制**。预算数的是**推送**不是触发器，否则一条折了三个
触发器的推送会扣三次额度。

### 状态目录

`ASHARE_DS_HOME` 覆盖，默认 `~/.ashare-ds/`：

```text
positions.json            持仓（人维护：成本价、股数、建仓日、计划止损与目标）
alerts/<date>.json        当日告警与观测状态，用于去重
alerts/sector-<date>.json 当日**板块**告警与观测状态（与个股分开，见上）
market/intraday_sector_<date>.jsonl
                          当日板块截面序列，一轮一行。「持续监控」的价值在序列
                          不在截面，只存最新一条就把变化本身扔了。约 3MB/天，
                          是这个目录里最大的一类，**保留 30 天**后自动清理
daemon_state.json         当日各任务完成情况，用于幂等与重启恢复
journal/<month>.jsonl     预测台账，按月
news/corpus.sqlite3       舆情语料库（持久，跨日累积）
taxonomy/ths_profiles.json 同花顺静态分类缓存（每天重取，上游 00:00 UTC 刷新）
holidays.json             节假日与调休表
```

**语料库是唯一用 SQLite 的地方**，其余全是 JSON/JSONL。理由：它是这个系统里唯一
需要**查询**的数据——按板块、按标的、按时间窗、按 first_seen 回查，且会长期累积。
JSONL 要回答「这个板块过去一周的舆情热度曲线」只能全量扫。台账用 JSONL 是因为它
是纯追加、按月分片、每次统计本来就要全读。

## 三、舆情：从缓存升级为语料库

原来的 `NewsCache` 是 TTL 1 小时、按天分目录、放在输出目录里的**临时缓存**，
跑完即弃。它解决的是「同一个早上跑两次不要重复拉」，不解决「这条消息是什么时候
第一次出现的」。

对超短线，后者才是关键：**同一条利好，10 分钟前第一次出现和已经发酵三天，
是完全不同的两件事**，而临时缓存里两者长得一模一样。

```text
采集（全天多次）
   ↓  按 (source, url) 或标题指纹去重
语料库 news/corpus.sqlite3
   ↓  记 first_seen_at / last_seen_at / seen_count
   ↓  记模型归因结果（板块、方向、事件类型、传导机制）
派生读数
   ├── 板块热度时间序列：某板块的舆情密度随时间怎么变
   ├── 新鲜度：这条是新出现的还是在重复播
   └── 事后归因：当时为什么选了这个板块，原文还在
```

缓存层保留（它仍然解决重复拉取），语料库在它下游。

## 四、调度

| 时刻 | 任务 | 做什么 | 推送 |
|---|---|---|---|
| 08:00 | `news` | 隔夜舆情全量采集，写缓存 + 入库 | 无 |
| 08:20 | `morning` | **主链路**：舆情 → 大盘 → 板块 → 选股 → 当日候选 → 台账 | 盘前简报 |
| 09:15 | `preopen` | 持仓的价位、止损、情景（昨收口径，明确标注）；持仓为空则跳过 | 执行卡 |
| 09:35–14:55 | `monitor` | 循环：时效闸门 → 买卖点重算 → 触发器 → 告警<br>每 5 轮附带一次板块截面 → 板块跃迁 → 板块告警 | 实时告警<br>板块异动 |
| 15:10 | `postclose` | 持仓打分、次日决策矩阵；持仓为空则跳过 | 盘后简报 |
| 15:40 | `review` | 台账里 T-1..T-5 的建议对照实际走势 | 复盘 |

每个任务的构造都**延迟到执行时刻**（`adapter_factory` 而不是 `adapter`）：08:00 的
网络故障不该让 08:20 的任务在构造阶段就崩掉。

非交易日整张表跳过。判定顺序：工作日 → 节假日表 → 未配置时明说「未经假期校验」。

## 五、越紧急的输出，越不经过 LLM

| 输出 | 写作方式 | 理由 |
|---|---|---|
| 盘中告警 | 纯模板 | 秒级时效，LLM 增加 2–5 秒延迟与一次失败可能 |
| 执行卡 | 纯模板 | 全是价位，没有需要组织的语言 |
| 买卖点裁决 | LLM + 候选集闸门 | 有取舍要做，但选项由规则给定；**只在 `advise` 与盘前，不在盘中** |
| 盘前/盘后简报 | LLM + 数字闸门 + 多空辩论 | 信息量大，语言组织有价值 |
| 对话 | LLM + 数字闸门 | 本来就是对话 |

LLM 不在关键路径上——Qwen 挂了，整条链路照跑，简报变模板体，买卖点退回规则默认。

## 六、降级规则

| 缺失 | 行为 |
|---|---|
| 分钟线 | 只给日线结构判断，明确标注价位为前复权口径、不可挂单 |
| 日线 | 只给分时结构，不引用历史支撑压力 |
| 五档 | 候选集里少「买盘墙/卖盘墙」两类、封板状态未知，其余照常 |
| 舆情源 | 该源计 0，简报里写明哪个源挂了 |
| 全部舆情源 | 板块排序仅依据量价动量，显式标注 |
| 日线与分钟线对不上 | 不引用日线位置，标注原因 |
| LLM 不可用或输出越界 | 回退确定性模板（L2 建成后回退其默认排序），标注原因 |
| 非当日分钟数据 | 简报顶部横幅 + 每只标的的 warning |
| 全市场扫描不可用 | **放行**而非拦截——用「没测到」当否决理由，等于让数据缺失冒充风险判断 |

## 七、失败模式

| 失败 | 行为 |
|---|---|
| 单个数据源挂 | 该 agent 的 finding 标 `ok=False`，其余照跑，简报里写明哪个源挂了 |
| 分钟线停更 | 挂起告警（`SOLUTION.md` §四.1），循环继续检测恢复 |
| 数据源限流 | 指数退避 → 降频（2→5→10 分钟）→ 挂起，每次降级推一条通知 |
| LLM 不可用 | 回退模板 / 规则默认，标注原因 |
| 飞书推送失败 | 返回 False，控制台与文件通道不受影响 |
| 单个任务抛异常 | 捕获、记日志、推一条失败通知，守护进程继续 |
| 守护进程崩溃重启 | 读 `daemon_state.json`，当天已完成的任务不重跑 |
| 非交易日 | 整张表跳过，不产出任何推送 |
| 板块分类分片取数失败 | 抛 `SectorTaxonomyError` 且**不写缓存**——宁可跑不出来，也不留一份不知道完不完整的分类 |

最后一条是实测教训：撞限流后把异常吞成「这个分片没有成分股」，写出来的是一份
**缺片但外观正常**的分类。2026-08-01 现场那份少了 469/4430 只，31 个行业一个不缺，
链路一声不响跑完。缓存是永久的，一次限流会污染之后每一次盘前扫描。

## 八、飞书推送

- webhook 从 `FEISHU_WEBHOOK_URL` 读，可选签名 `FEISHU_SECRET`
  （`timestamp\n{secret}` 的 HMAC-SHA256 base64）
- **飞书应用层错误也返回 HTTP 200**，必须检 body 里的 `code`
- 按**字节**切分（中文 3 字节/字）
- 永不抛异常：推送失败只返回 `False` 并记 note，不能拖垮分析

告警走紧凑卡片，简报走完整 markdown。控制台与文件通道始终保留——飞书挂了，本地仍有
完整记录。

## 九、人的入口没有被自动化取代

自动化解决「系统主动告诉我」，问答解决「我主动问系统」。两者读**同一份状态**。

```bash
ashare-ds ask "今天该看什么"           # 单入口：按时段自动装上下文
ashare-ds ask                         # 不带问题＝只打印上下文，一次模型调用都不发
ashare-ds ask --deep "这几只低开了"    # 分步研究：计划 → 逐步论证 → 决策卡 + 排序 + 价位轴
ashare-ds chat                        # 多轮追问，手工控制上下文
```

`ask` 省掉「先知道该敲哪个 `/` 命令」这一步，按时刻决定装什么：

| 时段 | 自动装配 |
|---|---|
| 开盘前（05:00–09:15） | 持仓 + 最近一次盘前主链路 + 最近一次买卖点 + 台账统计 |
| 盘中（09:15–15:00） | 持仓 + 盘前主链路 + 当日告警 + **现算**的实时买卖点与五档 + 台账统计 |
| 盘后（15:00–） | 持仓 + 盘前主链路 + 当日告警 + 次日决策矩阵 + 台账统计 |
| 非交易日/时段 | 最近一次的结果，且**每一条都标明是旧数据** |

盘中**不读**落盘的那份买卖点：它是上一次跑出来的，而这一刻有现算的。两份并排
放进上下文，模型无从判断该引用哪一个价。拿不到实时计算入口时才退回落盘那份，
并在 `notes` 里写明它可能已经过时——不假装它是实时的。

三条设计约束：

- **读的是自动化链路正在维护的那份状态**，不是自己重算一遍。否则「系统刚才提醒我
  的那条是什么意思」会得到一个用不同数据算出来的答案，那比不回答更糟。
- **只有盘中的实时价位是现算的**，因为它按定义就没有「已经算好的那一份」。盘前
  不算——开盘前没有当日分时，现算只会拿到昨天的数据然后被当成今天的。
- **每一块独立守卫。** 实时价位算不出来，不该把板块排序、告警、台账一起带走。

不带问题直接跑，就是把装配好的上下文原样打印——**不经过模型**。没配 key 时这是
全部功能，配了 key 时这是核对模型有没有胡说的办法。

### `--deep`：分步研究

一次调用产出整个答案有两个后果，第二个更要命：

1. **没有重点。** 模型要在整包上下文里自己决定什么重要，而它没有依据可以决定。
2. **全有或全无。** 数字闸门是整段丢弃的。三只票十五个小节，只要有一个数追溯
   不到，十五个小节一起消失，你拿到的是一堆原始 JSON。

`--deep` 把它拆开，六步里前五步确定性、只有第三步进模型：

```text
① 解析问题      标的（代码 + 已知简称）· 意图（买点/卖点/低开/风险/大盘/复盘）· 约束
                  ↓ 认不出的名字明说，不猜——猜错一个字，后面拿另一只票的数据答你
② 决策卡        每只票压成一张：结论标签 · 触发条件 · 失效条件 · 阻断项 · 关键读数
                  ↓ 三档标签（可执行/需确认/不成立）判据写死在 verdict.py，不问模型
③ 研究计划      按「意图 × 手上有什么」列步骤；系统没有的数据立成一条明确的 gap
                  ↓ 逐只 ≤4 步、总计 ≤8 步；被截掉的进速览表，且报出来
④ 分步执行      每步只看自己那一小块事实，**过自己那一道闸门**，并行跑
                  ↓ 一步被丢弃只损失那一步的论证段
⑤ 组织报告      结论先行 → 速览表 → 排序解释 → 价位轴 → 逐只卡 → 环境 → 纪律
⑥ 可视化        ASCII 价位轴与对比表，零依赖、不经模型
```

**能被丢弃的东西，本来就不该是结论。** 结论、排序、价位、触发与失效条件全部由
规则算，模型只在每张卡下面写一段论证。没配 key 时深挖路径照跑——计划照列、卡照
出、表和价位轴照画，只是每张卡下面写明论证段缺失。

排序也是确定性的（先按结论分档，再按盈亏比、评分，同分按代码）。让模型排序等于
让它在没有拟合模型的前提下给相对强弱，那正是 [`SOLUTION.md`](SOLUTION.md) §七
一直拒绝提供的东西。模型能做的是解释已经排好的顺序。

`chat` 的 `/` 命令仍然是精确控制上下文的方式：

```text
/positions    /alerts    /journal 600519.SH    /sectors    /debate    /show
```
