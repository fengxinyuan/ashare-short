# 架构

总览见 [`SOLUTION.md`](SOLUTION.md)。本文写模块职责、层次边界、调度与状态、失败模式。

> **实现状态约定**同 `SOLUTION.md`：未建的一律标「⬜ 未建」。

```text
                    ┌──────────────┐
                    │  scheduler   │  时间表 · 交易日历 · 幂等 · 失败隔离
                    └──────┬───────┘
          ┌────────────────┼────────────────┐
          ▼                ▼                ▼
     jobs/*.py        monitor/loop      journal/*
     （纯函数）        （盘中循环）      （台账与兑现）
          └────────┬───────┴────────┬───────┘
                   ▼                ▼
              state/            notify/
     自选股·候选池·告警·台账     控制台 · 文件 · 飞书
```

`jobs/*.py` 全是纯函数：给参数、返回结果、不碰全局状态。调度层因此可以任意重排、
重试、单跑某一段，而不需要 job 知道自己是被谁调用的。

## 一、三层自主度：数字与取舍的分界

系统里最需要划清的一条线。`SOLUTION.md` §三给了买卖点的例子，这里是通用契约。

### L1 事实层 —— 确定性算子，不是 LLM

统一接口，并行执行，各自独立失败：

```python
@dataclass(frozen=True)
class Finding:
    agent: str
    ok: bool
    data: dict
    notes: list[str]

class Agent(Protocol):
    name: str
    def run(self, ctx: AgentContext) -> Finding: ...
```

| agent | 职责 | 实现 |
|---|---|---|
| `NewsAgent` | 市场级舆情采集 → 跨源去重 → 12 小时半衰期折权 → 按板块归因 | `news/` |
| `SymbolNewsAgent` | 个股新闻 + 当日公告 → 逐票情绪读数（进 `ScoreInput.news`，封顶 ±6） | `news/` |
| `LlmNewsClassifier` | 大模型舆情归因：板块 · 方向 · 事件 · 传导机制。**只出标签不出数字**，失败退回词典 | `news/llm_classifier.py` |
| `LimitPoolAdapter` | 涨停池 / 炸板池 / 跌停池 → 炸板率与最高连板，进大盘情绪 | `adapters/limit_pool.py` |
| `SectorMetricsAgent` | 成分股日线聚合成板块动量 | `sectors/momentum.py` |
| `PriceAgent` | 日线结构：趋势、均线、支撑压力 | `signals/daily_technical.py` |
| `StructureAgent` | 威科夫阶段 | `signals/wyckoff.py` |
| `IntradayAgent` | 分时结构：VWAP、日内位置、量能 | `signals/intraday.py` |
| `OrderBookAgent` ⬜ | 五档：委比、买卖盘厚度、挂单墙价位、spread | ⬜ **未建**。`adapters/snapshot.py` 已能取五档，但没有调用方 |
| `CapitalAgent` | 龙虎榜净额归因 | `news/akshare_source.py` |
| `RiskAgent` | ST/退市/否决性公告/可交易性 | `screens/` |

叫 agent 是因为它们**自治、可并行、可单独失败、输出同一种结构**——不是因为里面有模型。
**系统里所有数字都只在这一层产生。**

并行是实打实的收益：分钟线是每标的一次 HTTP、串行 1.0 秒/只，8 线程降到 0.19 秒/只
（20 只 3.8 秒，实测）。这是监控循环可行的前提。

### L2 候选层 —— 规则生成带出处的选项　⬜ 未建

> 现状：`advice/engine.py` 直接产出单一组价位，没有候选集。以下是目标形态。

L2 不再输出「那一个答案」，输出的是**一组带依据的候选**：

```python
@dataclass(frozen=True)
class PriceCandidate:
    side: str          # entry | stop | target
    price: float
    basis: str         # "五档买盘墙" / "分时均价回踩" / "日线支撑" / "20日高"
    evidence: dict     # 支撑这个价的 L1 读数，供 L3 引用
    default_rank: int  # 规则自己的排序，L3 可以推翻
```

规则仍然给出 `default_rank`——LLM 不可用时直接取 rank 0，链路照跑。

### L3 裁决层 —— 模型做取舍，不做算术

`LevelAdjudicator` ⬜ 未建；多空辩论三角色已建。

| 角色 | 职责 |
|---|---|
| `LevelAdjudicator` ⬜ | 从 L2 候选里选价、说明依据、可弃权（"今天不该买"） |
| `BullAgent` | 从 facts 里找支持做多的证据，逐条引用 |
| `BearAgent` | 从同一份 facts 里找反对的证据 |
| `JudgeAgent` | 对比两方，指出关键分歧点和它取决于哪个价位 |

为什么多空要拆成对立两方：单个总结器天然会把反面证据埋进从句。「量比 3.2 倍」
既能读成放量突破、也能读成情绪透支，强制辩论会把这种双面读数顶到台面上。

### 数字闸门

全部 L3 输出过 `writer/llm.py:unverified_numbers`。买卖点裁决另有一道更严的：

```text
通用闸门（简报、对话）：数字必须能追溯到 facts —— 逐字 / 按精度舍入 / 万亿% 换算　✅ 已建
买卖点闸门（裁决）    ：价格必须**恰好等于**某个 L2 候选或 L1 读数　　　　　　　　 ⬜ 未建
```

后者更严是因为「近似匹配」在价位上是危险的：22.95 和 22.96 在文本比对里都能过，
但那是两个不同的挂单价。越界即整段丢弃，回退 L2 的 `default_rank == 0`。

合规文本在生成之后**程序化追加**，不交给模型——实测 Qwen 在被明确要求「保留全部
风险提示」时，仍然会在概括过程中整段丢掉。

### 状态目录

`ASHARE_DS_HOME` 覆盖，默认 `~/.ashare-ds/`：

```text
watchlist.json            自选股（人维护，永不自动删除；含持仓状态与成本价）
candidates.json           候选池（每早生成，隔日失效）
alerts/<date>.json        当日告警与观测状态，用于去重
daemon_state.json         当日各任务完成情况，用于幂等与重启恢复
journal/<month>.jsonl     预测台账，按月
news/corpus.sqlite3       舆情语料库（持久，跨日累积）
（hotlist.json 热门股池 ⬜ 未建）
holidays.json             节假日与调休表
```

**语料库是唯一用 SQLite 的地方**，其余全是 JSON/JSONL。理由：它是这个系统里唯一
需要**查询**的数据——按板块、按标的、按时间窗、按 first_seen 回查，且会长期累积。
JSONL 要回答「这个板块过去一周的舆情热度曲线」只能全量扫。台账用 JSONL 是因为它
是纯追加、按月分片、每次统计本来就要全读。

## 三、舆情：从缓存升级为语料库

原来的 `NewsCache` 是 TTL 1 小时、按天分目录、放在输出目录里的**临时缓存**，
跑完即弃。它解决的是「同一个早上跑两次不要重复拉」，不解决「这条消息是什么时候
第一次出现的」。

对超短线，后者才是关键：**同一条利好，10 分钟前第一次出现和已经发酵三天，
是完全不同的两件事**，而临时缓存里两者长得一模一样。

```text
采集（全天多次）
   ↓  按 (source, url) 或标题指纹去重
语料库 news/corpus.sqlite3
   ↓  记 first_seen_at / last_seen_at / seen_count
   ↓  记模型归因结果（板块、方向、事件类型、传导机制）
派生读数
   ├── 板块热度时间序列：某板块的舆情密度随时间怎么变
   ├── 新鲜度：这条是新出现的还是在重复播
   └── 事后归因：当时为什么选了这个板块，原文还在
```

缓存层保留（它仍然解决重复拉取），语料库在它下游。

## 四、调度

| 时刻 | 任务 | 做什么 | 推送 |
|---|---|---|---|
| 08:00 | `news` | 隔夜舆情全量采集，写缓存 + 入库 | 无 |
| 08:20 | `morning` | **主链路**：舆情 → 大盘 → 板块 → 选股 → 候选池 → 台账 | 盘前简报 |
| 09:15 | `preopen` | 自选股 + 候选池的价位、止损、情景（昨收口径，明确标注） | 执行卡 |
| 09:35–14:55 | `monitor` | 循环：时效闸门 → 买卖点重算 → 触发器 → 告警 | 实时告警 |
| 15:10 | `postclose` | 自选股打分、次日决策矩阵 | 盘后简报 |
| 15:40 | `review` | 台账里 T-1..T-5 的建议对照实际走势 | 复盘 |

每个任务的构造都**延迟到执行时刻**（`adapter_factory` 而不是 `adapter`）：08:00 的
网络故障不该让 08:20 的任务在构造阶段就崩掉。

非交易日整张表跳过。判定顺序：工作日 → 节假日表 → 未配置时明说「未经假期校验」。

## 五、越紧急的输出，越不经过 LLM

| 输出 | 写作方式 | 理由 |
|---|---|---|
| 盘中告警 | 纯模板 | 秒级时效，LLM 增加 2–5 秒延迟与一次失败可能 |
| 执行卡 | 纯模板 | 全是价位，没有需要组织的语言 |
| 买卖点裁决 ⬜ | LLM + 候选集闸门 | 有取舍要做，但选项由规则给定（未建） |
| 盘前/盘后简报 | LLM + 数字闸门 + 多空辩论 | 信息量大，语言组织有价值 |
| 对话 | LLM + 数字闸门 | 本来就是对话 |

LLM 不在关键路径上——Qwen 挂了，整条链路照跑，简报变模板体，买卖点退回规则默认。

## 六、降级规则

| 缺失 | 行为 |
|---|---|
| 分钟线 | 只给日线结构判断，明确标注价位为前复权口径、不可挂单 |
| 日线 | 只给分时结构，不引用历史支撑压力 |
| 五档 ⬜ | 候选集里少「买盘墙/卖盘墙」两类，其余照常（随 L2 一起未建） |
| 舆情源 | 该源计 0，简报里写明哪个源挂了 |
| 全部舆情源 | 板块排序仅依据量价动量，显式标注 |
| 日线与分钟线对不上 | 不引用日线位置，标注原因 |
| LLM 不可用或输出越界 | 回退确定性模板（L2 建成后回退其默认排序），标注原因 |
| 非当日分钟数据 | 简报顶部横幅 + 每只标的的 warning |
| 全市场扫描不可用 | **放行**而非拦截——用「没测到」当否决理由，等于让数据缺失冒充风险判断 |

## 七、失败模式

| 失败 | 行为 |
|---|---|
| 单个数据源挂 | 该 agent 的 finding 标 `ok=False`，其余照跑，简报里写明哪个源挂了 |
| 分钟线停更 | 挂起告警（`SOLUTION.md` §四.1），循环继续检测恢复 |
| 数据源限流 | 指数退避 → 降频（2→5→10 分钟）→ 挂起，每次降级推一条通知 |
| LLM 不可用 | 回退模板 / 规则默认，标注原因 |
| 飞书推送失败 | 返回 False，控制台与文件通道不受影响 |
| 单个任务抛异常 | 捕获、记日志、推一条失败通知，守护进程继续 |
| 守护进程崩溃重启 | 读 `daemon_state.json`，当天已完成的任务不重跑 |
| 非交易日 | 整张表跳过，不产出任何推送 |
| 板块分类分片取数失败 | 抛 `SectorTaxonomyError` 且**不写缓存**——宁可跑不出来，也不留一份不知道完不完整的分类 |

最后一条是实测教训：撞限流后把异常吞成「这个分片没有成分股」，写出来的是一份
**缺片但外观正常**的分类。2026-08-01 现场那份少了 469/4430 只，31 个行业一个不缺，
链路一声不响跑完。缓存是永久的，一次限流会污染之后每一次盘前扫描。

## 八、飞书推送

- webhook 从 `FEISHU_WEBHOOK_URL` 读，可选签名 `FEISHU_SECRET`
  （`timestamp\n{secret}` 的 HMAC-SHA256 base64）
- **飞书应用层错误也返回 HTTP 200**，必须检 body 里的 `code`
- 按**字节**切分（中文 3 字节/字）
- 永不抛异常：推送失败只返回 `False` 并记 note，不能拖垮分析

告警走紧凑卡片，简报走完整 markdown。控制台与文件通道始终保留——飞书挂了，本地仍有
完整记录。

## 九、人的入口没有被自动化取代

自动化解决「系统主动告诉我」，问答解决「我主动问系统」。两者读**同一份状态**。

```bash
ashare-ds chat                        # 多轮追问（已建）
```

⬜ **`ask` 单入口未建。** 目标是省掉「先知道该敲哪个 `/` 命令」这一步，
按时刻决定装什么进上下文：

| 时段 | 自动装配 |
|---|---|
| 开盘前 | 大盘方向 + 板块排序 + 候选池 + 隔夜舆情 |
| 盘中 | 上述 + 自选股/持仓的实时买卖点 + 五档 + 当日告警 |
| 盘后 | 上述 + 当日兑现 + 台账统计 |

在它建成之前，`chat` 的 `/` 命令是精确控制上下文的方式：

```text
/watch    /alerts    /journal 600519.SH    /sectors    /debate    /show
```
