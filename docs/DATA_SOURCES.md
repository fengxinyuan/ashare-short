### 2.1 「每次调用都稳」不等于「链路能跑完」——TickFlow 有硬闸门

**测于 2026-08-02。** 上表每格测的是**单次调用**，永远碰不到配额。盘前全链路一次要打：

| 阶段 | 调用次数 |
|---|---|
| 申万 SW1 分类（335 个分片，冷启动） | 335 |
| 板块动量（4430 只 / 100 一批） | 45 |
| 候选股 240 日历史 + 标的信息 | ~15 |

**实测闸门：60 次 / 滚动 60 秒，第 61 次必定 429。** 而 60 次只花 22.5 秒——
按自然节奏打，配额会以 **2.7 倍速**烧光。错误消息里带服务端自报的等待时长
（`请 38266ms 后重试`），比任何本地猜测都准。

后果是**两个都不响的故障**：`morning` 跑到候选股取数时直接崩；更糟的是分类层把异常
吞成空成分股，**残缺的分类被写进缓存**（3961/4430 只，静默少 469 只，31 个行业一个
不少，文件外观完全正常）。

**已修**（`adapters/ratelimit.py`）：客户端滑动窗口令牌桶（默认 55/60s，
`TICKFLOW_RATE_LIMIT` 可覆盖）+ 撞墙后按服务端等待时长退避。闸门包在 SDK client 上
而不是适配器方法上——`taxonomy.py` 拿的是 `adapter.client` 直接调 `universes.*`，
包方法覆盖不到那条路径。

| | 修复前 | 修复后 |
|---|---|---|
| 连打 80 次 `universes.get` | 第 61 次 429 崩 | 80/80 成功，66s |
| SW1 分类冷启动 | 3961/4430（静默缺片） | **4430/4430，0 分片失败**，363s |
| `ashare-ds morning` 全链路 | 崩在 `_rank_candidates` | **跑完，72s（缓存命中）** |

### 2.2 逐笔明细：翻页必须从第 0 页起

腾讯 `detail` 端点按页返回当日成交（3 秒切片，带 B/S/M 方向）。**页号从 0 开始，
第 0 页装 09:25 集合竞价那一笔与开盘后约 8 分钟的成交。** 从第 1 页起会把它整段丢掉，
而缺口精确等于第 0 页：

| 标的（2026-08-03） | 第 0 页 | 占全天成交额 |
|---|---|---|
| 利欧股份（当日 +10.09%） | 16.71 亿 | **23.9%** |
| 中际旭创 | 30.86 亿 | 10.6% |
| 德明利 | — | 12.9% |
| 华能国际 | 0.36 亿 | 4.1% |

缺口**对跳空与涨停的标的最大**——正是超短最在意的那批。修复后逐笔合计与行情
成交额的偏差从 4–24% 降到 **0.0%**（中际旭创 291.5 亿 vs 291.4 亿）。

两条口径不能省：B/S 是腾讯按当时盘口的**推断**，不是交易所委托方向；竞价那一笔
本身没有主动方，但实测它对主动买占比的影响只有 -0.7~+1.3pp（占全天主动成交
0.4%~2.9%），所以照单收下、不单独剔除。

### 2.3 北向资金：已停止披露，不是取不到

`stock_hsgt_fund_flow_summary_em` 能通（走 `datacenter-web`），但**净买额恒为 0、
历史序列全为 NaN**——沪股通/深股通的实时资金流数据已不再发布。有数的只有南向
（2026-08-03：沪港通 64.28 亿 + 深港通 46.03 亿）。

这条单独写出来，是因为它长得像故障：接口 200、返回结构完整、字段齐全，只是数字
全是 0。**不写清楚的话，下一个人会去调重试、换源、怀疑代理**，而那里根本没有数据。

同一个响应里**有用的**是涨跌家数（2026-08-03 沪市 1078 涨 / 543 跌、深市 1357 涨 /
498 跌），它和当天上证 -0.59%、深证 -0.96% 一起，是「宽度为正、指数为负」最直接的
一组交叉印证。

### 2.4 官方栏目：两种「看起来正常」的失效（2026-08-09 实测）

给舆情层补 `health_check()` 之后当天就查出两件事，都不会抛异常：

**一、`gov.cn/zhengce/zuixin.htm` 已经变成 meta-refresh 跳转壳子。** HTTP 200、
正文 856 字节、一条带日期的链接都没有——于是国务院这一路**静默产出 0 条**，而它
是链路里除新闻联播外唯一的国内政策输入。跳转目标 `zuixin/home.htm` 现在 404，
`zuixin/` 只有 12 条且混着站点导航，**`gov.cn/zhengce/` 才是今天在更新的那一版**
（实测 12 条真实政策条目）。已改指后者。

这一类失效比 404 危险：404 会进 note，200 + 空结果只会让这一路从简报里消失。

**二、`bls.gov` RSS 本机 403。** 换 UA 无效（试过完整 Chrome UA 串），`api.bls.gov`
同样 503——是 CDN 层拦的，不是接口问题。缺的是**就业与通胀**那一块，而这正是
「宽松预期 → 风格切换」那条推理链的输入端。

补的办法不是找 BLS 的镜像，是找**另一个官方口径**：

| 新增源 | 补的读数 |
|---|---|
| 美国经济分析局 `apps.bea.gov` | GDP、**个人收入与支出（PCE）**、贸易差额 |
| 美国人口普查局 `census.gov` | 零售、耐用品、批发库存、新屋销售、营建支出 |

**PCE 不是 CPI 的退而求其次，它是更该看的那个**——议息决策盯的本来就是 PCE。
实测两路可达，海外官方从 2/3 路 34 条变成 4/5 路 82 条，而并发之后**墙钟时间没
有变化**（这一段由能源信息署那一路决定，见第四条）。

**非农仍然没有第二个官方来源**，只能靠华尔街见闻那一路的中文快讯兜。BLS 保留
在册不删：「取不到」和「不存在」是两回事，换个部署环境它就回来了，而并发之后
它 0.25s 就失败，代价只有 note 里的一行。

**四、能源信息署那一路是这一段的地板。** 实测连跑三次 10.55s / 9.85s / 9.54s，
响应只有 10KB——是服务端延迟，不是载荷大小。并发之后整个舆情层的冷跑时间就等于
它（9.59s），其余十三路加起来不到 1 秒。**没有调低超时把它踢掉**：为省 7 秒丢掉
一路能用的官方源不划算，而缓存已经让这 9.5s 每个交易日只付一次。

**三、脚本正文曾经变成「标题」。** `_plain` 只删尖括号，`<script>` 与 `</script>`
之间那段 JS 是纯文本，会原样留下——央行页面因此产出过一条 1121 字的「标题」，
内容是 `var wa='RSS订阅'; document.write(wa)`。这种东西进语料库之后，词典打分会
照常在里面找多空词。已在解析前连内容一起去掉，并对导航条/页脚加了长度与分隔符
判据（实测真标题 12–63 字，导航与页脚 117–1121 字）。修完 43 条里噪声为 0。

## 三、不可用的源：是本机网络策略，不是数据源问题

**这条对付费决策最关键。**

所有域名都解析到 `198.18.0.x`（保留网段）——本机在**出口代理白名单**后面。TCP 443
能连上（代理接受），但目标不在白名单时代理直接重置连接，这正是 `RemoteDisconnected`
的成因：

```
curl push2.eastmoney.com/api/qt/clist/get    → http=000   （代理重置）
curl push2ex.eastmoney.com/getTopicZTPool    → http=200   ✅
curl hq.sinajs.cn/list=sh600519              → http=200   ✅
```

| 主机 | 状态 | 影响的接口 |
|---|---|---|
| `push2.eastmoney.com` | ❌ 被拒 | 批量行情、五档盘口、板块列表、efinance 全部 |
| `push2his.eastmoney.com` | ❌ 被拒 | 分钟线、日线 |
| `push2ex.eastmoney.com` | ✅ 通 | 涨停池/炸板池/强势股池（`stock_intraday_em` 逐笔仍 0/8） |
| `datacenter-web.eastmoney.com` | ✅ 通 | 龙虎榜、北向（但北向已停止披露，见 §2.3） |
| `hq.sinajs.cn` / `qt.gtimg.cn` | ✅ 通 | 五档、快照、涨跌停价、宽基指数 |
| `stock.gtimg.cn` | ✅ 通 | 成交逐笔明细（见 §2.2） |

**「主力资金净流入」那一套在本机全军覆没**，2026-08-04 复测 4/4 全部
`RemoteDisconnected`：

```
stock_individual_fund_flow        ❌   个股资金流
stock_market_fund_flow            ❌   大盘资金流
stock_sector_fund_flow_rank       ❌   板块资金流排名
stock_individual_fund_flow_rank   ❌   个股资金流排名
```

它们全在 `push2.eastmoney.com` 上。所以本机能拿到的多日资金口径只有三路，**每一路
都是代理量、不是真正的方向性资金流**：龙虎榜净买额（`datacenter-web`，可按 5 日/20 日
聚合）、板块成交额占比迁移（见 `PIPELINE.md` §2c）、日线的 20 日涨跌量比。逐笔那一路
只有当日。

**所以：**

- 不存在「重试能救活」的可能——这是网络策略，不是抖动或限流。
- **换到本地或国内云主机，东财全系大概率复活。**「东财已死」是**本机结论，不是数据源结论**。
- 因此：**不要为了绕开本机网络限制去买付费数据源**——那是花钱买错东西。先换部署环境验证。

> 诚实记录：16:46 单次探测中 `stock_zh_a_hist`、`stock_individual_fund_flow`、
> `stock_market_fund_flow`、efinance 全市场快照曾各成功一次；随后 8 轮受控复测 0/8。
> 按不可用处理。
>
> **2026-08-04 盘中二次实测（带指数退避重试，不是单次探测）**——结论不变，但把
> 「偶尔能通」这件事量化了，因为它正是最容易让人误判的地方：
>
> | 接口 | 结果 |
> |---|---|
> | `stock_individual_fund_flow` | 首次直接失败，退避重试**第 6 次**才通过一次，拿到 22 日分档净额 |
> | `stock_individual_fund_flow_rank` | 5 次重试 **0 成功** |
> | `stock_zh_a_hist_min_em` | 5 次重试 **0 成功** |
> | `stock_zh_a_hist` | 先成功一次，随后 6 次连续失败 |
> | `stock_zh_a_daily`（新浪） | ✅ 兜底成功，MA60 等日线读数改由它供给 |
>
> **「偶尔能通」比「完全不通」更危险。** 一次成功足以让人把它当成可用数据源接进主链路，
> 而它在需要的那天大概率不在。所以判定维持不变：**不进主链路、不进打分、不进盘中**。
> 同一次实测里 `datacenter-web.eastmoney.com` 是 `http=200 / 0.28s`，
> `push2his.eastmoney.com` 是 `http=000`——两台主机的差别是稳定的，可以据此分配依赖。

**经验法则：`push2*` 上的任何东西在本机都不可用。** 系统不依赖它们——板块行情从成分股
日线聚合，分钟线来自新浪，五档来自新浪/腾讯。

### 3.1 反过来说：`datacenter-web` 稳定可达，龙虎榜可以做深

上面那张表里 `datacenter-web.eastmoney.com` 一直是通的，而项目此前只从它取了
**个股净买额**一个数（`news/akshare_source.py:fetch_dragon_tiger`），汇总进板块打分。

2026-08-04 实测确认**席位明细同样可达**：

```
stock_lhb_detail_em(20260701, 20260804)          → 2446 条上榜记录  ✅
stock_lhb_stock_detail_em(000009, 20260731, 买入) → 5 行席位明细    ✅
```

字段含 `交易营业部名称 / 买入金额 / 卖出金额 / 净额 / 占总成交比例`，足以把
「净买 3 亿」拆成「谁买的」——`机构专用`、`深股通专用` 是交易所固定称谓，
其余为营业部。已建 `adapters/lhb_seats.py`。

两条边界写在这里免得再踩：

1. **同一席位会同时出现在买入榜和卖出榜**，两边整行数值完全一致，不去重会把净额算两遍。
2. **`机构专用` 是所有机构席位的统一匿名称谓**，同一天四行 `机构专用` 是四家不同机构。
   按名称去重会静默合并成一家，净额直接算错。去重键必须用整行。
3. **上榜有门槛，大市值蓝筹基本不出现。** 牧原股份（流通市值 1248 亿）在 7/1–8/4
   整个区间一次都没上榜。取不到是常态不是故障。

## 四、付费档（TickFlow Pro，¥99/月）实测

主机 `api.tickflow.org`（免费档是 `free-api.tickflow.org`，是**两个不同的 host**）
解析到 `198.18.0.50`，返回 401 正常鉴权响应而不是连接重置——付费主机在本机出口代理
白名单内，**这是付款前唯一必须确认的事**（东财 `push2` 就是死在这一层）。

**代码零改动**：把 key 写进 `.env.tickflow` 或 `export TICKFLOW_API_KEY=...` 即可，
`mode` 自动切 `full`，能力位翻 `True`，`wrap_client()` 对付费 key 自动退化成透明代理。

| `stream` websocket 推送 | ⚠️ 唯一真差异 | 未测（本轮未接） |
| **批量接口** | 没意识到 | ✅ **最大的一笔**，见 4.2 |
| `financials.*` 财务数据 | — | ❌ **Pro 档无权限**。PE/PB 仍只有新浪有 |
| `klines.intraday_batch` | — | ❌ **Pro 档无权限**。单只 `klines.intraday()` 可用 |

### 4.2 批量接口——付费档最被低估的部分

| 操作 | 免费档 | 付费档 | 倍数 |
|---|---|---|---|
| 申万分类冷启动（335 分片） | 335 次串行，受 60/min 节流 = **6 分 16 秒** | `universes.batch` 2 次调用 = **1.58 秒** | **≈240×** |
| 全 A 行情 | 新浪 56 页并发 5.3s | `quotes.get(universes=['CN_Equity_A'])` 0.7s | 7.5× |
| 全 A 标的元数据 | 腾讯逐只 | `instruments.batch` 5534 只 / **0.97s**，涨跌停价 **100% 覆盖** | — |

最后一行解掉了一条长期已知边界：`strong_count` 此前用「涨幅 ≥ 9.5%」近似涨停，
分不清主板 10% 与创业板/科创板 20%。实测宁德时代涨停价 482.26（20%）、平安银行
12.77（10%），两档区分正确。**该判据尚未改用真实涨停价**——它直接喂板块打分，
换判据会让历史分数不可比，须连同阈值重标定一起做。

### 4.3 分钟 K 线的两个硬边界

**单次 5000 根封顶。** `count` 传 5000/10000/20000 返回的都是 5000 根，配 `start_time`
也一样——服务端给的永远是 `end_time` 之前最近的 5000 根。要更早的数据只能**把
`end_time` 逐段前推**，见 `adapters/tickflow_intraday.fetch_minute_history`。

| 周期 | 单次上限 | 覆盖 | 数据底 |
|---|---|---|---|
| 1m | 5000 根 | 21 个交易日 | 翻页可达 **2025-05-23** |
| 5m | 5000 根 | 104 个交易日 | 2025-05-23 |
| 15m / 30m / 60m | 4648 / 2324 / 1162 根 | 291 个交易日 | 2025-05-23 |

翻页实测：600519.SH 1m 拉满 12 个月 = **58322 根 / 242 个交易日 / 5.5 秒 / 12 页**。

**这是「未经回测」第一次具备解除条件。**

### 4.4 两家的分钟线并不逐根相同

量纲对齐之后，TickFlow 与新浪重叠的 1970 根 1 分钟线里完全一致的只有 **39%~61%**，
相对差中位 ~1e-4、最大 **0.15%~0.31%**（不同厂商把逐笔归并到分钟的边界处理不同，
不是谁错了）。

含义：换一条路会让价位漂移最多约 0.3%。**不要把两条路的读数混进同一次计算，
也不要拿一条路的历史去回测另一条路要跑的规则。**

## 五、量纲陷阱与校验

**这一节是错了不会报错、只会算错的地方。** 每一条都有测试钉住
（`tests/test_tickflow_market.py`、`tests/test_tickflow_intraday.py`）。

| 字段 | TickFlow | 新浪 | 腾讯 | 错了会怎样 |
|---|---|---|---|---|
| `volume`（行情与分钟线） | **手** | 股 | **手** | 差 100 倍。`_vwap` 用 `amount/volume`，不换算茅台 VWAP 算成 135083 而不是 1351 |
| `amount` | 元 | 元 | **万元** | 差 10000 倍 |
| 五档挂单量 | — | 股 | **手** | 差 100 倍，挂单墙判定直接失效 |
| `ext.change_pct` | **比值**（-0.0082） | 百分数（-0.82） | — | 差 100 倍 |
| 流通市值 | 需自算 `float_shares × 现价`（元） | `nmc`（**万元**） | — | 不归一则 20 亿门槛变 20 万，可交易性筛选静默失效 |

**腾讯那三行是 2026-08-02 实测出来的，此前不知道。** 同一时刻取 600519，新浪
`volume` 5512752、腾讯 55128，比值 **99.999**；`amount` 比值 **10000.004**。不是
近似，是单位。`adapters/snapshot.py` 用同一个 `Snapshot` 承载两个源的读数，让字段
含义取决于 `source` 等于把量纲错误埋进每一个下游消费者——所以在解析层就换算掉了，
契约是**股与元**。

代价记在这里：腾讯的五档挂单量只精确到手。同一时刻新浪报 930020 股、腾讯报 9300 手
（= 930000 股），差的是那 20 股零股。做委比、做挂单墙都用不到这个精度。

**浮点卫生。** 复权后 OHLC 四个字段各自带尾巴，实测 60 只 / 15000 根 1 分钟线里
**1399 根（9.33%）满足 `high < low`**（量级 1e-13）。下游拿 `high - low` 当振幅、
拿 `low == min(lows)` 找枢轴点，倒挂会静默出错。取到 4 位小数后归零。

### 5.1 业绩预告：选错「预测指标」会把亏损公司读成增长

同一个标的在 `stock_yjyg_em` 里**每个预测指标一行，而预告类型随指标而变**。
2026 中报实测同一家公司：

| 预测指标 | 预告类型 | 变动幅度 |
|---|---|---|
| 归属于上市公司股东的净利润 | **续亏** | +6.98% |
| 扣除非经常性损益后的净利润 | **续亏** | +15.74% |
| 扣除后营业收入 | 略增 | +22.55% |
| 营业收入 | 略增 | +25.62% |

按行到达顺序取、或按最后一行覆盖，都会把一家**持续亏损**的公司读成「略增」——
而那正是业绩否决要拦的一类。`adapters/earnings.py` 按 `METRIC_PRIORITY` 选，
并把实际用的指标写进 `metric` 字段：营收口径的「略增」和净利润口径的「略增」
不是同一个结论，`screens/earnings.py` 只让净利润口径参与否决。

覆盖率实测 1874 家里 1867 家有归母口径，退档是罕见路径而不是常态。

**第二个坑：方向与水平是两个问题。**「减亏」的方向为正（同比在改善）而净利润
仍为负。只看方向会把一家还在亏钱的公司标成「业绩催化」。两个字段各答一问：
`direction` 答方向，`is_loss` 答水平，`is_profitable_growth` 要求两者同时成立。

**第三个坑：`业绩变动幅度` 是百分数不是比值**，且实测极值到 +265430 与 -31094。
任何下游都不该拿它直接乘进分数——否决只用**类型**，幅度只用于措辞与分档。

### 校验层做什么

`adapters/validate.py` 把上面这些做成可复用的检查，而不是散落在各调用点：

| 检查 | 方法 | 失败时 |
|---|---|---|
| 跨源交叉 | 两路都有的字段逐个比 | 出 note，**不改数** |
| 量纲 | 从 `amount / volume` **反推**单位，不查配置 | 推不出来就拒绝算 VWAP |
| 浮点卫生 | `high < low` 倒挂 | 取 4 位小数；仍倒挂则交换并计数 |
| 日线 ↔ 分钟线 | 同一交易日收盘价之比（`advice/engine.py`） | 落在 `[0.2, 5.0]` 外即判定对不上，**不给价** |
| 时效 | 最新 bar 时间戳 vs 当前时刻（`monitor/feed.py`） | 见 `SOLUTION.md` §四.1 |

原则和别处一致：**校验失败一律置空并标注，绝不用低分辨率数据顶替。**

三处刻意的设计：

**1. 量纲差异和读数分歧分开报。** 比对时这两件事必须分开：

- **比值 ≈ 100 或 10000** → 有一边量纲错了。这是 bug，有确定的修法，**修完两边完全一致**。
- **比值 ≈ 1 但差几个百分点** → 两个源对同一件事的测量确实不同（厂商把逐笔归并到
  分钟的边界处理不同，实测相对差最大 0.31%）。这是数据的性质，没有「正确答案」。

混在一起报会把唯一可修的那类埋进噪声里。上表三处陷阱全都是 100 倍或 10000 倍。

**2. 单位是反推的，不是配置的。** `amount / volume` 必须落在当根 bar 的价格量级上；
落在 100 倍开外，volume 记的就是手。这比信一个配置项可靠——量纲搞错不会报错，只会让
茅台的 VWAP 算成 135060 而不是 1350.60，然后每只票都显示为永远在均价下方。推不出来时
**不猜**：宁可不给 VWAP。

**3. 比对只出 note，不改数、不挑选。** 合并策略归 `CompositeMarketScanAdapter`
（主源整行为准，兜底只填空）。两件事混在一起会让「这个数用的是哪一路」变得不可追溯。

**没有分歧时也出一条 note。** 「比过了，一致」和「根本没比」在只报异常的设计里长得
一模一样——而后者正是这一层建起来之前的状态：`CompositeMarketScanAdapter` 一直在
合并两路，却从来没比过两路都有的字段。

## 六、价格口径

| 数据 | 口径 | 用途 |
|---|---|---|
| TickFlow 日线（默认 `forward`） | **比例前复权** | 均线、趋势、威科夫、支撑压力 |
| 新浪分钟线（`adjust=""`） | **不复权** | 买卖点、止损、目标——所有要挂单的价格 |

比例前复权锚定**最新**一根：不动今天，只重算历史。所以两条序列本来就共用今天的价格
尺度——2026-08-02 实测 400 只，前复权最新一根与不复权最新一根**无一例外完全相同**。

`TickFlowAdapter(adjust=...)` 接受 `none / forward / backward / forward_additive /
backward_additive`。**若改成 `backward`（后复权），历史保持原始价而今天被重算，
届时所有对外价位都必须换算**——`advice/engine.py:_session_alignment` 就是唯一
需要改的地方，乘法已经在正确的位置上了。

## 九、仍然没测的一件事：盘中时效

非交易时段测不出盘中时效。**这一项对免费档和付费档都还是未知数。**

```bash
python3 scripts/source_audit.py --watch 600 --interval 3
ashare-ds intraday-check --symbols 600519.SH                    # 按档位自动选路
ashare-ds intraday-check --symbols 600519.SH --source sina      # 强制免费路
```

看两个数：

- **数据滞后中位** ≤ 3s → 该档位可支撑盘中判断
- **时间戳前进次数** 接近轮询次数 → 数据真在更新；若为 0，说明盘中不推进

要比的是**两条路的相对时效**：如果付费档与新浪相当，那就确认这 ¥99 买的是分钟历史
与配额而非实时性；如果付费档明显更新，实时这条线也该切过去。

2026-08-01 周六测得滞后 ≈ 9 万秒（即距上次收盘的自然时间），**该数字在非交易时段
无意义**，脚本会明确标注。

另一件没测的：**持续轮询是否触发新浪限流**。并发测试跑在非交易时段、总量 40 次请求；
一个交易日是 145 轮 × 50 只 ≈ 7000 次。设计里留了退路——指数退避 → 自动降频
（2→5→10 分钟）→ 挂起，每次降级推通知。批量快照接入后请求数从 `轮数 × 标的数`
降到 `轮数`，这个风险基本消失。

## 十一、筹码数据边界

生产链路没有真实筹码分布源。TickFlow 不提供 `chip` / `cost` / `winner` 接口，
账号无财务数据权限；AkShare `stock_cyq_em` 依赖东方财富 `push2`，当前部署环境
实测为 `RemoteDisconnected`。因此系统不会把成交成本代理写成真实筹码。

当前可用的是两类确定性估算：

- `turnover_cost_15/30`：按窗口成交额/成交量计算的成交成本代理；
- `signals/chips.py`：以日线 OHLCV 与流通股本做换手衰减的筹码**估算**，字段固定带
  `_est` 后缀。

若将来换到可访问 CYQ 的环境，必须先验证字段、时效与稳定性，再以独立字段接入；
不得覆盖或重命名现有估算值。
