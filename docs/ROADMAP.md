## 0. 一句话结论

这套系统的**判断层**比它看起来完整得多（情绪周期闸门、四条打法分支、买卖点三层
裁决都已建成），真正的缺口在**三个别的地方**：

| 缺的 | 后果 |
|---|---|
| **记忆** | 每天从零开始。昨天为什么涨、上周主线是什么，系统答不出来 |
| **资金** | 只有 T+1 的龙虎榜。当下谁在买、大单是流入还是流出，完全看不见 |
| **元数据** | 候选表里只有 `300588.SZ`，没有名称、没有行业、没有概念 |

「策略太简单」这个感受的真实来源不是判据少，是**判据说不出人话**——
简报里写的是「回调到位 -4.50%（中位 0.9 个日波幅）」，不是「缩量回踩到 20 日均线，
量能萎缩到 0.62，属于洗盘不是出货」。同一件事，后者才是可核对的策略语言。

## 1. 三件你以为没有、其实已经有了

写在最前面，是为了避免下一轮重复实现。

### 1.1 明确的策略分支 —— 已有，但没修完

`strategy/regime.py` + `strategy/playbook.py` 已经把「今天该不该做」和
「这只票能用哪条判据链」拆成两个正交判断并取交集：

```text
情绪周期（涨停池）→ 冰点/启动/发酵/高潮/分歧/退潮 → 今天允许哪些打法 + 仓位上限
趋势状态（单票）  → UPTREND/REBOUND/RANGE/DOWNTREND → 这只票能用哪些打法
                          ↓ 取交集，空集就是不买
四条打法各自的入场判据链（全是门槛，不是权重）
```

**缩量已经是硬门槛**（`playbook.py:48`，`volume_contraction ≤ 0.90`），
**超跌反转必须带反转触发**（Spring / 放量反包 / 踩回 30 日成交成本收回，三选一），
**冰点档直接不出候选**。这些正是「放量上涨、缩量下跌」那类要求的机制形态。

**但有两处没修完，下一轮必须补：**

1. **突破打法选得中、拿不到买点。** `advice/candidates.py:190-193` 直接拒绝生成
   高于现价的买入价（低吸口径的遗留）。于是一只被判为 BREAKOUT 的票，`advise`
   会给它一组低吸口径的价位。选股层和买卖点层的口径对不上。
2. **止损和买入依据没有配对**（见 §4.3）。

### 1.2 「明盘」—— 已有

五档盘口 `signals/orderflow.py` 已建成：委比、买卖盘厚度、挂单墙（门槛按当日
成交额自缩放）、spread、真实涨跌停、封板退化标记。它刻意**不进打分**，只做三件事：
给 L2 候选价位提供出处、给告警附旁证、回答「此刻挂不挂得进」。

**真正缺的是「暗盘」那一半**——逐笔成交的主动买卖方向与大单净额。见 §3.2。

### 1.3 抄底与止损的依据链 —— 已有骨架

买卖点是三层：L1 确定性读数 → L2 带出处的候选集 → L3 模型只能在候选里选、
不能造价（输出候选 key 而不是价格，再过一道精确相等的闸门）。每个候选带 `basis`
（分时均价回踩 / 日线支撑 / 五档买盘墙 / 跌停价…），`basis` 进台账，
所以「哪一类依据兑现率高」是一个有数据能回答的问题。

止损距离已有 1–3 个 ATR 的上下限夹持（防止算出 172 倍盈亏比那种事故）。

**缺的是把止损和买入理由绑在一条逻辑链上**——见 §4.3。

## 3. 数据层：三件要接的事

### 3.1 标的元数据：静态文件做主，TickFlow 降为校验　【已定】

**来源**：`https://files.688798.xyz/ths/`（curl 实测 200）

| 文件 | 内容 | 实测（2026-08-09） |
|---|---|---|
| `industries.json` | `{symbol, name, industries:[一级,二级,三级]}` | **5446 只**（SH 2280 / SZ 2837 / **BJ 329**），**31 个一级 / 90 个二级 / 257 个三级** |
| `concepts.json` | `{symbol, name, concepts:[…]}` | **5550 只**（BJ 337），**390 个概念标签** |

一级行业名与申万一致（机械设备 602、电子 513、医药生物 500 … 银行 42、煤炭 34、综合 18）。

**两个文件的标的集合不一致，按并集合并。** 早先记的「两文件标的集合完全一致」
是错的：`concepts.json` 比 `industries.json` 多 **104 只**，而且不是还没归类的
新股——华银电力、华大智造、众生药业都在里面。以行业文件为主循环会让这 104 只
**整只消失**（连概念板块都进不去、简报里查不到画像），所以行业缺失时
`industries=()`，它照样进概念板块。

**上游每天 00:00 UTC（北京 08:00）刷新一次**（两个文件的 `last-modified` 实测都是
当天 00:00:0x）。所以 `MAX_AGE_DAYS = 0`，只认当天抓的——早先按「更新频率未知」
设的 7 天缓存会让**概念成分表落后一周**，而盘中板块监控读的正是这张表。

**对比现状**：

| | TickFlow SW1（现在） | 静态文件（下一轮） |
|---|---|---|
| 覆盖 | 4430 / 5528 | **5550**（含北交所 337 只，现在一只都没有） |
| 层级 | 一级 31 | **一/二/三级 31 / 90 / 257** |
| 概念 | 无 | **390 个**（过闸后 321 个进排序） |
| 冷启动 | **6 分钟**（335 分片 × 60/分钟闸门） | 一次 HTTP，**< 1 秒** |
| 配额 | 吃掉 60/分钟里的 45 次 | 不占 |
| 失败模式 | 限流 → 抛 `SectorTaxonomyError` → 整条链路停 | 文件不可达 → 用上次落盘的 |

**设计**：

```text
adapters/ths_taxonomy.py           新增。拉两个 json，落盘到 state_home/taxonomy/
  ├─ load()   → {symbol: (name, [l1,l2,l3], [concepts])}
  ├─ sectors(level)  → list[SectorDefinition]，喂给现有 sectors/ 链路
  └─ concepts()      → list[SectorDefinition]，概念板块（新维度）
```

- **接口不变**：产出 `SectorDefinition`，`sectors/momentum.py` 与
  `sectors/predict.py` 一行不用改。这是「改动可加」能成立的关键。
- **TickFlow taxonomy 保留**，降级为**启动时的一次交叉校验**：两边行业名与成分股
  重合度低于阈值就写进 notes 并告警。**不是双跑，是一次对账。**
- **落盘带 `schema` 戳与抓取日期**，沿用现有 taxonomy 缓存的约定。
- **必须记「这份文件多久更新一次、谁在更新」**——目前未知。新股上市、行业调整、
  ST 摘帽都会让它过期，而过期的分类**外观完全正常**（这正是 08-01 那次
  缺 469 只成分股事故的形态）。所以：文件抓取日期超过 N 天就在简报里写明。

**顺带修掉的**：候选表可以印「300588.SZ **奥拓电子**｜计算机·软件开发·横向通用软件
｜AI应用、算力租赁」，而不是一个裸代码。这是用户体感「策略不明确」的一大来源——
不是判据不够，是**读的人认不出这是什么公司、属于哪条线**。

**英文名不在这两个文件里**（只有 `symbol` / `name` / 分类）。已定：先不做，标为待补。

### 3.2 逐笔资金：腾讯 detail　【已定：盘后 + 自选/候选池】

**来源**（curl 实测 200）：

```
https://stock.gtimg.cn/data/index.php?appn=detail&action=data&c=sh600519&p=1
→ v_detail_data_sh600519=[1,"序号/时间/价格/涨跌/成交量(手)/成交额(元)/方向|…"]
  方向 = B(主动买) / S(主动卖) / M(中性)
```

实测 600519 当日 **4243 笔、61 页翻完全天**（含 15:00 后的盘后固定价格交易）。
每页约 70 笔。

**这是系统第一次能看见「当下谁在买」。** 现有资金面只有龙虎榜，是 T+1 的。

**能算出来的读数**（全部是 L1 确定性算子）：

| 读数 | 定义 | 回答什么 |
|---|---|---|
| 主动买卖比 | `ΣB金额 / (ΣB+ΣS)` | 今天是被买上去的还是被卖下来的 |
| 大单净额 | 单笔金额 ≥ 阈值的 B 减 S | 谁在动，散户还是大资金 |
| 分时段资金曲线 | 按 30 分钟分桶累计净额 | 早盘拉尾盘出？还是全天净流入 |
| 尾盘资金 | 最后 30 分钟净额 / 全天净额 | 收盘前是承接还是出逃 |
| 大单撤退 | 大单净额由正转负的时刻 | 卖点旁证 |

**三条必须写进代码的限制**（否则这个读数会被当成比它实际更硬的证据）：

1. **B/S/M 是腾讯按买一卖一推断的，不是交易所提供的委托方向。** 撮合在中间价、
   或大单拆单时会误判。它是**行业惯例口径**，不是真相。
2. **大单阈值必须按标的自身缩放。** 100 万在茅台是零头，在一只 20 亿流通的票上
   是大单。用「该票近 20 日单笔成交额的 95 分位」而不是固定金额——
   和 `dipbuy` 的 ATR 归一化同源。
3. **`R_tail = 尾盘净额 / 全天净额` 在全天净流出时符号翻转**——`DECISIONS.md` §2.2
   已经记过这个坑（当时是别人方案里的）。这里必须加方向门槛：仅当全天净额 > 0 时
   才判定，否则标未定义、不参与打分。**别把同一个错误自己再犯一次。**

**成本与范围**：约 61 次 HTTP × 每票每天。已定范围 = **盘后复盘 + 自选股/候选池
（20–40 只）**，一次 1200–2400 次请求。不进盘中循环。

**第一版不进打分。** 和五档、同花顺指数同一条原则：先落台账，等 `review` 能回答
「大单净额为正的那些建议，兑现率高多少」，再决定要不要给它权重。

**未验证**：盘中时效、是否限流、非交易日返回什么。接之前用 `scripts/source_audit.py`
补一轮 `--repeats` / `--watch`。

## 4. 策略层：量价形态字典

这是「策略太简单、没有放量上涨缩量下跌」的直接回应。

### 4.1 形态不是标签，是「形态 × 位置 × 阶段」三元组

**单独一个「放量上涨」什么都不说明。** 同一个形态在不同位置含义相反：

```text
放量上涨 @ 60日分位 0.20  →  启动，量能确认
放量上涨 @ 60日分位 0.95  →  高位放量，很可能是派发
缩量下跌 @ 回调 1.5 个日波幅、MA20 上方  →  洗盘，低吸最想要的形态
缩量下跌 @ 已破 MA20、回调 5 个日波幅   →  阴跌，接刀
```

所以 `signals/volume_price.py` 输出的是三元组，不是单一标签：

```python
@dataclass(frozen=True)
class VolumePriceShape:
    pattern: str        # 放量上涨 / 缩量上涨 / 放量下跌 / 缩量下跌 / 放量滞涨 / 缩量横盘
    position: str       # 60 日分位档：低位 / 中位 / 高位
    stage: str          # 回调段 / 启动段 / 破位段（读 dipbuy.pullback_band 与 MA20）
    reading: str        # 一句人话，进简报："缩量回踩 20 日线，量能萎缩至 0.62，抛压收敛"
```

### 4.2 六个基本形态，阈值按标的自身分布归一

| 形态 | 判据 | 超短含义 |
|---|---|---|
| 放量上涨 | `ret>0` 且 量比 ≥ 自身 70 分位 | 有资金进；位置决定是启动还是派发 |
| 缩量上涨 | `ret>0` 且 量比 ≤ 自身 30 分位 | 惜售，抛压轻；也可能是无人接的虚涨 |
| **放量下跌** | `ret<0` 且 量比 ≥ 自身 70 分位 | **出货 / 破位——低吸的一票否决** |
| **缩量下跌** | `ret<0` 且 量比 ≤ 自身 30 分位 | **回调到位的健康形态——低吸最想要的** |
| 放量滞涨 | `\|ret\| < 0.3 个日波幅` 且 量比 ≥ 自身 85 分位 | 高位换手，派发嫌疑 |
| 缩量横盘 | `\|ret\| < 0.3 个日波幅` 且 量比 ≤ 自身 30 分位 | 蓄势或无人问津，看位置 |

**为什么用自身分位而不是 1.2 / 0.8。** 日均换手 0.5% 的银行股和 15% 的题材股，
同一个绝对量比含义完全不同。这和 `dipbuy.py` 用 ATR 归一化回调档位是同一条理由，
而且那次归一化的效果是实测过的（建行与长电的最大回撤绝对值差 46%，除以各自
日振幅后是 4.4 与 4.3）。**别在量能上重犯已经在幅度上修过的错。**

### 4.3 止损必须是「买入依据失效」的那个价 ★

这是「卖出止损有依据」的正解，也是现在最明显的一处逻辑断裂。

现状：买入候选是「五档买盘墙 22.80」，止损候选却是「日内波动下沿 22.31」——
**两个价不在同一条逻辑链上**。跌破 22.31 意味着什么？没人说得清。

改法（改动很小，收益很大）：

```python
@dataclass(frozen=True)
class PriceCandidate:
    ...
    invalidates: str | None = None   # 跌破这个价，哪条买入依据失效
```

配对规则：

| 买入依据 | 配对止损 | 跌破意味着 |
|---|---|---|
| 五档买盘墙 | 墙价下方一跳 | 墙被吃穿，唯一「有人真的挂着」的证据消失 |
| 日线支撑 | 该支撑下方 | 支撑失效，日线结构破坏 |
| 分时均价回踩 | 当日低点 | 回踩变破位，当日结构不成立 |
| 超跌反转 | **触发日最低** | `playbook.py:357` 已经写了「跌破触发当日最低即无条件离场」，但这句话从没接到 `candidates.py` |
| 区间下沿 | 区间下沿下方 | 不是震荡，是破位 |

止损候选按「与选中买入依据配对的那条」优先排序，`default_rank` 相应重排。
1–3 ATR 的距离夹持继续生效（配对价落在夹持外时取夹持边界并写明）。

**这条直接让每一个止损都能说出人话**：「止 22.75——买盘墙被吃穿，
买入的唯一即时证据消失」，而不是「止 22.31——日内波动下沿」。

### 4.4 多日序列：形态的价值主要在连续

单日形态信息量有限，**序列才是超短线真正读的东西**：

```text
放量上涨 → 缩量下跌 → 缩量下跌 → 缩量下跌收阳     洗盘结束（低吸的经典入场）
放量上涨 → 放量滞涨 → 放量下跌                     派发（不管分数多高都不该买）
缩量横盘 → 放量上涨（低位）                        启动确认
放量下跌 → 放量下跌                                 加速出货，超跌反转也别接
```

第一版只做 **3 日序列的模式匹配**，命名 6–8 条，匹配不上就返回 `None`（不硬凑）。

### 4.5 第一版不进打分

**形态标签只进台账 + 简报措辞，不改任何分数。**

理由和五档、同花顺行业指数完全一样，而且 `DECISIONS.md` §六b 记录了反面教材：
上一轮把缩量做成 ±6 分的权重，结果 60 条建议里 52 条是放量回调——
**只要它是权重，就能被别的项买回来**。

正确顺序是：**落台账 → `review` 按形态分组 → 看到 edge → 才决定是门槛还是权重。**
在那之前，加权重加的是噪声。

## 5. 板块层：轮动与跷跷板

### 5.1 数据已经在手上，只是被扔掉了

`adapters/ths_sector_index.py` 每次运行都拉 90 个行业指数的**全年日线**
（2026 年 140 根），`_fetch_one` 返回 `(name, bars)`，然后 `_measure` 把
整条序列压成一个 `SectorIndexReading` 就丢了。无限流、不占 TickFlow 配额。

**改动：落盘。** 把 bars 一起写进 `state_home/sector_index/{code}.json`，
增量追加。取数成本已经付过了，这一步几乎免费。

### 5.2 `sectors/rotation.py`（新增）

四个读数，全部是确定性算子：

**1. 领涨接力表 / 主线持续度**

近 5 个交易日每天涨幅前 5 的板块，看是同一批还是天天换。
`主线持续度 = |近 5 日 top5 的交集| / 5`。接近 1 = 主线明确该跟；
接近 0 = 无主线的快速轮动，超短最容易两头挨打的状态。

**2. 跷跷板矩阵**

任意两个板块近 60 日日收益的相关系数，**只报实测出来的显著负相关对**。

> **不预设银行 vs 半导体是跷跷板。** 这是一个待验证的假设，不是前提。
> 相关系数在 A 股上的稳定性本身存疑（60 日滚动窗口会漂），所以第一版
> **只用于解释今天的分歧，不用于预测**：「今天银行 +1.2%、半导体 -2.8%，
> 两者近 60 日相关 -0.4x，与历史关系一致」——这是陈述，不是「所以明天会反过来」。
> 相关系数的窗口与稳定性必须和读数一起印出来。

**3. 相对强弱排名与排名变化**

板块相对全市场的超额收益 5 日累计 → RS 排名。**排名变化比排名本身更有用**：
排名上升最快的板块 = 资金正在流入。这是「轮动到哪了」最直接的读数。

**4. 宽度与指数的背离**

`sectors/momentum.py` 给的是成分股等权中位数（宽度口径），
`ths_sector_index` 给的是市值加权指数。两者不一致的时候恰恰是信息：
**指数涨 + 宽度弱 = 权重股拉抬**；指数平 + 宽度强 = 普涨但大票不动。
这一条 `PIPELINE.md` §2b 已经论证过，只是从来没有人把它算成一个读数。

### 5.3 概念板块（390 个）　【已做】

申万一级 31 个太粗——「半导体」「AI 算力」「存储芯片」「稳定币」在申万里全在
「电子」或「计算机」下面，而超短线真正轮动的单位是概念不是行业。

390 个概念的规模分布（2026-08-09 实测，中位 89 只、最大 3846 只）：

| 成分股数 | 概念个数 | 处置 |
|---|---|---|
| < 15 | 3 | 中位数由个别票决定，不参与排序 |
| 15–400 | 321 | 参与排序 |
| > 400 | 32 | **参与排序**（此前被上限挡掉，见下） |

其中 34 个是**交易机制与政策口号标签而非主题标签**：融资融券 3846、深股通 1875、
沪股通 1639、国企改革 1468、专精特新 1227。它们不是板块，进「今天哪个板块强」
是纯噪声，走显式黑名单（`adapters/ths_taxonomy.py:CONCEPT_BLOCKLIST`）。另有一个
字面量叫 `nan` 的「概念」——上游某一步把 NaN 字符串化了，单独挡掉。

**规模上限已取消。** 原方案对 `> 400` 的处置是「太大的概念涨说明的是大盘涨」，
用成分股只数当判据。那个担心是对的，但代价极高：被 400 挡掉的 32 个概念恰好是
超短的**全部主战场**——

> 机器人概念1215、人工智能1083、新能源汽车1061、华为概念1003、芯片概念911、
> 储能894、DeepSeek概念769、数据中心(AIDC)650、AI应用527、商业航天503、
> 低空经济498、无人机463、人形机器人461、AI智能体453、东数西算409 …

也就是说「监控机器人板块有没有异动」这件事，在旧闸门下**结构上不可能实现**。

精确的判据是**超额涨幅**（板块中位 − 全市场中位，`sectors/intraday.py`）：
占市场 22% 的「机器人概念」跟着大盘涨时超额≈0，自己排不上去；只有真的整体异动
才拉得开。同一个担心，量出来而不是用只数猜。

概念板块走**和申万完全相同的动量算子**（`sectors/momentum.py` 不用改），
只是换一组 `SectorDefinition`。

**概念之间基本正交，不需要去重层。** 321 个过闸概念里 Jaccard ≥ 0.5 的只有两对
（金属锌/金属铅 0.74、网络游戏/手机游戏 0.58），所以 31 个行业 + 321 个概念并排
排名不会产出一批「同一批票撑起五个概念同时上榜」的重复读数。

## 6. 记忆层：日报 / 周报 / 月报

这是用户诉求里最核心、也是系统现在**完全没有**的一层。

### 6.1 台账和记忆是两件事

| | `journal/`（已有） | `memory/`（新增） |
|---|---|---|
| 记什么 | 我建议了什么、兑现没有 | 市场发生了什么、为什么 |
| 回答 | 这套规则有没有用 | 现在是什么行情、主线是什么、上次这种情况怎么走的 |
| 粒度 | 每条建议一行 | 每个交易日一份 |

**不要合并。** 台账的样本单位是「一条建议」，记忆的样本单位是「一天」，
混在一起两个问题都答不好。

### 6.2 三级压缩：这就是「上下文不宜太长」的机制

```text
日报  ←  当天的全部原始读数（舆情 1200 条、板块 90 个、涨停池、台账）
周报  ←  只读 5 份日报，不重读原始舆情
月报  ←  只读 4 份周报
```

**每一级只读上一级的产物**，所以 token 量是有界的、可预测的。
这是控制上下文长度唯一可靠的办法——按条数截断做不到，因为原始舆情的量每天在变。

### 6.3 每份报告分两层：事实层与叙述层

```text
memory/daily/2026-08-03.json   事实层：结构化，永远可查、可聚合、可回填
memory/daily/2026-08-03.md     叙述层：一段人话，给人读、给 LLM 装上下文
```

**事实层字段**（收盘后 15:30 生成，全部来自已有算子）：

- 大盘：涨跌、宽度、成交额、站上 MA20 占比
- 情绪周期：档位标签 + 炸板率 / 最高连板 / 涨停跌停家数 + 当日仓位上限
- 板块：90 个指数的涨跌 / 收位 / 量比 / 距 20 日高；领涨领跌前 8
- 轮动：主线持续度、RS 排名变化前 5、当日显著背离对
- 主线归因：**每个领涨板块配一条「为什么」**，来自当日舆情归因；
  取不到就明写「无消息面归因，属于纯资金/技术驱动」
- 台账：当日建议数、情绪周期、仓位系数

**叙述层的三条硬约束**（复用现有 `news/daily_read.py` 的做法，别另造一套）：

1. 每条结论必须**回抄它依据的标题前 12 字**，核不上就丢
2. 数字必须能在事实层里找到（复用 `writer/llm.py:unverified_numbers`）
3. **不产出预测。** 「明天可能补涨」不写。日报是记录，不是预言

### 6.4 周报与月报

**周报**：本周主线、轮动路径（周一到周五每天的领涨板块序列）、
哪些板块是持续的哪些是一日游、情绪周期走势、
**以及上周日报里的主线在本周被验证了没有**——最后这条是让记忆能自我纠错的机制。

**月报**：月度主线、板块 RS 排名变化、情绪周期分布，
外加复用 `journal/stats.py` 的台账统计（兑现率、筛选价值、按形态分组）。

### 6.5 历史回填：只能回填一半，必须说清楚

用户要「先不断学习过去的市场情况」。能回填的和不能回填的：

| 维度 | 能否回填 | 原因 |
|---|---|---|
| 板块指数涨跌 / 收位 / 量比 | ✅ | `ths_sector_index` 有当年 140 根 |
| 个股量价、形态、轮动、RS | ✅ | TickFlow 日线可回溯 |
| 涨停池 / 炸板率 | ⚠️ 部分 | 东财 `push2ex` 只给近期 |
| **舆情归因、主线原因** | ❌ | 语料库从 2026-08 才开始累积 |

所以回填的日报**必须带 `partial: true` 标记，且叙述层留空**。
**不能让回填的日报看起来和实时日报一样完整**——这和「没数据 ≠ 中性」、
「缺片的分类不许落盘」是同一条原则。一份没有归因的日报被当成有归因的读，
比没有这份日报更糟。

### 6.6 消费端

`ask` / `chat` / `morning` 装上下文时注入**最近 5 份日报叙述 + 最近 1 份周报**，
而不是原始舆情。这样「最近行情怎么样」「上次退潮期是什么时候、怎么走的」
第一次变成能回答的问题，而且上下文长度固定。

### 6.7 命令

```bash
ashare-ds report daily             # 收盘后生成当日日报（daemon 15:30 自动）
ashare-ds report weekly            # 周五收盘后
ashare-ds report monthly           # 月末
ashare-ds report backfill --from 2026-01-01   # 历史回填，产物标 partial
ashare-ds report show --last 5     # 看最近 5 份
```
