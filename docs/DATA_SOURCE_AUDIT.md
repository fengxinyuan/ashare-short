# 数据源时效性与稳定性实测

**测于 2026-08-01（周六）本机，非交易时段。** 复跑：

```bash
python3 scripts/source_audit.py --repeats 5 --json audit.json     # 通/时效/稳
python3 scripts/source_audit.py --watch 300 --interval 3          # 高频轮询压测
```

三个数：**通**（能不能答）、**时效**（最新数据落在哪一刻）、**稳**（5 次重复的成功率与 p50 延迟）。

---

## 一、结论先行

**不需要开通付费数据源。** 免费档不仅够用，还有**没吃干净的红利**——实测推翻了 `SOLUTION.md` 里两条关键判断。

| 需求 | 原判断 | 实测 |
|---|---|---|
| 1 盘前板块 | 免费够用 | ✅ 且被低估：板块级实时资金流/涨跌家数免费可得，无需从成分股聚合 |

| 4 对话 | 无差别 | ✅ 无差别 |

**唯一还没测的**：盘中时间戳是否真的推进。周一 09:30 后跑 `--watch` 即可定论——**在那之前不建议付费**。

### 2.1 但「每次调用都稳」不等于「链路能跑完」——TickFlow 有硬闸门

**测于 2026-08-02。** 上表每格测的是**单次调用**，一次跑 5 遍，永远碰不到配额。
盘前全链路一次要打的次数远不止 5：

| 阶段 | 调用次数 |
|---|---|
| 申万 SW1 分类（335 个分片，冷启动） | 335 |
| 板块动量（4430 只 / 100 一批） | 45 |
| 候选股 240 日历史 + 标的信息 | ~15 |

**实测闸门：60 次 / 滚动 60 秒，第 61 次必定 429。** 而 60 次只花 22.5 秒——
按自然节奏打，配额会以 **2.7 倍速**烧光。错误消息里带服务端自报的等待时长
（`请 38266ms 后重试`），比任何本地猜测都准。

```
tickflow._exceptions.RateLimitError: 请求频率超限 (60/min)，请 38266ms 后重试。
```

这条闸门此前没被记录，后果是**两个都不响的故障**：

1. `ashare-ds morning` 跑到候选股取数时直接崩，栈顶在 `klines.batch`；
2. 更糟的是分类层——`sectors/taxonomy.py` 的 `_universe_get` 把异常吞成空成分股，
   于是**残缺的分类被写进缓存**。2026-08-01 现场那份 SW1 缓存是 **3961/4430 只，
   静默少了 469 只（10.6%）**，31 个行业一个不少，文件外观完全正常，链路一声不响
   地跑完了。缓存是永久的，之后每一次盘前扫描都在用它。

**已修**（`adapters/ratelimit.py`）：客户端滑动窗口令牌桶（默认 55/60s，
`TICKFLOW_RATE_LIMIT` 可覆盖）+ 撞墙后按服务端等待时长退避。闸门包在 SDK client
上而不是适配器方法上——`taxonomy.py` 拿的是 `adapter.client` 直接调 `universes.*`，
包方法覆盖不到那条路径。

实测效果：

| | 修复前 | 修复后 |
|---|---|---|
| 连打 80 次 `universes.get` | 第 61 次 429 崩 | 80/80 成功，66s（等待 47.5s） |
| SW1 分类冷启动 | 3961/4430（静默缺片） | **4430/4430，0 分片失败**，363s |
| `ashare-ds morning` 全链路 | 崩在 `_rank_candidates` | **跑完，72s（分类缓存命中）** |

配套的两条完整性约定：分片有任何失败就抛 `SectorTaxonomyError` 且**不写缓存**；
缓存带 `schema` 戳，无戳的（修复前写的）一律重建。

## 三、新发现：免费档还能拿到什么

### 3.1 五档盘口——原判断"只能付费"是错的

`easyquotation` 走新浪 `hq.sinajs.cn`，**akshare 没有封装这个端点**，所以此前没被发现：

| 调用 | 覆盖 | p50 | p95 | 字段 |
|---|---|---|---|---|
| `sina.stocks([...])` | 指定标的 | **45ms** | 52ms | bid1-5/ask1-5 + 量、date、time |
| `sina.market_snapshot()` | **全市场 5599 只** | **443ms** | 802ms | 同上，全带五档 |
| `tencent.stocks([...])` | 指定标的 | **11ms** | 15ms | 五档 + **涨停价/跌停价/量比/委差/均价/流通市值** |

**压测（无间隔连打）**：

```
sina 单票五档    200 次  失败 0   22.4 次/秒
tencent 单票     200 次  失败 0   97.9 次/秒
sina 全市场五档   40 次  失败 0    2.7 次/秒   ← 全市场五档可每 0.37 秒刷一次
```

**5 分钟 / 3 秒间隔 / 268 次请求：4 个源全部 100% 成功，未观察到任何限流。**

两个直接后果：

1. **买卖点可以落到真实挂单档位**——这正是原文档说必须付费才能做的事。
2. **`strong_count` 的近似可以去掉**。`docs/SOLUTION.md` §七承认「用涨幅 ≥ 9.5% 代替真实涨停判定，创业板/科创板 20% 涨停区分不了」——腾讯接口直接给 `涨停价`/`跌停价`，TickFlow `instruments` 也给 `limit_up`/`limit_down`。不用再近似。

### 3.2 板块级读数——不必再从成分股聚合

原链路因为东财板块接口不可达，只能拿 4400 只成分股日线聚合出板块动量（30–60 秒）。同花顺全系可用：

|---|---|---|---|---|
| 行业资金流·即时 | `stock_fund_flow_industry` | 100% | 0.30s | 90 |
| 概念资金流·即时 | `stock_fund_flow_concept` | 100% | 0.89s | 386 |
| 行业板块汇总（涨跌幅/成交额/净流入/**涨跌家数**） | `stock_board_industry_summary_ths` | 100% | 0.29s | 90 |

这是**独立于成分股聚合的第二个读数**，可用来交叉验证板块排序，而不是替换它。

### 3.3 超短线情绪指标——目前系统完全没用

东财 `push2ex` 与 `datacenter-web` 在本机稳定可用（8 轮受控复测 8/8）：

| 数据 | 接口 | p50 | 行数 | 超短线用途 |

| 炸板池 | `stock_zt_pool_zbgc_em` | 0.12s | 107 | **炸板率 = 情绪退潮的第一信号** |

## 四、不可用的源：是本机网络策略，不是数据源问题

**这条对付费决策最关键。**

所有域名都解析到 `198.18.0.x`（保留网段）——本机在**出口代理白名单**后面。TCP 443 能连上（代理接受），但目标不在白名单时代理直接重置连接，这正是 `RemoteDisconnected` 的成因：

```
curl push2.eastmoney.com/api/qt/clist/get    → http=000   （代理重置）
curl push2ex.eastmoney.com/getTopicZTPool    → http=200   ✅
curl hq.sinajs.cn/list=sh600519              → http=200   ✅
```

| 主机 | 状态 | 影响的接口 |
|---|---|---|
| `push2.eastmoney.com` | ❌ 被拒 | 批量行情、五档盘口、板块列表、efinance 全部 |
| `push2his.eastmoney.com` | ❌ 被拒 | 分钟线、日线 |
| `push2ex.eastmoney.com` | ✅ 通 | 涨停池/炸板池/强势股池（`stock_intraday_em` 逐笔仍 0/8） |
| `datacenter-web.eastmoney.com` | ✅ 通 | 龙虎榜、北向 |
| `hq.sinajs.cn` / `qt.gtimg.cn` | ✅ 通 | 五档、快照 |

**所以：**

- 不存在「重试能救活」的可能——这是网络策略，不是抖动或限流。
- **换到本地或国内云主机，东财全系大概率复活。** "东财已死"是**本机结论，不是数据源结论**。
- 因此：**不要为了绕开本机网络限制去买付费数据源**——那是花钱买错东西。先换部署环境验证。

> 诚实记录：16:46 单次探测中 `stock_zh_a_hist`、`stock_individual_fund_flow`、`stock_market_fund_flow`、efinance 全市场快照曾各成功一次；随后 8 轮受控复测 0/8。按不可用处理。

## 五、付费档到底还能买到什么

TickFlow 免费档的闸门是**硬性的**，实测报错明确：

```
quotes.get_by_symbols()   → PermissionError: 免费服务不支持实时行情数据
klines.intraday()         → PermissionError: 免费服务不支持日内分时数据
depth.get()               → PermissionError: 无市场深度查询权限（市场: CN）
```

但这三样**免费档已从别处拿到了两样**：

| 付费档提供 | 免费替代 | 还值不值得买 |
|---|---|---|
| `quotes` 实时报价 | 新浪/腾讯快照，全市场 443ms | ❌ 不值 |
| `depth` 五档盘口 | 新浪 `hq` 全市场五档，443ms | ❌ 不值 |
| `klines.intraday` 分钟线 | 新浪 `stock_zh_a_minute`，1.0s/次 | ⚠️ 看周一盘中时效 |
| `stream.on_quotes/on_depth` **websocket 推送** | **无免费替代**（只能轮询） | ⚠️ 唯一真差异 |

**唯一买得到的真差异是推送 vs 轮询。** 3 秒轮询能否满足，取决于持仓周期——分时抢点不够，5 分钟级别判断绰绰有余。

**付费也买不到的**（不变，见 `docs/PLAN_REVIEW.md`）：集合竞价撮合量/未匹配量。加上 **09:20–09:25 交易所不接受撤单**，该窗口撤单率恒为 0，任何档位、任何数据源都拿不到。

## 六、周一必须做的一件事

非交易时段测不出盘中时效——**这是免费档唯一的未知数**：

```bash
python3 scripts/source_audit.py --watch 600 --interval 3
```

看两个数：

- **数据滞后中位** ≤ 3s → 免费档可支撑盘中判断，确定不用付费
- **时间戳前进次数** 接近轮询次数 → 数据真在更新；若为 0，说明盘中不推进，需求 2/3 必须付费或等 QMT

本次周六测得滞后 ≈ 9 万秒（即距上次收盘的自然时间），**该数字在非交易时段无意义**，脚本会明确标注。

## 七、建议的落地顺序（都不花钱）

1. **周一验证盘中时效**——决定要不要付费的唯一依据。
2. **接入五档盘口**（`easyquotation` 新浪源），买卖点落到真实档位；同时用腾讯的 `涨停价/跌停价` 替掉 `strong_count` 的 9.5% 近似。
3. **接入涨停/炸板池**——超短线情绪的核心读数，当前完全空白。
4. **接入同花顺板块资金流**，作为板块排序的第二读数交叉验证。
5. 若要脱离本机网络限制，**优先换部署环境**（东财全系复活），而不是买数据。

依赖（可选装，不影响现有功能）：

```bash

pip install baostock           # 历史分钟线回测底座
```
