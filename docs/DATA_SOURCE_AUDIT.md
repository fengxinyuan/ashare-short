**免费档测于 2026-08-01（周六）本机，非交易时段。付费档（Pro，¥99/月）于 2026-08-02 开通并实测，见 §五。** 复跑：

### 2.1 但「每次调用都稳」不等于「链路能跑完」——TickFlow 有硬闸门

**测于 2026-08-02。** 上表每格测的是**单次调用**，一次跑 5 遍，永远碰不到配额。
盘前全链路一次要打的次数远不止 5：

| 阶段 | 调用次数 |
|---|---|
| 申万 SW1 分类（335 个分片，冷启动） | 335 |
| 板块动量（4430 只 / 100 一批） | 45 |
| 候选股 240 日历史 + 标的信息 | ~15 |

**实测闸门：60 次 / 滚动 60 秒，第 61 次必定 429。** 而 60 次只花 22.5 秒——
按自然节奏打，配额会以 **2.7 倍速**烧光。错误消息里带服务端自报的等待时长
（`请 38266ms 后重试`），比任何本地猜测都准。

```
tickflow._exceptions.RateLimitError: 请求频率超限 (60/min)，请 38266ms 后重试。
```

这条闸门此前没被记录，后果是**两个都不响的故障**：

1. `ashare-ds morning` 跑到候选股取数时直接崩，栈顶在 `klines.batch`；
2. 更糟的是分类层——`sectors/taxonomy.py` 的 `_universe_get` 把异常吞成空成分股，
   于是**残缺的分类被写进缓存**。2026-08-01 现场那份 SW1 缓存是 **3961/4430 只，
   静默少了 469 只（10.6%）**，31 个行业一个不少，文件外观完全正常，链路一声不响
   地跑完了。缓存是永久的，之后每一次盘前扫描都在用它。

**已修**（`adapters/ratelimit.py`）：客户端滑动窗口令牌桶（默认 55/60s，
`TICKFLOW_RATE_LIMIT` 可覆盖）+ 撞墙后按服务端等待时长退避。闸门包在 SDK client
上而不是适配器方法上——`taxonomy.py` 拿的是 `adapter.client` 直接调 `universes.*`，
包方法覆盖不到那条路径。

实测效果：

| | 修复前 | 修复后 |
|---|---|---|
| 连打 80 次 `universes.get` | 第 61 次 429 崩 | 80/80 成功，66s（等待 47.5s） |
| SW1 分类冷启动 | 3961/4430（静默缺片） | **4430/4430，0 分片失败**，363s |
| `ashare-ds morning` 全链路 | 崩在 `_rank_candidates` | **跑完，72s（分类缓存命中）** |

配套的两条完整性约定：分片有任何失败就抛 `SectorTaxonomyError` 且**不写缓存**；
缓存带 `schema` 戳，无戳的（修复前写的）一律重建。

## 四、不可用的源：是本机网络策略，不是数据源问题

**这条对付费决策最关键。**

所有域名都解析到 `198.18.0.x`（保留网段）——本机在**出口代理白名单**后面。TCP 443 能连上（代理接受），但目标不在白名单时代理直接重置连接，这正是 `RemoteDisconnected` 的成因：

```
curl push2.eastmoney.com/api/qt/clist/get    → http=000   （代理重置）
curl push2ex.eastmoney.com/getTopicZTPool    → http=200   ✅
curl hq.sinajs.cn/list=sh600519              → http=200   ✅
```

| 主机 | 状态 | 影响的接口 |
|---|---|---|
| `push2.eastmoney.com` | ❌ 被拒 | 批量行情、五档盘口、板块列表、efinance 全部 |
| `push2his.eastmoney.com` | ❌ 被拒 | 分钟线、日线 |
| `push2ex.eastmoney.com` | ✅ 通 | 涨停池/炸板池/强势股池（`stock_intraday_em` 逐笔仍 0/8） |
| `datacenter-web.eastmoney.com` | ✅ 通 | 龙虎榜、北向 |
| `hq.sinajs.cn` / `qt.gtimg.cn` | ✅ 通 | 五档、快照 |

**所以：**

- 不存在「重试能救活」的可能——这是网络策略，不是抖动或限流。
- **换到本地或国内云主机，东财全系大概率复活。** "东财已死"是**本机结论，不是数据源结论**。
- 因此：**不要为了绕开本机网络限制去买付费数据源**——那是花钱买错东西。先换部署环境验证。

> 诚实记录：16:46 单次探测中 `stock_zh_a_hist`、`stock_individual_fund_flow`、`stock_market_fund_flow`、efinance 全市场快照曾各成功一次；随后 8 轮受控复测 0/8。按不可用处理。

## 五、付费档（Pro，¥99/月）实测

**2026-08-02 开通并实测。** 主机 `api.tickflow.org`（免费档是 `free-api.tickflow.org`，是**两个不同的 host**）解析到 `198.18.0.50`，返回 401 正常鉴权响应而不是连接重置——付费主机在本机出口代理白名单内，这是付款前唯一必须确认的事（东财 `push2` 就是死在这一层）。

**代码零改动**：`export TICKFLOW_API_KEY=...` 即可，`mode` 自动切 `full`，三个能力位翻 `True`，`wrap_client()` 对付费 key 自动退化成透明代理。

| `depth` 五档 | ❌ 不值，新浪已有 | ⚠️ 平级冗余。500 只 / 0.79s |

### 5.2 批量接口——付费档最被低估的部分

| 操作 | 免费档 | 付费档 | 倍数 |
|---|---|---|---|
| 申万分类冷启动（335 分片） | 335 次串行 `universes.get`，受 60/min 闸门节流 = **6 分 16 秒** | `universes.batch` 2 次调用 = **1.58 秒** | **≈240×** |
| 全 A 行情 | 新浪 Market_Center 56 页并发 5.3s | `quotes.get(universes=['CN_Equity_A'])` 0.7s | 7.5× |
| 全 A 标的元数据 | 腾讯逐只 | `instruments.batch` 5534 只 / **0.97s**，涨跌停价 **100% 覆盖** | — |

最后一行解掉了一条长期已知边界：`strong_count` 此前用「涨幅 ≥ 9.5%」近似涨停，分不清主板 10% 与创业板/科创板 20%。实测宁德时代涨停价 482.26（20%）、平安银行 12.77（10%），两档区分正确。**该判据尚未改用真实涨停价**——它直接喂板块打分，换判据会让历史分数不可比，须连同阈值重标定一起做，见 `sectors/momentum.py` 注释。

### 5.3 分钟 K 线的两个硬边界

**单次 5000 根封顶。** `count` 传 5000/10000/20000 返回的都是 5000 根，配 `start_time` 放宽窗口也一样——服务端给的永远是 `end_time` 之前最近的 5000 根。要更早的数据只能**把 `end_time` 逐段前推**，见 `adapters/tickflow_intraday.fetch_minute_history`。

**各周期的数据底**（实测 600519.SH）：

| 周期 | 单次上限 | 覆盖 | 数据底 |
|---|---|---|---|
| 1m | 5000 根 | 21 个交易日 | 翻页可达 **2025-05-23** |
| 5m | 5000 根 | 104 个交易日 | 2025-05-23 |
| 15m / 30m / 60m | 4648 / 2324 / 1162 根 | 291 个交易日 | 2025-05-23 |

翻页实测：600519.SH 1m 拉满 12 个月 = **58322 根 / 242 个交易日 / 5.5 秒 / 12 页**。

**这是「未经回测」第一次具备解除条件**——仓内 `advise` 的价位规则、板块打分权重、仓位系数映射全部是人工设定且从未验证过，此前没有分钟级历史可用。

### 5.4 两个会静默出错的量纲陷阱

付费档与免费档对同一件事用了不同量纲，错一处不会报错，只会算错：

| 字段 | TickFlow | 新浪 | 后果 |
|---|---|---|---|
| `volume`（行情与分钟线） | **手** | 股 | 差 100 倍。`_vwap` 用 `amount/volume`，不换算茅台 VWAP 会算成 135083 而不是 1351 |
| `ext.change_pct` | **比值**（-0.0082） | 百分数（-0.82） | 差 100 倍 |
| 流通市值 | 需自算 `float_shares × 现价`（元） | `nmc`（**万元**） | 不归一则 20 亿门槛变 20 万，可交易性筛选静默失效 |

外加一条浮点卫生：复权后 OHLC 四个字段各自带尾巴，实测 60 只 / 15000 根 1 分钟线里 **1399 根（9.33%）满足 `high < low`**（量级 1e-13）。下游拿 `high - low` 当振幅、拿 `low == min(lows)` 找枢轴点，倒挂会静默出错。取到 4 位小数后归零。

以上每一条都有测试钉住（`tests/test_tickflow_market.py`、`tests/test_tickflow_intraday.py`）。

**付费也买不到的**（不变，见 `docs/PLAN_REVIEW.md`）：集合竞价撮合量/未匹配量。加上 **09:20–09:25 交易所不接受撤单**，该窗口撤单率恒为 0，任何档位、任何数据源都拿不到。

## 六、仍然没测的一件事：盘中时效

非交易时段测不出盘中时效。**这一项对免费档和付费档都还是未知数**：

```bash
python3 scripts/source_audit.py --watch 600 --interval 3
ashare-ds intraday-check --symbols 600519.SH          # 走当前实际在跑的那条路
```

看两个数：

- **数据滞后中位** ≤ 3s → 该档位可支撑盘中判断
- **时间戳前进次数** 接近轮询次数 → 数据真在更新；若为 0，说明盘中不推进

要比的是**两条路的相对时效**：如果付费档与新浪相当，那就确认这 ¥99 买的是分钟历史与配额而非实时性；如果付费档明显更新，实时这条线也该切过去。

2026-08-01 周六测得滞后 ≈ 9 万秒（即距上次收盘的自然时间），**该数字在非交易时段无意义**，脚本会明确标注。
