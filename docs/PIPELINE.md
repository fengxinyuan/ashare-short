# 链路详解：舆情 → 板块 → 选股 → 买卖点

总览见 [`SOLUTION.md`](SOLUTION.md)，模块边界见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，
数据源实测见 [`DATA_SOURCES.md`](DATA_SOURCES.md)。本文写每一段具体怎么算、为什么这么算。

```text
0. 舆情入库   采集 → 跨源去重 → 时效折权 → 大模型归因 → **写入语料库**
1. 板块定义   TickFlow universes  →  31 个申万一级行业（335 个分片按名合并）
2. 板块动量   成分股日线（批量）  →  中位涨幅 / 上涨占比 / 量比 / 站上 MA20 占比
2b. 板块指数  同花顺 90 个行业指数 →  收盘日内位置 / 距 20 日高（**并列读数，不进打分**）
3. 舆情读数   语料库 → 词典打分 / 模型标签 → 按行业归因
4. 资金       龙虎榜净买额        →  按成分股汇总到板块
5. 板块排序   动量(±30) + 舆情(±12) + 资金(±8) + 基准 50
6. 硬筛       ST/退市/非可交易板块 → 可交易性（流通市值/成交额） → 致命公告否决
7. 个股打分   日线技术面 + 威科夫 + 低吸画像 + 个股舆情（两段粗排/精排）
8. 买卖点     L1 事实 → L2 候选价位 → L3 模型裁决 → 数字闸门
9. 出稿       模板渲染 →（可选）LLM 改写 → 数字校验 → 合规文本追加
```

## 0. 舆情入库：缓存与语料库是两件事

```text
采集（全天多次）
   ↓  缓存层：按「交易日 + 源」缓存，TTL 1 小时
   ↓  解决「同一个早上跑两次不要重复拉」
   ↓
   ↓  语料库：按 (source, url) 或标题指纹去重入库
   ↓  记 first_seen_at / last_seen_at / seen_count
   ↓  记模型归因结果（板块、方向、事件类型、传导机制）
   ↓
派生读数
   ├── 板块热度时间序列
   ├── 新鲜度：新出现的 vs 在重复播
   └── 事后归因：当时为什么选了这个板块，原文还在
```

**为什么必须记 `first_seen`。** 对超短线，同一条利好「10 分钟前第一次出现」和
「已经发酵三天」是完全不同的两件事——前者是机会，后者往往是接盘位置。临时缓存里
两者长得一模一样，因为它只存「今天见到的」。

### 五路舆情，分工不重叠

| 源 | 补的是什么 |
|---|---|
| 财联社电报 | 盘面情绪、题材，**时效趋近 0** |
| 东财全球快讯 | 盘面情绪、题材，200 条/次 |
| 新闻联播 | 政策主线 |
| 沪深全量公告 | 风险否决（带交易所指定的**公告类型**字段，不用解析自由文本） |
| 华尔街见闻 | **数据发布（PMI/CPI/社融）与海外流动性** |

最后一路补的是实测出来的硬缺口。2026-08-02 实测，原有三路在全市场 200 条里的命中：

| 关键词 | 命中 |
|---|---|
| 伊朗 / 中东 | 66 / 26 ✅ 地缘覆盖得很好 |
| **PMI / 统计局 / 制造业** | **0 / 0 / 0** |
| **美债 / 收益率 / 降准 / 关税** | **0 / 0 / 0 / 0** |

**宏观数据发布对系统完全不可见。** 同一天 07-31 09:30 公布的「中国 7 月官方制造业
PMI 49.2（前值 50.3）」三个全线跌破荣枯线——链路里一个字都没有。这不是权重问题，
是这类消息压根没进来。

对盘前研判是硬缺口：板块方向可以靠量价推，**风格切换不行**。PMI 破荣枯线直接对应
「宽松预期升温 → 红利/消费占优、顺周期走弱」，而这条推理链的输入端是空的。

接入后实测：舆情从 200 条 → **324 条（去重后）**，归到板块的从 81 条 → **146 条**。

**翻页按时间窗而不是页数**：两个频道流量差一个数量级，固定页数会让高流量频道只翻到
几小时前——07-31 09:30 的 PMI 恰好落在那个盲区里。窗口锚在 `trade_date`，所以同一个
交易日无论几点跑，取回的输入都一样。

### 时效折权与去重

- 按发布时间做 **12 小时半衰期**折减，超过 **72 小时**整条丢弃
- 跨源同标题合并，保留**最早发布**的那条
- 无法解析时间戳的**不折减**（否则只给日期的源会被整体抹掉），但会计数并写进简报

### 大模型归因：只出标签，不出数字

`news/llm_classifier.py` 让模型输出：属于哪些板块、方向、事件类型、传导机制。
**标签到分值的映射仍是规则层的固定表。**

模型归因**会错，而且错得像对的**。实测两个真实缺陷：

1. 模型自报的序号整体偏一位，导致整批标签错行——「法国森林火灾」拿到了
   「动画电影票房超预期」的归因
2. 模型会给海外灾害硬凑 A 股板块

现在的防线：

- 对齐只认**模型回抄的标题前缀**（可拿原文核对），核不上就丢
- 归了板块却**说不出传导机制**的，按未归因处理
- **半数以上对不上则整批作废**，退回关键词词典

实测 180 条快讯里 95 条归到板块，其余模型主动弃权。没配 key、调用失败、或对齐核不上，
整批退回词典，简报里写明本轮走了哪条路。

## 1–2. 板块定义与动量

`universes.list()` 返回 1013 个 universe。一级行业以 **335 个分片**到达、
**折成 31 个行业名**，所以必须先按名合并；`universes.get(id)` 再返回成分股。
覆盖 5528 只 A 股里的 4430 只。

这是整条板块链路能在无订阅条件下跑通的关键，而它在 SDK 文档里并不显眼。

**东财 `push2` 系接口在本机全部不可达，所以板块行情不是直接取板块指数，
而是从成分股日线聚合出来的。** 这条链路不依赖任何 `push2` 接口。

### 分类缓存的两条完整性约定

335 个分片要打 335 次，而免费档闸门是 60 次/滚动 60 秒。撞墙后如果把异常吞成
「这个分片没有成分股」，写出来的就是一份**缺片但外观正常**的分类——2026-08-01 现场
那份少了 469/4430 只，31 个行业一个不缺，链路照跑不误。**缓存是永久的，一次限流会
污染之后每一次盘前扫描。**

所以：

1. **有任何分片取数失败就抛 `SectorTaxonomyError`，且不写缓存。**
   `_universe_get` 返回 `None` 表示取数失败，与「成分股确实为空」区分开——
   后者是合法读数，不该触发告警。
2. **缓存带 `schema` 戳，无戳的一律重建。**

冷启动耗时取决于档位：免费档逐个取 335 个分片、被节流，约 **6 分钟**；付费档走
`universes.batch(ids)`，两次调用 **1.58 秒**（实测输出完全一致：31 个行业 / 4430 只 /
0 个失败分片）。`--output-dir` 默认固定是 `briefs`，所以这个代价只付一次；
用按日期命名的输出目录会每天重付。

## 2b. 为什么要第二套板块读数

申万成分股聚合拿不到两样东西：

1. **市值加权的板块指数本身**——所有人嘴里的「半导体今天跌了多少」说的是这个，
   不是成分股涨跌幅的中位数。两者不一样的时候恰恰是信息：**指数涨、宽度弱 = 权重股拉抬**。
2. **板块级的日内位置**——收盘落在当日区间的哪个分位。2026-07-31 实测：半导体
   **+4.23% 却收在当日最低**（收位 0%），同日白酒 +0.63% 收在当日最高（收位 97%）。
   「涨了多少」两者都是正的，「谁在被卖」只有收位看得见。

它**刻意不参与打分**：同花顺 90 个行业 ≈ 申万二级粒度，硬映到申万一级 31 个只会造出
一个看起来精确的错数。两套读数并列呈现，由人（或写稿层）去读它们的分歧。

## 5. 板块排序与仓位系数

### 覆盖率不够的板块被排除，而不是给默认分

一个成分股拿不到日线的板块，`trusted=False`，**永远不会被选中**。

如果给它中性 50 分，那么「没数据」会压过「有数据但走弱」（走弱的板块会低于 50）。
**排序里最不该出现的就是无知胜过测量。**

### 舆情权重的两道闸

板块级上限 **±12 分**，个股级 **±6 分**——都压不动量价，因为关键词与模型标签都会误归因。

另一道是样本量：文档数不足 8 条时按 `条数/8` 折权。**没有这道闸时实测出现过基础化工
靠 2 条快讯拿满 +12、计算机 22 条只拿 +2.0**——`intensity` 是命中密度而非证据量，
样本越小平均密度越高，方向正好反了。

### 仓位系数封顶 0.80，且在普涨末段下调

- 基准 `0.15 + 宽度 × 0.75`，封顶 **0.80**——任何未经回测的单一读数都不该建议满仓
- 若宽度 ≥ 85% **且** 板块 5 日中位涨幅 ≥ 6%，乘 0.75 并写明理由

对超短线来说，「83% 个股上涨、5 日已涨 7~10%」的那天是**你来晚了**，不是起涨点。
朴素的宽度映射会在情绪最热时给最大仓位，顺周期，恰好错在最贵的地方。

该系数始终是**建议值**，`--position-factor` 手工值优先，且两者都会打印出来供对照。

### 涨停池：指数与情绪可以反向

实测当日指数口径大盘 79.7 偏多，而**炸板率 52%、107 只炸板**——指数全线上涨与封板
意愿崩塌是同一天发生的两件事，此前链路里一个读数都看不到后者。

炸板率 `炸板 / (涨停 + 炸板)` 与最高连板进 `MarketOutlook`，上限 ±10 分。
服务端对周末/盘前日期返回最近交易日，所以**以响应里的 `qdate` 标注数据日期**，
而不是以请求日期。

**「连板高度」只认东财 `lbc`。** 同一行里的 `zttj` 是「N 天 M 板」统计窗口，
不是连板数（爱丽家居 `{'days':20,'ct':10}` + `lbc=9` = 20 天 10 板、当前连 9 板）。
读错字段会把统计窗口当高度，而这个数直接进情绪打分（≥5 加分、≤2 减分），一只
「10 天 5 板」的**首板**股会把减分翻成加分。

## 6. 硬筛：筛选与打分分离

screen 直接踢出标的，不是扣分。**ST、退市、立案调查这类风险无法被好走势补偿，
做成扣分迟早会被其他因子的正分盖过。**

顺序：ST/退市 → 可交易性 → 致命公告。可交易性放中间是因为它最便宜（本地查表），
先砍掉一批能让后面的公告匹配少做无用功。

### 可交易性这一层此前是空的

候选池原来只过 ST 与致命公告——一只 15 亿流通、日成交 3000 万的票和茅台在筛选层面
完全等价。**超短线的核心风险不是买错，是卖不掉**，而此前没有任何一层看这件事。

现在按流通市值 ≥ 20 亿、日成交额 ≥ 0.8 亿过滤（阈值可传参）。实测一次盘前扫描剔除
**242 只**。取值偏松是刻意的：这一层的职责是**排除不可交易**，不是替使用者选票。

拿不到行情的标的**一律放行**并单独计数——用「没测到」当否决理由，等于让数据缺失
冒充风险判断。

### 公告风险否决用的是上一个有公告的自然日

盘前 08:30 跑时当日公告尚未披露，周末与节假日更是一条都没有（akshare 在空结果上抛
`KeyError: '代码'`，不是返回空表）。所以按自然日回退最多 5 天，实际用的日期会写进 note。
回溯 5 天还取不到就明说「本次没有公告风险否决」——**这一层静默消失比缺一条候选危险**。

新闻联播同理：盘前跑时今晚的联播还没播，硬取「今天」的结果是政策主线源每天早上静默
缺席（实测 2026-08-02 返回 0 条，而 07-31 有 15 条）。已改为回退最近一期有稿的日子。

## 7. 个股打分：整体口径是低吸，不是追涨

### 为什么转向低吸

2026-08-02 实测：转向前这套打分选出的 30 只候选，按标的自身波动归一化后，
落在低吸理想窗口的 **0 只**、缩量的 **0/30**、19 只根本没有回调。
**它一直在选「正在涨的票」而不是「回调到位的票」。** 三处根因：

1. 威科夫 MARKUP（主升段）给 +12，而 LPS（回踩承接）只给 +4——权重把追高排在了回踩前面
2. 量能 `ratio >= 1.0` 一律 +8，缩量 `< 0.6` 反而 -5。**低吸最健康的形态恰恰是缩量回调**
   （回调放量意味着出货），符号是反的
3. 全部用阶跃函数，量比 1.02 和 3.99 同分，而 4.0 处有 13 分悬崖。项目在大盘层已经
   明确否定过阶跃，个股层没同步

现在的口径：**趋势还在（L1）× 回调到位（L2）× 缩量（回调质量）**，斜坡取代阶跃。

### 低吸画像按标的自身波动归一

档位单位是**这只票自己的日均真实波幅（ATR%）**，不是绝对百分比。用绝对百分比是错的，
2026-08-02 实测八只票一年日线：

```
长江电力（日振幅 1.82%）  ideal 只占  8% 的交易日，deep 一次都没到过
计算机题材（日振幅 6.23%） deep 占了 49% —— 一个本该意味着「趋势可能已破坏」
                          的档位成了它的常态，等于没有告警能力
```

归一化之后同一档位在不同波动的票上含义才一致：建行一年最大回撤 -11.47%、长电 -7.85%，
绝对值差 46%，除以各自日振幅后是 **4.4 与 4.3——几乎相同**。

档位 `0.8 / 2.0 / 4.0` 个日波幅，是拿八只票（五只红利蓝筹 + 计算机/传媒/茅台）的分布
标定出来的，目标是**每只票四个档位都填得满、且没有哪一档吞掉一半以上**。
这是先验校准，**不是收益验证**——哪一档真的更值得买，要等台账样本回答。

用**真实波幅（含跳空）**而不是简单的 `high-low`：A 股一字板和跳空开盘时，当日最高最低
可以贴在一起，只看日内区间会把「跳空 5%」读成「几乎没波动」。

### 量能的含义随所处阶段翻转

**回调途中要的是缩量**（放量下跌是出货），**没有回调时放量才是启动确认**。
同一个量比在两种状态下意义相反，所以量能项必须读 `dip.pullback_band` 才能定符号。

### 止损距离的上下限

实测 603508.SH 现价 23.16、最近支撑 23.15，止损距离 **0.04%**——A 股日内正常振幅
3–5%，这种止损是随机噪声，必然被打掉，而且它会让盈亏比算出 **172.84** 直接拿满分。

所以止损必须落在 **1 个日均波幅之外**（低于这个距离的不是止损，是在赌下一跳的方向），
且不超过 **3 个日波幅**（更远的「止损」已经保护不了任何东西，只会制造一个假的大分母）。
两头都用 ATR 而非固定百分比，理由和低吸档位一样。

### 两段打分：粗排 → 精排

个股新闻是**每标的一次 HTTP**，对几百只成分股全拉是几分钟的事，为了一个封顶 ±6 分的
读数不值得。所以：

```text
量价粗排  →  每板块取 per_sector × 3（全局封顶 40 只）  →  拉个股新闻与当日公告  →  精排
```

3 倍这个系数是拿封顶反推的：舆情最多改变 ±6 的原始分，映射到终分约 ±3.9。一只在本
板块排到 3 倍配额之外的票，需要越过的分差通常大于这个量。

**落在网外的票会计数并写进 note**——被截掉多少必须说出来，不能让「只看了前 N 只」
读起来像「全看过了」。

## 8. 买卖点：候选集 + 裁决　⬜ 未建

> **现状**：`advice/engine.py` 直接产出单一组价位（买入区间 = VWAP ± 12% 日振幅、
> 止损 = 当日低点下方 15% 日振幅、目标 = 当日高点与日线压力），常量写死在模块里。
> 情景推演与「无参照追高位置不给目标价」已建；候选集与模型裁决未建。
>
> 本节描述目标形态。架构与理由见 [`SOLUTION.md`](SOLUTION.md) §三。

### L2 候选价位的来源

| 候选类型 | 来源 | 何时可用 |
|---|---|---|
| 分时均价回踩 | `signals/intraday.py` VWAP | 盘中 |
| 当日低点 / 当日高点 | 分时序列 | 盘中 |
| 五档买盘墙 / 卖盘墙 | `signals/orderflow.py` ⬜ 未建 | 盘中，五档可得时 |
| 日线支撑 / 压力 | `signals/daily_technical.py` 枢轴点 | 总是 |
| 回调 N 个日波幅 | `signals/dipbuy.py` 档位 | 总是 |
| 20 日高 / 60 日区间边界 | 日线序列 | 总是 |
| 缺口位 | 日线跳空 | 总是 |
| 真实涨停价 / 跌停价 | `adapters/snapshot.py`（腾讯，已实测可用但无调用方） | 盘中 |

每个候选带 `basis`（人话出处）和 `evidence`（支撑它的 L1 读数）。规则给出
`default_rank`——**LLM 不可用时直接取 rank 0，链路照跑**。

### 五档能说什么、不能说什么

**能**：委比（买卖挂单量之比）、买卖盘厚度、挂单墙价位、spread。这些是**当下挂着的单**。

**不能**：委托流向、撤单率、大单意图。逐笔委托与撤单记录**任何档位都拿不到**，
集合竞价撮合量/未匹配量同理。

所以五档在打分里是**有界读数**（上限与个股舆情同量级 ±6），只做旁证不做主判：
它可以被撤、可以是假挂，而且只有五档。**把它当主判据，等于把仓位押在别人随时能
撤掉的挂单上。**

### 情景推演，不是概率　✅ 已建

```text
强势延续  放量站上当日高点 X   → 沿分时均价持有；跌回均价下方即结束该情景
均价震荡  在均价 Y 与高点 X 间  → 方向未定，只做回均价的低吸，不追高
转弱回落  有效跌破均价 Y 不收回 → 下看当日低点 Z；跌破则当日结构破坏
```

**没有概率、没有胜率、没有预期收益率**——没有拟合模型能支撑它们。系统只印
**会改变判断的价位**。

### 现价已是当日最高且上方无历史压力时

不给目标价，直接说明：「属于无参照的追高位置，只能用移动止损跟随」。
**印一个破折号会让人以为系统算不出来，说清楚才知道这是位置的性质。**

## 9. 出稿：LLM 不能引入任何数字

`writer/llm.py` 的闸门：生成文本中的每个数字，必须能追溯到输入 facts——逐字命中、
按书写精度四舍五入命中、或经 `万/亿/%` 换算命中。否则**整段丢弃，回退模板**。

已知会被误判的四类格式（都已放行，有测试覆盖）：

| 形式 | 例子 | 处理 |
|---|---|---|
| 补尾零 | facts `8.1` → 输出 `8.10` | 数值比对放行 |
| 长浮点四舍五入 | facts `12198154.379999977` → 输出 `12198154.38` | 按精度比对放行 |
| 千分位逗号 | 输出 `12,198,154.38` | 正则整体识别为一个数 |
| 单位换算 | facts `0.6667` → 输出 `67%` | 按后缀 scale 放行 |

买卖点裁决走**更严的闸门**（⬜ 随 L3 一起未建）：价格必须**恰好等于**某个 L2 候选
或 L1 读数。近似匹配在价位上是危险的——22.95 和 22.96 在文本比对里都能过，但那是
两个不同的挂单价。

**合规文本（纪律提醒、免责声明）在生成之后程序化追加，不交给模型。**
实测 Qwen 在被明确要求「保留全部风险提示」时，仍然会在概括过程中整段丢掉。

## 词典与关键词的维护

- `news/lexicon.py`：利好/利空词表 + 程度副词 + 否定词。加词是一行改动，不需要动打分逻辑。
- `sectors/keywords.py`：申万行业名 → 新闻实际用词（「电力设备」→ 光伏/储能/锂电/风电…）。
  **没有这张表，舆情项会全为 0**，因为新闻里从不出现「申万电力设备」这种说法。

两张表都是人工整理、未经拟合。**权重是相对量级，不是概率。**

## 已知边界

- 板块打分、个股打分、买卖点规则**全部未经回测**，只决定「今天先看哪里、哪个价位重要」
- 模型裁决尚未建成；建成后同样是未经验证的——给裁量权是因为写死的阈值同样没有依据，
  不是因为有证据说模型更好
- `strong_count` 用涨幅 ≥ 9.5% 而非真实涨停判定，分不清 10% 与 20% 板。数据侧限制已解除，
  但换判据会让历史板块分数不可比，须连同阈值重标定一起做
- 龙虎榜是 T+1 数据，反映昨天的资金
- 同花顺行业指数不参与打分，只并列呈现
- 可交易性阈值（流通 20 亿 / 成交额 0.8 亿）是行业惯例量级，不是拟合结果；
  它只排除「进出困难」，不代表通过的票流动性充足
- 两家的分钟线并不逐根相同，相对差最大 0.15%~0.31%——不要混用，也不要拿一条路的历史
  回测另一条路要跑的规则
- **免费档盘中时效仍未实测**
