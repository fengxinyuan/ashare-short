# 链路详解：舆情 → 板块 → 选股 → 买卖点

总览见 [`SOLUTION.md`](SOLUTION.md)，模块边界见 [`ARCHITECTURE.md`](ARCHITECTURE.md)，
数据源实测见 [`DATA_SOURCES.md`](DATA_SOURCES.md)。本文写每一段具体怎么算、为什么这么算。

```text
0. 舆情入库   采集 → 跨源去重 → 时效折权 → 大模型归因 → **写入语料库**
1. 板块定义   TickFlow universes  →  31 个申万一级行业（335 个分片按名合并）
2. 板块动量   成分股日线（批量）  →  中位涨幅 / 上涨占比 / 量比 / 站上 MA20 占比
2b. 板块指数  同花顺 90 个行业指数 →  收盘日内位置 / 距 20 日高（**并列读数，不进打分**）
3. 舆情读数   语料库 → 词典打分 / 模型标签 → 按行业归因
4. 资金       龙虎榜净买额        →  按成分股汇总到板块
5. 板块排序   动量(±30) + 舆情(±12) + 资金(±8) + 基准 50
6. 硬筛       可交易性（流通市值/成交额） → 致命公告否决
7. 个股打分   日线技术面 + 威科夫 + 低吸画像 + 个股舆情（两段粗排/精排）
8. 买卖点     L1 事实 → L2 候选价位 → L3 模型裁决 → 数字闸门
8b. 持仓卖点  止损 · 目标 · 结构破坏 · 时间止损 · 浮盈回吐（后两类只对持仓）
9. 出稿       模板渲染 →（可选）LLM 改写 → 数字校验 → 合规文本追加
```

## 0. 舆情入库：缓存与语料库是两件事

```text
采集（全天多次）
   ↓  缓存层：按「交易日 + 源」缓存，TTL 1 小时
   ↓  解决「同一个早上跑两次不要重复拉」
   ↓
   ↓  语料库：按 (source, url) 或标题指纹去重入库
   ↓  记 first_seen_at / last_seen_at / seen_count
   ↓  记模型归因结果（板块、方向、事件类型、传导机制）
   ↓
派生读数
   ├── 板块热度时间序列
   ├── 新鲜度：新出现的 vs 在重复播
   └── 事后归因：当时为什么选了这个板块，原文还在
```

**为什么必须记 `first_seen`。** 对超短线，同一条利好「10 分钟前第一次出现」和
「已经发酵三天」是完全不同的两件事——前者是机会，后者往往是接盘位置。临时缓存里
两者长得一模一样，因为它只存「今天见到的」。

### 五路舆情，分工不重叠

| 源 | 补的是什么 |
|---|---|
| 财联社电报 | 盘面情绪、题材，**时效趋近 0** |
| 东财全球快讯 | 盘面情绪、题材，200 条/次 |
| 新闻联播 | 政策主线 |
| 沪深全量公告 | 风险否决（带交易所指定的**公告类型**字段，不用解析自由文本） |
| 华尔街见闻 | **数据发布（PMI/CPI/社融）与海外流动性** |

最后一路补的是实测出来的硬缺口。2026-08-02 实测，原有三路在全市场 200 条里的命中：

| 关键词 | 命中 |
|---|---|
| 伊朗 / 中东 | 66 / 26 ✅ 地缘覆盖得很好 |
| **PMI / 统计局 / 制造业** | **0 / 0 / 0** |
| **美债 / 收益率 / 降准 / 关税** | **0 / 0 / 0 / 0** |

**宏观数据发布对系统完全不可见。** 同一天 07-31 09:30 公布的「中国 7 月官方制造业
PMI 49.2（前值 50.3）」三个全线跌破荣枯线——链路里一个字都没有。这不是权重问题，
是这类消息压根没进来。

对盘前研判是硬缺口：板块方向可以靠量价推，**风格切换不行**。PMI 破荣枯线直接对应
「宽松预期升温 → 红利/消费占优、顺周期走弱」，而这条推理链的输入端是空的。

接入后实测：舆情从 200 条 → **324 条（去重后）**，归到板块的从 81 条 → **146 条**。

**翻页按时间窗而不是页数**：两个频道流量差一个数量级，固定页数会让高流量频道只翻到
几小时前——07-31 09:30 的 PMI 恰好落在那个盲区里。窗口锚在 `trade_date`，所以同一个
交易日无论几点跑，取回的输入都一样。

### 时效折权与去重

- 按发布时间做 **12 小时半衰期**折减，超过 **72 小时**整条丢弃
- 跨源同标题合并，保留**最早发布**的那条
- 无法解析时间戳的**不折减**（否则只给日期的源会被整体抹掉），但会计数并写进简报

### 大模型归因：只出标签，不出数字

`news/llm_classifier.py` 让模型输出：属于哪些板块、方向、事件类型、传导机制。
**标签到分值的映射仍是规则层的固定表。**

模型归因**会错，而且错得像对的**。实测两个真实缺陷：

1. 模型自报的序号整体偏一位，导致整批标签错行——「法国森林火灾」拿到了
   「动画电影票房超预期」的归因
2. 模型会给海外灾害硬凑 A 股板块

现在的防线：

- 对齐只认**模型回抄的标题前缀**（可拿原文核对），核不上就丢
- 归了板块却**说不出传导机制**的，按未归因处理
- **半数以上对不上则整批作废**，退回关键词词典

实测 180 条快讯里 95 条归到板块，其余模型主动弃权。没配 key、调用失败、或对齐核不上，
整批退回词典，简报里写明本轮走了哪条路。

**事件类型也要过清单。** 板块名和方向一直在校验，事件类型此前没有——实测 314 条
归因里 17 条（5.4%）带着清单外的自创类型（销量 10、事件 3、高管变动 / 组织调整 /
产品创新 / 品牌建设各 1），而它们会原样印进简报的「关键词：技术突破、品牌建设、
需求变化」。现在清单外的值置空（`EVENT_TYPES`），归属与方向仍保留——只有这个标签不可信。

### 0b. 舆情通读：逐条打标签答不了的那部分

`news/daily_read.py`。**和上面那条路并列，不是替代。**

打标签解决「板块排序要不要动」，但它把每条快讯独立压成三个标签，于是**跨条目、
跨市场的因果链整个消失了**：

| 事件 | 传导 | 落到 A 股 |
|---|---|---|
| 中东冲突升级 / OPEC+ 增产 | 原油供给风险溢价 | 石油石化、油运；航空反向 |
| 韩股 SK海力士涨停、美股存储指数大涨 | 存储周期共振 | 半导体、存储、PCB |
| 美债 10 年期收益率创新高 | 无风险利率上行 | 成长股、创新药、AI 算力承压 |
| 离岸人民币单日贬值 | 出口链汇兑弹性 | 电子代工、家电 |

这些链条的两端分属不同条目甚至不同市场。按条打标签时，「以色列袭击伊朗」归到国防
军工、「原油涨 3%」归到石油石化，而**把两者连起来的那句话不会出现在任何输出里**。

所以整份清单交给模型读一遍，输出 `chains`（触发 → 机制 → 品种 → 方向）、主线、风险，
以及持仓各自的消息。三条硬约束：

- **每条结论必须回抄它依据的标题前 12 字**，核不上就丢（与上面的对齐同一套做法）
- **数字闸门复用 `writer/llm.py` 的 `unverified_numbers`**：输出里每个数字都要能在
  喂进去的标题里找到。可以引用「韩国综指涨 17.91%」，不能写「预计高开 2%」——整份丢弃
- **不进打分。** 不改板块分、不改选股、不写台账。产物只是简报里的一段

**取样按分节配额，不按新鲜度截断。** 实测语料 1205 条里 A 股盘面快讯占绝大多数且
时间最新，纯按时间取前 240 条会把海外压到 21 条、宏观数据压到 1 条——而海外与宏观
正是这一层存在的理由。配额取样后八节全部取满（海外 45 / 美国政治 30 / 海外公司 22 /
地缘 25 / 大宗 20 / 政策 35 / 宏观 15 / A股 48）。

为此 `NewsAgent` 的市场快讯取宽到 600/源（`WIDE_MARKET_LIMIT`），但送进**板块归因**的
仍按原量级封顶（`CLASSIFY_MAX_DOCS` 360）——多出来的那批绝大多数是海外与地缘消息，
本来就归不到 A 股板块，让分类器按批计费地读它们没有意义。两层共用一个语料，各取所需。

## 1–2. 板块定义与动量

`universes.list()` 返回 1013 个 universe。一级行业以 **335 个分片**到达、
**折成 31 个行业名**，所以必须先按名合并；`universes.get(id)` 再返回成分股。
覆盖 5528 只 A 股里的 4430 只。

这是整条板块链路能在无订阅条件下跑通的关键，而它在 SDK 文档里并不显眼。

**东财 `push2` 系接口在本机全部不可达，所以板块行情不是直接取板块指数，
而是从成分股日线聚合出来的。** 这条链路不依赖任何 `push2` 接口。

### 分类缓存的两条完整性约定

335 个分片要打 335 次，而免费档闸门是 60 次/滚动 60 秒。撞墙后如果把异常吞成
「这个分片没有成分股」，写出来的就是一份**缺片但外观正常**的分类——2026-08-01 现场
那份少了 469/4430 只，31 个行业一个不缺，链路照跑不误。**缓存是永久的，一次限流会
污染之后每一次盘前扫描。**

所以：

1. **有任何分片取数失败就抛 `SectorTaxonomyError`，且不写缓存。**
   `_universe_get` 返回 `None` 表示取数失败，与「成分股确实为空」区分开——
   后者是合法读数，不该触发告警。
2. **缓存带 `schema` 戳，无戳的一律重建。**

冷启动耗时取决于档位：免费档逐个取 335 个分片、被节流，约 **6 分钟**；付费档走
`universes.batch(ids)`，两次调用 **1.58 秒**（实测输出完全一致：31 个行业 / 4430 只 /
0 个失败分片）。`--output-dir` 默认固定是 `briefs`，所以这个代价只付一次；
用按日期命名的输出目录会每天重付。

## 2b. 为什么要第二套板块读数

申万成分股聚合拿不到两样东西：

1. **市值加权的板块指数本身**——所有人嘴里的「半导体今天跌了多少」说的是这个，
   不是成分股涨跌幅的中位数。两者不一样的时候恰恰是信息：**指数涨、宽度弱 = 权重股拉抬**。
2. **板块级的日内位置**——收盘落在当日区间的哪个分位。2026-07-31 实测：半导体
   **+4.23% 却收在当日最低**（收位 0%），同日白酒 +0.63% 收在当日最高（收位 97%）。
   「涨了多少」两者都是正的，「谁在被卖」只有收位看得见。

它**刻意不参与打分**：同花顺 90 个行业 ≈ 申万二级粒度，硬映到申万一级 31 个只会造出
一个看起来精确的错数。两套读数并列呈现，由人（或写稿层）去读它们的分歧。

## 2c. 轮动与成交额迁移：同一批序列，两个问题

同花顺板块指数的整年日线落盘之后（`adapters/ths_sector_index.py:_persist_history`），
有两层纯计算的读数从它读回来。**都不进打分**，理由与 2b 相同。

### 轮动必须报两个窗口，而且它们经常反号

「资金从高位板块流向低位板块」的可测版本是：**前期涨幅与近期涨幅在横截面上的秩相关**。
但「前期」怎么取，会决定结论。

| 口径 | 2026-08-03 实测 | 标签 |
|---|---|---|
| 20 日 vs 5 日（**窗口重叠**） | +0.68 | 强者恒强 |
| 前 15 日[t-20→t-5] vs 近 5 日 | +0.45 | 强者恒强 |
| **相邻两个 5 日**（等长、不重叠） | **-0.47** | **高低切换** |

第一行是**不会报错的错误**：20 日窗口**包含**最近 5 日，本周暴涨的板块自动显得
「前期已经涨高了」，给相关系数注入纯机械的正偏。这条已经修掉（`_pct_between`）。

后两行都正确，但回答的不是同一个问题，所以**两个都要出**：

- `switch_correlation`（长窗口对短窗口）：这**一个月**的趋势有没有反转；
- `adjacent_correlation`（相邻等长窗口）：这**一周**资金有没有掉头。

同一天一个 +0.45「强者恒强」、一个 -0.47「高低切换」，不是矛盾——半导体前期
-22.8% 之后继续跌 -12.8%（月度弱者恒弱成立），但它在中间那一周反弹到第 6 名，
于是相邻窗口读出 6→89 的剧变。**超短按后者，仓位按前者**，简报里这句话会自动出现。

`adjacent_correlation` 与 `rank_change` 用的是同一对窗口，这是刻意的：排名变化榜说
「谁从第 90 冲到第 7」，相关系数说「这种对调是整体现象还是个例」。此前只有前者，
于是「谁在涨」有数、「是不是在切换」没数。

### 成交额迁移：占比上升不等于资金进场

同一批序列里的 `amount`，回答的是价格答不了的那个问题：**钱挪到哪个板块去了**。

**它不叫「资金流」，也不许被写成那样。** 成交额是双边的，一笔成交同时是买和卖；
带方向的「主力净流入」要么来自逐笔推断（只有当日、方向是厂商推断），要么来自东财
push2（本机被出口代理挡死）。这一层两样都不是。同一条纪律的出处见
`signals/volume_price.py` 开头。

用**占比**而不是绝对额：全场成交总额本身在剧烈波动（实测近 5 日均值比前 15 日低
14.0%），看绝对额几乎每个板块都在「流出」，那测的是水位不是迁移。但占比会抹掉总量，
而总量恰恰决定含义——**存量腾挪下的高低切换与增量入场下的高低切换，对仓位的含义
相反**，所以总量单独出一个读数。

判据强制配价格方向，否则整层唯一会被读反的那格就会混进「资金流入」榜：

```text
占比↑ + 价↑   放量上涨   有人在买
占比↑ + 价↓   放量下跌   有人在跑     ← 只看占比会读成「资金流入」
占比↓ + 价↑   缩量上涨   惜售，但没有新钱
占比↓ + 价↓   缩量阴跌   没人看
```

另出一条**绝对额榜**，因为占比榜会漏掉一整类：总量整体收缩时，成交额腰斩的板块
占比可能几乎不动。2026-08-03 的半导体日均少了 887 亿（全场最大），占比只动 -4.8%，
落在中性带里，在占比榜上一行都不出现。

## 5. 板块排序与仓位系数

### 覆盖率不够的板块被排除，而不是给默认分

一个成分股拿不到日线的板块，`trusted=False`，**永远不会被选中**。

如果给它中性 50 分，那么「没数据」会压过「有数据但走弱」（走弱的板块会低于 50）。
**排序里最不该出现的就是无知胜过测量。**

### 舆情权重的两道闸

板块级上限 **±12 分**，个股级 **±6 分**——都压不动量价，因为关键词与模型标签都会误归因。

另一道是样本量：文档数不足 8 条时按 `条数/8` 折权。**没有这道闸时实测出现过基础化工
靠 2 条快讯拿满 +12、计算机 22 条只拿 +2.0**——`intensity` 是命中密度而非证据量，
样本越小平均密度越高，方向正好反了。

### 仓位系数封顶 0.80，且在普涨末段下调

- 基准 `0.15 + 宽度 × 0.75`，封顶 **0.80**——任何未经回测的单一读数都不该建议满仓
- 若宽度 ≥ 85% **且** 板块 5 日中位涨幅 ≥ 6%，乘 0.75 并写明理由

对超短线来说，「83% 个股上涨、5 日已涨 7~10%」的那天是**你来晚了**，不是起涨点。
朴素的宽度映射会在情绪最热时给最大仓位，顺周期，恰好错在最贵的地方。

该系数始终是**建议值**，`--position-factor` 手工值优先，且两者都会打印出来供对照。

### 涨停池：指数与情绪可以反向

实测当日指数口径大盘 79.7 偏多，而**炸板率 52%、107 只炸板**——指数全线上涨与封板
意愿崩塌是同一天发生的两件事，此前链路里一个读数都看不到后者。

炸板率 `炸板 / (涨停 + 炸板)` 与最高连板进 `MarketOutlook`，上限 ±10 分。
服务端对周末/盘前日期返回最近交易日，所以**以响应里的 `qdate` 标注数据日期**，
而不是以请求日期。

**「连板高度」只认东财 `lbc`。** 同一行里的 `zttj` 是「N 天 M 板」统计窗口，
不是连板数（爱丽家居 `{'days':20,'ct':10}` + `lbc=9` = 20 天 10 板、当前连 9 板）。
读错字段会把统计窗口当高度，而这个数直接进情绪打分（≥5 加分、≤2 减分），一只
「10 天 5 板」的**首板**股会把减分翻成加分。

### 宽基指数：大盘方向读数是等权的，它看不见权重在杀

`MarketOutlook` 的每一个输入都是**等权**量——板块涨幅中位数、上涨家数占比、
站上 20 日均线占比。它回答「今天多少股票在涨」，结构上答不了「市值加权的指数
是涨是跌」，而这两件事经常同一天发生且差得很远。

2026-08-03 实测：加权上涨占比 76%、板块当日中位 +1.66%，系统给出**偏多 88.85／100**。
同一天——

| 指数 | 涨跌 | 指数 | 涨跌 |
|---|---|---|---|
| **科创50** | **-5.08%** | 上证指数 | -0.59% |
| 上证50 | -1.23% | 深证成指 | -0.96% |
| 沪深300 | -0.98% | 创业板指 | -1.24% |
| 中证500 | -1.06% | 中证1000 | +0.06% |

七成股票在涨，同时每一个宽基都在跌。两个读数都没算错，量的是不同的东西：
小票普涨、权重股杀跌。但只报前者的话，**一个权重崩塌的日子会拿到接近满分的方向
读数**——那是方向性盲区，不是噪声。

判据要求**两条同时成立**：等权宽度 ≥ 55% **且** 宽基中位数 ≤ -0.5%。少了第一条，
它就退化成「只要指数跌就告警」，与直接看指数无异。另外单个宽基跌破 -3% 会被单独
点名——板块级的崩塌会被其余七个指数的中位数平掉，而它通常就是当天资金在逃的主线。

**这一层不改 score、不改仓位系数。** 除了「新读数先进简报」这条通例，这里还有一条
更硬的：台账里已积的待兑现记录都是按现行公式打的，改公式会让新旧记录不可比——
而那批记录正是这套系统用来验证自己的全部样本。

**口径闸门是必需的而不是保险。** `hq.sinajs.cn` 给的是实时行情：盘前跑它返回上一个
交易日收盘，与等权那一路对得上；盘中跑它返回此刻点位，而板块动量仍是昨收。两边
不同日就只报事实、不下背离判断，日期未知同样不判断（把未知当可比，等于在调用方
忘了传日期时静默恢复成有 bug 的版本）。

## 6. 硬筛：筛选与打分分离

screen 直接踢出标的，不是扣分。当前只保留**可交易性、立案调查等致命公告与业绩
否决**；ST/退市名称与代码段不再作为候选过滤条件。

顺序：可交易性 → 致命公告 → 业绩否决。可交易性最便宜，先砍掉一批能让后面的公告
匹配少做无用功。

### 可交易性这一层此前是空的

候选此前只过名称/代码段与致命公告——一只 15 亿流通、日成交 3000 万的票和茅台在
筛选层面完全等价。**超短线的核心风险不是买错，是卖不掉**，而此前没有任何一层看
这件事。

现在按流通市值 ≥ 20 亿、日成交额 ≥ 0.8 亿过滤（阈值可传参）。实测一次盘前扫描剔除
**242 只**。取值偏松是刻意的：这一层的职责是**排除不可交易**，不是替使用者选票。

拿不到行情的标的**一律放行**并单独计数——用「没测到」当否决理由，等于让数据缺失
冒充风险判断。

### 公告风险否决用的是上一个有公告的自然日

盘前 08:30 跑时当日公告尚未披露，周末与节假日更是一条都没有（akshare 在空结果上抛
`KeyError: '代码'`，不是返回空表）。所以按自然日回退最多 5 天，实际用的日期会写进 note。
回溯 5 天还取不到就明说「本次没有公告风险否决」——**这一层静默消失比缺一条候选危险**。

新闻联播同理：盘前跑时今晚的联播还没播，硬取「今天」的结果是政策主线源每天早上静默
缺席（实测 2026-08-02 返回 0 条，而 07-31 有 15 条）。已改为回退最近一期有稿的日子。

## 7. 个股打分：整体口径是低吸，不是追涨

> **口径已扩展。** 低吸不再是唯一打法，也不再是默认打法——它是**退潮期**的打法。
> 选股现在先过 `strategy/regime.py`（今天允许哪类打法）与 `strategy/playbook.py`
> （这只票的趋势允许哪类打法），取交集后再逐条验入场判据；本节描述的打分只在
> **通过门槛之后**决定排序。完整设计见 [`SOLUTION.md`](SOLUTION.md) §二b。
>
> 下面「为什么转向低吸」那一段保留原样，因为它记录的是**上一轮**修掉的缺陷
> （权重把追高排在回踩前面）。**它没有修完**：门槛只挡掉 `none` 档，缩量仍是
> 权重——2026-08-03 实测 60 条建议里 52 条是**放量**回调。这一轮把缩量提成门槛。

### 为什么转向低吸

2026-08-02 实测：转向前这套打分选出的 30 只候选，按标的自身波动归一化后，
落在低吸理想窗口的 **0 只**、缩量的 **0/30**、19 只根本没有回调。
**它一直在选「正在涨的票」而不是「回调到位的票」。** 三处根因：

1. 威科夫 MARKUP（主升段）给 +12，而 LPS（回踩承接）只给 +4——权重把追高排在了回踩前面
2. 量能 `ratio >= 1.0` 一律 +8，缩量 `< 0.6` 反而 -5。**低吸最健康的形态恰恰是缩量回调**
   （回调放量意味着出货），符号是反的
3. 全部用阶跃函数，量比 1.02 和 3.99 同分，而 4.0 处有 13 分悬崖。项目在大盘层已经
   明确否定过阶跃，个股层没同步

现在的口径：**趋势还在（L1）× 回调到位（L2）× 缩量（回调质量）**，斜坡取代阶跃。

### 低吸画像按标的自身波动归一

档位单位是**这只票自己的日均真实波幅（ATR%）**，不是绝对百分比。用绝对百分比是错的，
2026-08-02 实测八只票一年日线：

```
长江电力（日振幅 1.82%）  ideal 只占  8% 的交易日，deep 一次都没到过
计算机题材（日振幅 6.23%） deep 占了 49% —— 一个本该意味着「趋势可能已破坏」
                          的档位成了它的常态，等于没有告警能力
```

归一化之后同一档位在不同波动的票上含义才一致：建行一年最大回撤 -11.47%、长电 -7.85%，
绝对值差 46%，除以各自日振幅后是 **4.4 与 4.3——几乎相同**。

档位 `0.8 / 2.0 / 4.0` 个日波幅，是拿八只票（五只红利蓝筹 + 计算机/传媒/茅台）的分布
标定出来的，目标是**每只票四个档位都填得满、且没有哪一档吞掉一半以上**。
这是先验校准，**不是收益验证**——哪一档真的更值得买，要等台账样本回答。

用**真实波幅（含跳空）**而不是简单的 `high-low`：A 股一字板和跳空开盘时，当日最高最低
可以贴在一起，只看日内区间会把「跳空 5%」读成「几乎没波动」。

### 量能的含义随所处阶段翻转

**回调途中要的是缩量**（放量下跌是出货），**没有回调时放量才是启动确认**。
同一个量比在两种状态下意义相反，所以量能项必须读 `dip.pullback_band` 才能定符号。

### 止损距离的上下限

实测 603508.SH 现价 23.16、最近支撑 23.15，止损距离 **0.04%**——A 股日内正常振幅
3–5%，这种止损是随机噪声，必然被打掉，而且它会让盈亏比算出 **172.84** 直接拿满分。

所以止损必须落在 **1 个日均波幅之外**（低于这个距离的不是止损，是在赌下一跳的方向），
且不超过 **3 个日波幅**（更远的「止损」已经保护不了任何东西，只会制造一个假的大分母）。
两头都用 ATR 而非固定百分比，理由和低吸档位一样。

### 两段打分：粗排 → 精排

个股新闻是**每标的一次 HTTP**，对几百只成分股全拉是几分钟的事，为了一个封顶 ±6 分的
读数不值得。所以：

```text
量价粗排  →  每板块取 per_sector × 3（全局封顶 40 只）  →  拉个股新闻与当日公告  →  精排
```

3 倍这个系数是拿封顶反推的：舆情最多改变 ±6 的原始分，映射到终分约 ±3.9。一只在本
板块排到 3 倍配额之外的票，需要越过的分差通常大于这个量。

**落在网外的票会计数并写进 note**——被截掉多少必须说出来，不能让「只看了前 N 只」
读起来像「全看过了」。

### 7b. 板块-个股联合因子

个股精排不再只看自身技术结构。`scoring/context.py` 为每只候选附加一份可序列化的
`StockFactorContext`，把「这只票是否和正在走强的板块同向」与「它自己有没有资金、
业绩或事件催化」分开计算：

| 因子 | 主要读数 | 处理方式 |
|---|---|---|
| 板块关系 | 板块评分、上涨宽度、板块资金相对强度 | 只对覆盖率可信的板块计分 |
| 个股相对强弱 | 个股 5 日收益 − 板块 5 日收益 | 跑赢板块才加分，避免板块涨而个股掉队 |
| 资金流 | 龙虎榜净买额或逐笔大单净额、相对当日候选归一值、相对成交额 | 单日绝对金额不直接跨标的比较 |
| 持续量价 | 放量/缩量方向、连续放量、20 日涨跌量比、放量跌破 | 放量上涨与放量下跌方向相反，天量滞涨扣分 |
| 业绩 | 新鲜、可盈利的预增/快报，预减/亏损风险 | 业绩风险仍由 `EarningsScreen` 否决，正面业绩只作二级加分 |
| 政策与事件 | 政策支持、涨价、中标、订单、回购、增持等标题关键词 | 只作为相关板块/个股的事件催化，不替代价格结构 |

技术分仍是主分，交叉因子只对技术上已经可比较的标的做二级排序；所有交叉因子合计
有上限，下跌趋势个股的正向上下文加分还会再次限额。这样可以避免一条政策新闻把破位
个股直接排到健康趋势个股之前。

`SelectedSymbol.to_row()` 和晨报台账会同时保存 `score_components` 与
`factor_context`。后续兑现统计可以按「板块关系」「资金流」「业绩」「催化」拆分，
而不是只看到一个无法归因的总分。上下文数据缺失时按未知处理，不把缺失当作利空。

### 个股舆情要先过相关性闸门

`news/relevance.py`。东财个股页面挂的文章有很大一部分是**行业综述、资金流榜单、
概念涨幅榜**——它们把几十只票列在正文里，于是每一只都「有新闻」。词典对整段文本
打分，于是**别家公司的利好利空被记到了这只票头上**。

2026-08-02 实测 14 只标的，过完 72 小时时效闸门后存活 11 条个股文档，
**标题点名本公司的 0 条**，全是综述与榜单。其中三条还产生了方向：

| 标的 | 读数 | 实际出处 |
|---|---|---|
| 601519 大智慧 | **-1.0（立案）** | 立案的是**湘财证券、国盛证券** |
| 600900 长江电力 | **+1.0（中标）** | 中标的是**天溯计量** |
| 601939 建设银行 | +1.0（新高） | 「工行、建行、交行创年内新高」榜单 |

大智慧那条一路走到了盘前简报和台账：`个股舆情 1 条偏空（-1.2，关键词：立案）`。
一家公司因为另外两家被立案而扣了分——不是权重问题，是**归属错了**。

判据是**标题**：综述与榜单的共同特征恰恰是「正文里有、标题里没有」，而真正的公司
新闻一定点名（「中国神华：定州三期机组全部建成投运」）。两条放宽：

- 标题用「公司」「控股股东」自指的（`控股股东拟大幅减持，公司收到问询函`）算数——
  这是公司公告最常见的写法，只认公司名会把减持与问询一起挡掉
- **拿不到证券简称时一律放行**：闸门挡的是「明确不相关」，不是「无法判断」

公告不过这道闸门——它本来就是按代码挂上来的，标题是「年报｜2025 年年度报告」这种
形式，不含公司名。

闸门只影响**打分**这条路。通读那一层（§0b）拿的是未经 72 小时截断的原始个股文档，
所以它仍然能说出「长江电力上半年发电量 1327.44 亿千瓦时，同比 +4.81%」这类两周前的
经营数据——**打分要的是「最近有没有事」，通读要的是「这只票是什么情况」，两者该看
的窗口本来就不同。**

## 8. 买卖点：候选集 + 裁决

`advice/engine.py` 编排三层：L1 读数由调用方传进来，L2 候选在 `candidates.py`
生成，L3 裁决由可选的 `adjudicate.py:LevelAdjudicator` 做。裁决层默认关闭
（`advise --adjudicate` 打开），关掉时走规则默认排序。架构与理由见
[`SOLUTION.md`](SOLUTION.md) §三。

### L2 候选价位的来源

| 候选类型 | 来源 | 何时可用 |
|---|---|---|
| 分时均价回踩 | `signals/intraday.py` VWAP | 盘中 |
| 当日低点 / 当日高点 | 分时序列 | 盘中 |
| 五档买盘墙 / 卖盘墙 | `signals/orderflow.py` | 盘中，五档可得时 |
| 日线支撑 / 压力 | `signals/daily_technical.py` 枢轴点 | 总是 |
| 回调 N 个日波幅 | `signals/dipbuy.py` 档位 | 总是 |
| 20 日高 / 60 日区间边界 | 日线序列 | 总是 |
| 缺口位 | 日线跳空 | 总是 |
| 真实涨停价 / 跌停价 | `adapters/snapshot.py`（腾讯，一次请求同时给五档） | 盘中 |

每个候选带 `basis`（人话出处）和 `evidence`（支撑它的 L1 读数）。规则给出
`default_rank`——**LLM 不可用时直接取 rank 0，链路照跑**。

`basis` 不只是给人看的：它进台账，让统计能按**依据类别**分组，回答「分时均价回踩
和五档买盘墙哪一类兑现率高」。只存价格的话，这两者在事后长得一模一样。

候选集另有距离护栏（买入位现价下方 6% 内、止损位 9% 内），但**它们不作用于规则
自己的默认值**——`advice.stop` 必须永远在自己的候选集里，否则闸门会把引擎自己
报的价判成越界。

### 五档能说什么、不能说什么

**能**：委比（买卖挂单量之比）、买卖盘厚度、挂单墙价位、spread。这些是**当下挂着的单**。

**不能**：委托流向、撤单率、大单意图。逐笔委托与撤单记录**任何档位都拿不到**，
集合竞价撮合量/未匹配量同理。

### 逐笔资金：能拿到成交明细，拿不到委托意图

腾讯 `stock.gtimg.cn/detail` 给的是**成交**逐笔（3 秒切片），带 B/S/M 方向，能算出
主动买占比、大单净额（阈值按当日 95 分位自适应）与尾盘 30 分钟净额。盘前链路会把它
挂到最终候选上，**只作旁证、不进打分也不进排序**——候选是按量价结构选出来的，
逐笔是选完之后多给的一眼，混进「为什么选它」会让它读起来像入选依据。

只对最终候选取数（约 23–28 只），不铺到粗排那几百只：一只票要翻约 67 页明细，
并发 4 路仍要两分多钟。`--no-trade-flow` 可关掉。

**两条口径必须一起说：**

1. **B/S 是腾讯按当时盘口的推断，不是交易所委托方向。** 真正的主动买卖按每笔成交
   撮合在买一还是卖一分，这里拿不到。
2. **翻页必须从第 0 页起。** 第 0 页装 09:25 集合竞价那一笔与开盘后约 8 分钟的成交；
   从第 1 页起会整段丢掉，实测缺口精确等于第 0 页——利欧股份 16.71 亿（全天
   **23.9%**）、中际旭创 30.86 亿（10.6%）、华能国际 0.36 亿（4.1%）。缺口对跳空与
   涨停的标的最大，而那恰好是超短最在意的那批。修复后逐笔合计与行情成交额的偏差
   从 4–24% 降到 **0.0%**。
   竞价那一笔本身没有主动方（集中撮合），但实测它对主动买占比的影响只有
   -0.7~+1.3pp（占全天主动成交 0.4%~2.9%），所以照单收下，不单独剔除。

**挂单墙的判定门槛是自缩放的。** 一开始只卡绝对金额（20 万元），2026-08-02 实测
茅台被误报：买一挂 5 手 = 68 万元，过了绝对门槛、占本方五档 56%，于是成了「买盘
墙」——而 68 万在一只当日成交 73.7 亿的票上什么都挡不住。现在再卡一道**相对当日
成交额**的比例（0.1%），它自己会随股价和活跃度缩放；成交额缺失时退回绝对门槛，
而不是放行。

**委比在涨跌停上是退化的。** 封死涨停时卖盘五档全空，委比恒等于 +1.0。这不是
「强到极致」的连续读数，是**封板**这个离散事实——混进任何按委比排序的地方，
涨停票会永远排第一位，而它恰恰是买不进的那只。所以 `is_degenerate` 单独标出。

**五档不进打分。** 它进的是三个地方，都不改变「这只票值不值得看」这个判断：

| 去处 | 用法 | 代码 |
|---|---|---|
| L2 候选集 | 买盘墙/卖盘墙成为**带出处的候选价位**，不改变排序 | `advice/candidates.py` |
| 盘中告警 | 要求下单动作的那几类附两行盘口旁证；封板时把「进入买入区间」降级成「买不进」 | `monitor/triggers.py:BOOK_RELEVANT` |
| 买卖点简报 | 同一句措辞（`OrderBookReading.describe`）印进简报，不另写一份 | `notify/render.py` |

**不进打分是刻意的**：它可以被撤、可以是假挂，而且只有五档。把它当选股依据，
等于把仓位押在别人随时能撤掉的挂单上。它只回答「这个动作此刻做不做得成、
那个价上现在有没有人挂着」——**「到位了」和「动得了」是两个问题，只有五档能
回答后一个。**

### 情景推演，不是概率　✅ 已建

```text
强势延续  放量站上当日高点 X   → 沿分时均价持有；跌回均价下方即结束该情景
均价震荡  在均价 Y 与高点 X 间  → 方向未定，只做回均价的低吸，不追高
转弱回落  有效跌破均价 Y 不收回 → 下看当日低点 Z；跌破则当日结构破坏
```

**没有概率、没有胜率、没有预期收益率**——没有拟合模型能支撑它们。系统只印
**会改变判断的价位**。

### 现价已是当日最高且上方无历史压力时

不给目标价，直接说明：「属于无参照的追高位置，只能用移动止损跟随」。
**印一个破折号会让人以为系统算不出来，说清楚才知道这是位置的性质。**

## 8b. 持仓的第五类卖点：浮盈回吐

上一句里的「移动止损」此前在监控层没有任何对应实现。而缺的正是这一类：

```text
成本 10.00  →  最高 11.00（+10%）  →  现价 10.40（+4%）

止损 9.00    没破        目标 12.00   没到
日线支撑 9.50 没破        持有 2 天    没到期
                                       ↓
                         四类卖出触发一条都不响，全程静默
```

这就是「坐电梯」的全过程，也是低吸最常见的亏法之一——它不产生亏损，只是把一笔
做对了的交易还回去，因而不会被任何一条以「亏」为判据的规则捕捉到。

### 判据：一个比例 + 一个自缩放的下限

**两条同时成立才触发**（`monitor/holdings.py:assess_giveback`）：

| 条件 | 值 | 单独用会怎样 |
|---|---|---|
| 回吐量 ≥ 1 个日均真实波幅 | `GIVEBACK_MIN_ATR` | 只用比例：日振幅 6% 的票天天在「回吐一半浮盈」，告警退化成噪声 |
| 且吐掉了峰值浮盈的一半以上 | `GIVEBACK_RATIO` | 只用绝对回撤：浮盈 30% 的持仓回落 1 个日波幅就报警，那是正常回踩 |

单位取标的自身 ATR 而不是固定百分比，理由与低吸档位（§7）和止损距离完全一样。

**峰值取「建仓以来」，不是「今天以来」。** 只用当日峰值会漏掉最常见的那一种：
昨天冲到 +10%，今天平开一路阴跌到 +4%——今天的峰值约等于开盘价，日内回撤很小，
于是移动止损整天不响，而这正是它该说话的那一天。种子从 `prime()` 已经取回的日线
里按建仓日截取，不额外发请求；盘中用**当日最高**而非最新价推进（两分钟一轮，中间
那根冲高的分钟线不会被看见，漏掉尖顶等于把回撤算小）。

三种情况一律**不判**而不是判「没有回吐」：没填成本价、算不出 ATR、峰值未知。
**把「不知道」当成「没事」，正是这条触发器要防的那类静默。** 同理，没填建仓日
就不播种——拿 240 天的历史最高当峰值会算出一个假的回撤幅度，少一个种子只是迟
一点，播一个错的种子会直接报错误的告警。

已知的一处高估：建仓当日的最高价可能出现在你买入**之前**，日线粒度分不出来。
不修是因为修不了——除非记录买入时刻，而那是账户数据，系统拿不到。

### 你手填的止损与目标

`plan_stop` 与 `plan_target` 优先于系统算出来的两个数：**手工填的是决定，系统算的
是建议。** 两者冲突时听你的，你可能知道系统不知道的事（别处的敞口、税、仓位安排）。

`plan_target` 此前在整条监控链路里**没有任何读取点**——`position open --target`
一直能填、一直存着，而对称位置上的 `plan_stop` 从一开始就是生效的。现在两者
（`effective_stop` / `effective_targets`）都接进了触发器，并且：

- **取代而不是合并**：你填了 11.60，系统那串目标阶梯就不再报了。在你已经做完
  决定的地方再塞两个提醒没有意义，这与 L3 裁决选中一个目标就只报那一个同源
- **不受开盘 15 分钟的钉死约束**：那道约束是为了等当日结构成型（§8 的 `armed`），
  而你填的是绝对价位，第一分钟摸到就该报
- 告警里标明「（你设定的）」——否则你会以为那个数是系统算出来的

盈亏比在你设了目标之后不再印：它是拿系统那串目标算的，与你的目标对不上号，
两个数并排印出来只会让人不知道该信哪个。

## 9. 出稿：LLM 不能引入任何数字

`writer/llm.py` 的闸门：生成文本中的每个数字，必须能追溯到输入 facts——逐字命中、
按书写精度四舍五入命中、或经 `万/亿/%` 换算命中。否则**整段丢弃，回退模板**。

已知会被误判的四类格式（都已放行，有测试覆盖）：

| 形式 | 例子 | 处理 |
|---|---|---|
| 补尾零 | facts `8.1` → 输出 `8.10` | 数值比对放行 |
| 长浮点四舍五入 | facts `12198154.379999977` → 输出 `12198154.38` | 按精度比对放行 |
| 千分位逗号 | 输出 `12,198,154.38` | 正则整体识别为一个数 |
| 单位换算 | facts `0.6667` → 输出 `67%` | 按后缀 scale 放行 |

买卖点裁决走**更严的闸门**：价格必须**恰好等于**某个 L2 候选或 L1 读数。近似匹配
在价位上是危险的——22.95 和 22.96 在文本比对里都能过，但那是两个不同的挂单价。
上表那四类宽容在这里一条都不适用。

更根本的一道在闸门之前：裁决器输出的是候选的 **key**，不是价格。它没有「写一个数」
的通道，只有「指一个已有的数」的通道。

**合规文本（纪律提醒、免责声明）在生成之后程序化追加，不交给模型。**
实测 Qwen 在被明确要求「保留全部风险提示」时，仍然会在概括过程中整段丢掉。

## 缓存

- 舆情按「交易日 + 源」缓存到 `<output-dir>/news_cache/`，TTL 1 小时
- 语料库持久化到 `~/.ashare-ds/news/corpus.sqlite3`，跨日累积
- 板块分类缓存到 `<output-dir>/sector_taxonomy_sw1.json`，带 `schema` 戳

缓存写入失败（磁盘满、类型不可序列化）只降速，不影响正确性——调用方此时已经拿到了
实时数据。

**四路源今天都进缓存。** 此前只有 akshare 那一路收 `NewsCache`，华尔街见闻、国内
官方、海外 RSS——恰好是最慢的三路——每次跑都重新打网络。代价不只是慢：盘前本来
就会跑好几次，快讯流一直在动，07:40 和 08:20 拿到的是**两批不同的文档**，板块舆情
分也是两个数，而简报上看不出来是哪一次。

缓存键按**单路**而不是按整源分：官方那三个栏目分属三个机构、各自会挂，整源一个键
会让任何一路超时把另外两路已经取回的内容一起作废。华尔街见闻只在**翻完整**的那次
写缓存——半截值得用，不值得记住，写进去会让后面每次重跑都只看到半截而且看不出来。

## 并发

舆情采集这一段此前是纯串行：四路源顺次跑，每路内部再顺次跑自己的 3–6 个 feed，
合计约 14 次 HTTP 往返首尾相接。官方与 RSS 各自 15 秒超时，最坏情况光超时就
90 秒——而这一段全是网络等待，彼此没有任何依赖。

`fanout.py:gather` 把这些收成一个口子——舆情五处，加上盘后龙虎榜席位的逐标的
取数（实测每只 0.45s，几十只候选串行要十几秒），所以它在**包根**而不是 `news/`
下，理由同 `numeric.py`：它约束的不是舆情，是一类取数形状。两条约定写死在那里：

- **保序**：结果按入参顺序返回，与完成顺序无关。下游 `retain_market_docs` 按来源
  发配额、同一来源内取列表前缀，拼接顺序一变，同一个盘前跑两次就是两批文档。
- **抛异常 = 这一路失败**，返回空结果 = 这一路今天没内容。两者在 note 里必须分得
  开，合并成一种会让「栏目正常但当天没更新」被报成不可用，而真正挂掉那天你就不会
  再多看一眼。异常本身一并交还，note 里那个类名是排查时唯一的线索。

## 健康探针

`news/` 四路源和 composite 都实现了 `health_check()`，口径对齐 `adapters/` 那十个：
逐路报，不报一个总的布尔值——四路覆盖面互补，少哪一路决定的是**少哪一块**。

`gov.cn/zhengce/`，实测 12 条真实政策条目。

## 已知边界

- 板块打分、个股打分、买卖点规则**全部未经回测**，只决定「今天先看哪里、哪个价位重要」
- 模型裁决（`advise --adjudicate`）同样未经验证——给它裁量权是因为写死的阈值同样
  没有依据，不是因为有证据说模型更好。它到底比规则默认排序好还是差，要等台账里
  `adjudication_edge` 攒够样本才能回答；在那之前它不参与任何加权
- `strong_count` 用涨幅 ≥ 9.5% 而非真实涨停判定，分不清 10% 与 20% 板。数据侧限制已解除，
  但换判据会让历史板块分数不可比，须连同阈值重标定一起做
- 龙虎榜是 T+1 数据，反映昨天的资金
- 浮盈回吐的两个阈值（1 个日波幅、吐掉一半）是**量级判断，不是拟合结果**。它们
  只保证「回吐超出这只票的日常波动」这件事在不同波动的标的上含义一致，不代表
  这里就是该走的点。真正的门槛要等台账里有足够多的持仓样本才能回答
- 时间止损的 8 天与 2% 同理，且用的是**自然日**而不是交易日
- 同花顺行业指数不参与打分，只并列呈现
- 可交易性阈值（流通 20 亿 / 成交额 0.8 亿）是行业惯例量级，不是拟合结果；
  它只排除「进出困难」，不代表通过的票流动性充足
- 两家的分钟线并不逐根相同，相对差最大 0.15%~0.31%——不要混用，也不要拿一条路的历史
  回测另一条路要跑的规则
- **免费档盘中时效仍未实测**
