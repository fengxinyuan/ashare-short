# 使用指南

按日常场景查找命令。安装步骤见 [项目首页](../README.md)，
文档分工见 [文档导航](README.md)，回归和验收见 [TESTING.md](TESTING.md)。

**要看哪几只由你说了算。** `advise` / `ask` / `chat`
只算你写在命令里的代码；省略时才回落到持仓表。持仓是系统唯一还替你记着的名单，
因为「该不该卖」这个问题必须有成本价、计划止损和持有天数才答得了。

## 模型开关

模板出稿与模型分析是独立开关。已有模型密钥时，部分命令会自动使用模型：

| 能力 | 默认行为与开关 |
|---|---|
| 简报写稿 | 默认 `--writer template`；`--writer auto` 在有密钥时使用模型，`--writer llm` 尝试模型写稿 |
| 问答与对话 | `ask` / `chat` 默认只读事实，`--llm` 开启模型回答 |
| 买卖点裁决 | `advise --adjudicate` 显式开启 |
| 多空辩论 | `morning` / `post-close-brief` / `daemon` 有密钥时默认启用，`--no-debate` 关闭；`advise` 需加 `--debate` |
| 舆情归因与通读 | `morning` / `daemon` 的盘前任务有密钥时默认启用，`--no-llm-news` 关闭 |

只运行盘前确定性分析可使用 `ashare-ds morning --no-llm-news --no-debate`。
模型不可用或输出校验失败时回退规则或模板，并记录原因。

## 场景到命令

| 你想做的事 | 推荐命令 | 说明 |
|---|---|---|
| 看大盘和板块趋势 | `ashare-ds morning` | 盘前主链路：舆情 → 大盘趋势 → 板块排序 → 当日候选 |
| 复看最近一次板块分析 | `ashare-ds sector-analysis` | 只读 `morning` 的落盘事实，不重复访问行情源 |
| 生成板块情景预测 | `ashare-ds sector-forecast` | 主题重叠去重，并列出09:35后的确认/失效条件 |
| 盘中验证板块预测 | `ashare-ds sector-confirmation` | 读取 `monitor` 已落盘截面，返回已确认/部分确认/已否决 |
| 检查价格信号是否有效 | `ashare-ds sector-backtest` | 本地历史、固定基线、时间序列后30%留出验证 |
| 问单只股票怎么走 | `ashare-ds ask "600519 现在趋势和买点怎么样"` | 单入口问答，按时段自动装上下文 |
| 看单只股票的结构、量能和买卖点 | `ashare-ds advise 600519.SH` | 结合日线、分时、成交量、盘口生成买卖点 |
| 做全市场参数化选股 | `ashare-ds strategy-screen --profile all` | 比较多种形态，输出确定性候选事实 |
| 下午找可观察的股票 | `ashare-ds strategy-screen --profile all` → `ashare-ds advise <代码>` | 先看筛选截止日，再逐只核对当日价位；筛选排名本身不是买入信号 |
| 盯持仓与板块异动 | `ashare-ds monitor --feishu` | 不传代码就盯持仓；首轮补报已成立的买卖点，后续按跃迁提醒；**板块监控与名单无关，空仓也有话说** |
| 导出统一事实包 | `ashare-ds facts --output facts.json` | 给 Codex / Claude 的结构化输入，不调模型 |
| 维护历史缓存 | `ashare-ds history-refresh` | 回填同花顺板块指数与海外指数日线，供外盘映射历史基准率读取 |
| 多轮追问同一份事实 | `ashare-ds chat` | 默认读取事实；需要模型回答时显式加 `--llm` |
| 让模型在候选价里做取舍 | `ashare-ds advise --adjudicate 600519.SH` | 用 LLM 做买卖点裁决，可弃权 |
| 盘后生成次日执行卡 | `ashare-ds post-close-brief --symbols 600519.SH` | 基于实际行情日期生成执行卡、每日复盘与次日复查项 |
| 离线回放当天过程 | `ashare-ds review --daily` | 串联计划版本、监控、新闻与价位证据，说明缺失的过程记录 |
| 核对到期建议并查看规则反馈 | `ashare-ds review` | 完整窗口核对、同日对照、覆盖不足与复查原因 |

## 推荐用法

### 盘前先看趋势

```bash
ashare-ds morning
ashare-ds morning --explain   # 同时打印筛选漏斗
ashare-ds morning --top-sectors 5 --top-concepts 3  # 行业、概念分开取名额
ashare-ds sector-analysis     # 复看最近一次每日板块分析
ashare-ds sector-analysis --format text      # markdown/text 等价
ashare-ds sector-analysis --format json --output sector-analysis.json
ashare-ds sector-forecast    # 情景排序；评分不是上涨概率
ashare-ds monitor --once     # 09:35后采集一轮盘中板块截面
ashare-ds sector-confirmation
ashare-ds sector-backtest --output briefs/sector_backtest_latest.json
```

这一步关注的是大盘、板块和当日候选，不是逐票追问。
运行时会先打印几行阶段进度，再输出完整晨报。
行业和概念默认并排计算、各自排名；概念不会参与全市场宽度，避免一只股票因多个
题材标签被重复计权。只想看行业时使用 `--no-concepts`。

`sector-analysis` 是只读查看入口：它读取 `briefs/morning_latest.json`，汇总主攻板块、
行业指数位置、价格轮动、成交额迁移和情绪旁证，不会重新跑 `morning`，也不会消耗行情源配额。
如果文件不存在，先运行一次 `ashare-ds morning`。报告顶部把**报告日期**（`morning` 运行日）
和**行情截止**（用到的最后一根日线）分开印，交易日滞后按后者算：周日跑的报告，前者是周日、
后者是上周五，周一盘前读到的是「上一交易日」这个正常状态；休市日可以显示”最近交易日”，
报告日期缺失或晚于分析日期则标记降级，不能当成实时判断。

`sector-forecast` 把高度重叠的行业和概念折成主题簇，避免”芯片、电子、存储”被误读成
三条独立证据。输出明确区分预测目标日与信息截止日：目标日按交易日历取，休市日跑出来的
预测对的是下一个交易日；并要求盘中广度、相对收益和成交额
共同确认。`sector-backtest` 比较5日动量、超跌反转、趋势回调、强弱加速四个不调参基线；
它的滚动3/5日窗口会重叠，因此只能用于识别明显失效，不能直接解释为独立胜率样本。
`sector-confirmation` 不重写盘前判断，只附加盘中证据；广度低于45%，或放量但超额转负，
会明确标记为“已否决”。没有09:35后的有效截面时只返回“等待数据”，不会猜测结果。
CLI 每次运行会按“交易日 + 主题”去重写入确认台账，并保留状态变化序列；MCP 与
`get_facts` 仍然完全只读，不会因为模型查看数据而修改台账。

`--max-constituents` 只用于快速诊断链路，会在 summary 和 `morning_latest.json` 中标记
`diagnostic_mode=true`。诊断模式下的覆盖率、主攻板块和候选都不能视为正式全量结论。

同一已完成交易日的板块动量日线默认复用本地缓存；需要核对行情源修订时使用
`ashare-ds morning --force-refresh-daily`。盘中运行 `morning` 而板块日线仍停在上一
交易日时，报告会标记 `execution_ready=false`，不写入可执行建议台账。候选同时列出
完整日线的结构参考收盘价和盘中全市场快照价及其时间；实时快照不替代尚未形成的完整
日线，也不自动确认买点。午休是非连续交易时段，分钟线暂停更新不等于数据源故障。
全市场扫描完全成功后，其截面最多复用 5 分钟；午休转为下午连续交易时自动失效。
分页请求失败或中间页异常为空时，截面标记为不完整，不作为可执行判断的完整输入。
行情源全页失败、或显式关闭全市场扫描时，可交易性过滤失去输入，报告也会标为
`execution_ready=false`、执行仓位为 0。`suggested_position_factor` 仍保留为历史
研究读数，不是当前可执行仓位。

晨报里有四节是**只出读数、不进打分**的（打分权重未经回测，这几层连权重都还没有）：

| 小节 | 回答什么 | 关掉 |
|---|---|---|
| 大盘怎么读里的宽基那行 | 市值加权的指数在涨还是跌，与等权宽度是否背离 | `--no-broad-index` |
| 轮动到哪了 | 月度趋势有没有反转（长窗口）、这周资金有没有掉头（等长窗口） | 随 `--no-sector-index` 的序列走 |
| 成交额挪到哪了 | 钱挪去了哪个板块，以及那是在买还是在跑；全场总量是涨是缩 | 同上 |
| 候选行的「昨日逐笔」 | 上一交易日的主动买占比、大单净额、尾盘净额 | `--no-trade-flow`（省约 2 分钟） |

**赶时间就加 `--no-trade-flow`**——它是盘前链路里最慢的一段，一只候选要翻约 67 页
成交明细。其余几层都是秒级或纯磁盘读。

### 主题雷达与社媒线索

`morning` 的 facts 会附带主题雷达。内置范围包括 AI 高速互连、PCB 关键材料、光芯片、
先进封装、战略金属、铜、电网储能、机器人、低空商业航天、核电、锂电、创新药/CRO、
消费家电更新和航运。它只把主题标记为“社媒线索”“事件预警”或“价格确认观察”，不改变
板块分数，也不生成买卖指令。

可以通过合规渠道导入小红书、抖音等平台的每日热点快照，系统不会绕过登录、验证码或
平台反爬机制。设置 `ASHARE_DS_SOCIAL_HEAT_PATH=/data/social-heat` 后，目录中当天的
`*YYYYMMDD*.json` 文件会在下一次 `morning` 被读取：

```json
{
  "platform": "xiaohongshu",
  "items": [
    {
      "title": "电子布供需观察",
      "summary": "可选，保留原始摘要",
      "published_at": "2026-08-07 18:00",
      "url": "https://approved-source.example/topic"
    }
  ]
}
```

社媒数据只用于发现线索；要升级为“价格确认观察”，仍需财经/官方消息与关联板块的趋势或
广度共同确认。新题材可通过 `ASHARE_DS_THEME_CATALOG_PATH=/data/themes.json` 增加：每项包含
`name`、`terms`、`sectors`、`transmission`、`invalidation`，可选 `exclude`（含这些词的消息
不算本主题证据——「无人机袭击」命中「无人机」却不是低空经济的线索），格式为 JSON 数组或
带 `themes` 数组的对象。

### 盘中盯持仓

```bash
ashare-ds position open 600519.SH --cost 1350.6 --stop 1330 --target 1430
ashare-ds position list
ashare-ds monitor --once
ashare-ds monitor --feishu

ashare-ds monitor --symbols 600519.SH 000001.SZ   # 只盯这两只，已持仓的仍按卖点口径
ashare-ds position close 600519.SH                # 卖了就删掉，历史留在台账里
```

`monitor --once` 每次写入 `briefs/monitor_status_latest.json`，记录最新分钟线时效、
告警数和板块截面；`alerts-日期.md` 是当天已发告警的记录，取数恢复后不会删除旧告警。

不传 `--symbols` 就盯持仓表里的票，每轮重读——盘中 `position open` 登记的新仓位
立刻被盯上，不用重启监控。持仓按卖点口径（止损/目标/结构破坏/时间止损/浮盈回吐），
未持仓的显式代码按买点观察。`--symbols` 只限定名单，仍会读取这些代码的持仓资料。
启动时已经成立的可执行买卖点
会补报一次，普通均价震荡不补报，避免刷屏。
突破提醒还要求现价不高于计划买入上沿的 103%；过远的日内高点不再当成新的
ACTION 买点。止损幅度与盈亏比按告警当刻现价显示，而不是用计划买入下沿冒充
当前可执行价格。

对已登记的代码再次运行 `position open` 会更新成本价；未传入的股数、建仓日、止损、
目标和备注会保留。需要调整建仓日或股数时显式传 `--opened-on`、`--shares`。
成本价、止损价、目标价必须是正的有限数字，股数必须是正整数；输入或写入失败不会改动原持仓。
修改会在文件锁内读取最新持仓，避免两个命令互相覆盖。`position close` 接受简写与标准代码，
归一化后去重；`closed` 和 `not_found` 都返回标准代码。

`position list` 除了逐笔明细，还给一份**组合层读数**（`portfolio` 字段）：每只占
多少、按行业与题材归并之后最大的一块有多大、哪几笔还没有计划止损。三只票分属三个
代码但挂在同一个题材上时，它不是三笔分散的仓位，是一笔重仓——这句话逐行看是看不
出来的。归并用本地缓存的标的元数据，不打网络；缓存为空时只有权重，没有归并，并
明确写出「没有分类」而不是给一张空表。

它**不报总仓位**：仓位上限说的是占账户总资金的比例，而这套系统只知道持仓表，不
知道你账户里还有多少钱。

### 盘中盯板块趋势

`monitor` 默认**同时**在跑板块监控，不用额外开：每 5 轮（约 10 分钟）做一次全市场
扫描，按同花顺行业和概念各归并一次，只在板块**状态发生变化**时推送。
行业只有一层，当前约 90 个；概念随数据源更新，经过非主题标签与规模筛选，数量不固定。

```bash
ashare-ds monitor --feishu                  # 个股 + 板块，两条链路
ashare-ds monitor --no-sectors              # 只要个股告警
ashare-ds monitor --no-news                 # 不拉当日公告，关闭突发风险公告告警
ashare-ds monitor --sector-every 10         # 板块看得稀一点（约 20 分钟一次）
ashare-ds monitor --once                    # 运行一轮；空持仓且未给代码时只跑板块
```

推送的七种板块变化：

| 触发 | 级别 | 说的是 |
|---|---|---|
| 开盘板块概览 | WARN | 此刻钱在哪（每天一条基线，不是跃迁） |
| 排名跃升 | ACTION | 资金正在往这里挪：较开盘首轮升 8 名以上且进了前 15 |
| 转强 | ACTION | 超额 ≥ 1% **且**上涨占比 ≥ 70%——只有涨幅可能是两只权重股拉的 |
| 涨停潮 | ACTION | 涨停家数从 ≤1 跳到 ≥3 |
| 成交额虹吸 | WARN | 占全场成交额较开盘放大 1.5 倍且绝对占比过 2% |
| 领涨板块退潮 | WARN | **手上的该不该走**：曾进前 10 且从「强」转弱 |
| 排名下滑 | INFO | 默认不推 |

两条要点：

- **排的是超额涨幅**（板块中位 − 全市场中位），不是绝对涨幅。普涨日里 +1.5% 是落后，
  阴跌日里 −0.5% 是强势，绝对涨幅排出来的榜没有信息。
- **一个板块一轮只推一条。** 四条规则同时命中时折成一条，其余进正文——四条一模一样的
  推送正是通道被静音的原因。额度**按小时分配**（每小时 4 条、全天 20 条），所以早盘的
  噪声吃不掉下午的份；超了写进 notes 而不是静默丢掉。

你盯着的票（持仓，或本轮 `--symbols` 传进来的）落在哪个板块里会直接标在告警上
（`⚑ 你盯着的票在这个板块里`），
并且这类告警排在最前——同一条「退潮」，发生在你有仓位的方向上紧急程度高一个量级。

### 全天调度与实例占用

```bash
ashare-ds daemon --dry-run                 # 查看任务时间与开关
ashare-ds daemon                           # 按交易日历运行全天任务
```

同一 `ASHARE_DS_HOME` 下，`monitor` 与 `daemon` 分别只允许一个实例；`monitor --once`
也遵守这条限制。重复启动会立即提示已有实例占用，停止旧实例或使用独立状态目录后再运行。
daemon 进入监控任务时也要取得 monitor 的运行权。任务失败或进程退出后可重新启动。

### 单票做股价分析

```bash
ashare-ds advise 600519.SH 000001.SZ
ashare-ds advise --adjudicate 600519.SH
```

这里会看日线结构、分时位置、成交量、量比、五档盘口和风险过滤。
已在持仓表登记的代码会多出「持仓」与「回本」两行：成本、浮盈、持有天数，以及回本价与
压力位的关系；登记了 `--stop` / `--target` 时它们替换系统价位并重算盈亏比，风险栏标明「你设定的」。
`--adjudicate` 会让模型在规则候选里做取舍，但不会让它编新价位。
`ask` 也能直接问单票，问题里写出代码会自动识别。
命令末尾的 `analyzed` 是已分析只数，`with_levels`（兼容字段 `advised`）只是算出价位的只数；
`risk_qualified_plans` 表示打法与风险收益通过初筛，**仍不是当前价格已经触发买点**。
突破价未到时应等待上破，不能把它误读成回踩带失守。

### 用对话追问

```bash
ashare-ds chat
```

在对话里可以直接问：

- `600519 现在趋势怎么样`
- `今天量能放大但没突破，该怎么理解`
- `持仓里谁先触发止损`
- `如果明天低开，哪个价位先看`

`chat` 适合连续追问同一份事实；`ask` 适合一次性问清楚。
要问新票，先 `/add <代码>` 把它放进上下文；`/positions` 载入持仓，`/help` 列出全部命令。

### 参数化策略筛选

筛选使用同花顺分类和 TickFlow 日线数据。默认只看沪深主板、价格 3 到 60 元、当日成交额至少 5 亿元，并纳入名称含 ST/退的标的；系统会在候选 `warnings` 中标明风险：

```bash
ashare-ds strategy-screen --profile high-elasticity --price-max 60 --limit 30
ashare-ds strategy-screen --profile balanced-pullback --price-min 5 --price-max 30 --min-amount-yi 3
ashare-ds strategy-screen --profile all --price-max 40 --min-amount-yi 3 --limit 50
```

`--profile all` 会一次运行三种策略，输出各自的诊断漏斗、跨策略多样化短名单和重复命中标的；由于策略位置区间可能互斥，不再把空交集误读成“没有机会”。需要扩大范围时使用 `--all-a`；需要排除 ST/退市风险标的时显式使用 `--exclude-st`。除了价格和成交额，还可用 `--min-history-bars`、`--min-atr-pct`、`--max-atr-pct`、`--min-range-position`、`--max-range-position`、`--min-pullback-pct`、`--max-pullback-pct`、`--min-volume-ratio`、`--max-volume-ratio` 等参数细化策略。结果写入 `briefs/strategy_screen_latest.json`，并自动进入 `ask` / `facts` 上下文。这里的形态标签不是收益预测，不能据此承诺每日 1% 收益。

`as_of` 是筛选运行日，`trade_date` / `signal_date` 才是所用日线的日期。盘中运行也可能只取得上一交易日的日线；这时短名单是历史形态观察，不是今日买点。盘前观察池剔除按最小有效止损重算后盈亏比不足 0.8 的标的；0.8–1.5 的标的会明确标为“仅供观察”。盘中 `advise` 仍要求盈亏比至少 1.5，并重新核对当日价位、目标和可交易性。突破触发价不能同时作为兑现目标。

`advise` 的计划盈亏比按买入区间上沿和最近目标核算，监控提醒再按当刻现价复核。
例如买入区间 10.00–10.40、止损 9.80、目标 10.80，计划盈亏比为 0.67，不能用下沿
成交时的 4.00 代表整个区间。显示值保留两位，执行门槛使用未舍入值；费用、滑点和
隔夜跳空尚未计入。模型改选价位、监控锁定止损与目标后，会同步重算比值及风险提示。
多策略筛选在同一轮复用日线指标，下一轮重新计算，候选条件与各策略排序口径不变。


`--deep` 会拆成计划、逐步论证、决策卡和价位轴，适合要一个结构化答案的时候用。

### 让 Codex / Claude 先看 facts

```bash

```

用 `--sections` 选择需要的分区：

```bash
ashare-ds facts --sections 盘前主链路 持仓
```

需要在终端快速查看时使用文本模式；默认是精简摘要，完整文本加 `--full`。JSON 模式
仍然保留完整结构，并在顶层提供 `data_status`（`正常` / `降级` / `未记录`）。

```bash
ashare-ds facts --format text --no-live
ashare-ds facts --format text --full --no-live
```

省略的分区名称写入 `notes`。MCP 的 `get_facts` 使用相同参数与实现。
`facts --phase pre_open|intraday|post_close|off_hours` 可固定装配时段；
省略时按北京时间与交易日历自动判断。

先检查 `数据健康` 中各块的数据日期、交易日间隔与状态，再使用排序和价位。

```bash

```

这条命令只填样本：同花顺板块指数 + 海外指数日线。`preopen-research` 会只读这些

`sector_base_rates`，但它不生成预测、不改变板块评分。

### 盘后复盘与次日交接

```bash
ashare-ds post-close-brief --symbols 600519.SH
ashare-ds review --daily
ashare-ds review --daily 2026-08-03
ashare-ds pre-open-brief
```

`post-close-brief` 生成个股执行卡时自动运行每日复盘；`review --daily` 可单独补跑，
省略日期表示今天。每日复盘只读本地计划、台账、监控事件、板块截面与新闻语料，
不拉取实时行情。所有步骤使用同一 `--output-dir`，默认 `briefs`。
执行卡里过了打法门槛的候选同时落台账（来源 `post_close`），由 `review` 按 T+1..T+5 核对；
它们进总体与分组统计，不进入选/对照差值，因为这些票是人手点名的，没走过板块排序。

晨报在 `plans/YYYY-MM-DD.jsonl` 追加计划版本；相邻内容相同的重跑复用原版本和时点，
变更后改回旧方案也会留下一版。监控过程另存于状态目录的 `events/YYYY-MM-DD.jsonl`。
复盘按当时可用的计划关联事件，排除截止时点之后的证据；没有可核验的原始盘前计划时，
旧晨报只用于事后对照。报告区分条件提示、采样价位触及和用户实际成交，缺失记录不会补猜。
事件关联表示当时已有的计划背景，不表示监控重新加载或执行了该版本；监控仍依据实时结构和登记持仓。
新闻分类可能事后补录，仅用于检索和价格对照，不能倒推当时已知的标签。

结果写入 `daily-reviews/YYYY-MM-DD.json` 和同名 Markdown，最新索引为
`daily_review_latest.json`；更早日期或更早截止时点的回放不会覆盖已有的较新结果。
`pre-open-brief` 默认读 `--output-dir`（默认 `briefs`）下的 `post_close_latest.json`，
也可用 `--payload` 指定一份；它读取执行卡附带的同日复查项，未附带时查找同日复盘档案。
`ask` / `facts` 也会带入最近复盘摘要。近 20 个归档日期的汇总只说明过程覆盖，不能解释为胜率。

`morning`、`advise` 和 `post-close-brief` 支持 `--strategy-version`，默认 `rule-v2`。
v2 标记买入区间上沿风险口径及缺失情绪读数处理的调整；历史 `rule-v1` 台账保留原标签。
该参数标记本次规则版本，不会自动切换算法或调整参数。新台账保留判断编号、记录时点、
修订与前驱；同日改判追加记录，普通核对不改写已经保存的兑现结果。

### 盘后查看规则反馈

```bash
ashare-ds review
ashare-ds review --horizon 5
```

`review` 核对到期台账，并展示以下结果：

- 样本覆盖：记录数、交易日数、已知情绪周期分别距 200 条 / 60 日 / 3 类的门槛还有多少。
- 筛选价值与否决代价：匹配交易日、来源与策略版本，先算各可比组中位数之差，归并到当日后按日等权。
  期末收益与 MFE 还需匹配实际兑现窗口，避免把一日和五日结果混在一起；缺失版本单独配对，不推断为当前版本。
  模型与规则的裁决比较也使用这一口径，弃权与风控否决不进入裁决对照组。
- 规则观察与复查：给出“待补数据 / 继续观察 / 建议复查 / 保留观察”以及对应样本证据。
  两组各至少 20 条有效次日数据、覆盖至少 5 个共同交易日后，才提示复查反向效果；不自动调参。
- 执行口径：按日线模拟价格触发，区分可模拟、成交、已平仓、未平仓估值和待补数据。
  回踩开盘跌穿区间下沿则取消；突破须触及触发价，跳空越过买入上限不追。弃权、风控否决、
  无有效打法或价位不完整的记录只核对后续价格，不模拟买入。仅有有效止损和目标的盘前、盘后日线候选，
  可使用开盘价研究情景；这不代表已经通过盘中的止跌、放量及排队确认。
- 平仓与估值：成交当日不可卖；跳空退出按开盘价；单一涨跌价在缺少盘口时按可能封板保守处理。
  被阻碍的止损继续等待可卖时点；T+1 或期末仍封板的仓位只记浮动估值，不计已实现收益、胜率或
  研究曲线。必要开盘价缺失时保留待核对，补齐日线后可重试；开盘卖出后的涨跌不计入持仓 MFE/MAE。
- 成本与研究曲线：已平仓毛收益另外扣减固定 0.10% 往返成本作情景估计，未计最低佣金和滑点。
  按成交日归集多日持有期收益后复乘的曲线是研究读数；持有期可能重叠，未模拟资金占用、仓位上限
  或逐日盯市，不能作为真实账户净值及最大回撤。入选与对照的执行收益还需匹配模拟版本。
- 复查项共四条：筛选排序与风险否决读次日收盘差，执行口径排序读已实现收益差，分数分档也使用
  逐日配对的次日差，不直接相减总体中位数。优先比较最高与最低可比档，选档只看有效覆盖、不看收益正负，
  报告显示实际比较的档位和共同日期数；0–60 的有效分数也纳入。任一反向只提示复查，不改规则。
- 评分分项拆解：每个分项按同日、同来源、同策略版本的中位数划分高值组与低值组，同分留在一组。
  中位数等于最大值时，较低值划为低值组；同组取值全相同的记录不参加比较，不让不同日期的评分水平改变切点。
  次日、期末、已实现收益各自显示高/低组有效样本数、共同日期及覆盖不足标记。判读只采用覆盖达标的
  次日或执行指标，并注明“仅次日 / 仅执行 / 次日与执行”；少量极端成交不会左右整项结论及复查顺序。
  分项通过判断编号从建议接回兑现，历史记录无需重写；`review` 在结算后使用同一次台账读取关联两者。
  分组反向是关联观察，可能受其他因子和行业暴露影响，不证明单项因果；20 条 / 5 日只是人工复查门槛，
  不表示统计显著，也不作为自动调权依据。
- 盈亏比与止损距离分桶：按计划发出时的盈亏比（1.0 / 1.5 / 2.5 切点）和止损距离（日波幅倍数）
  分别列兑现率，是“1.5 的执行门槛该不该收紧”“3 个日波幅的止损上限该不该压低”的实证位。

盘前晨报的参考价是上一交易日收盘，窗口最早从计划日开始，旧参考日不能制造建议发出前的成交。
分时建议保存原始开盘价，通过同日开盘价对齐日线复权尺度，避免把盘中参考价替换成之后的收盘价；
日线模拟仅使用建议日之后的完整交易日，不能据此还原当日盘中交易。
旧记录缺少参考日期时，先匹配参考价与当日、前一日收盘，否则回退至建议日。
旧分时记录未保存原始开盘价时维持收盘近似口径；`anchor_date` 和 `execution.price_alignment`
分别说明锚定日期和价格口径。新模拟标记 `execution.model_version=daily-ohlc-v2`，已有兑现记录不改写；
旧记录中无法确认是否卖出的锁仓样本不进入已实现收益比较。

日线接口失败时，已有缓存可供复盘和盘后简报降级使用。输出会注明缓存截止日期和数据边界；
盘后简报按实际行情日期命名，不能把旧数据当成今日收盘结果。

核对窗口必须为正整数。每个交易日只保留一根日线，按北京时间确定日期，忽略晚于核对日的行情。
必须有建议日的有效收盘价和完整的后续窗口；停牌、残缺行情不会因为过去了足够多自然日而被提前结算。
窗口内价格无效时保留整条建议待核对，补齐后重跑即可；不会跳过坏日线，把更晚的一日当成次日。

报告说明按原因汇总待核对记录，结构化结果的 `deferred` 列出代码、日期、来源与原因。
默认待核对范围为最近 60 个自然日，统计读取最近一年台账；更早记录仍保留在本地 JSONL 中。
同一建议目前只结算一次，`--horizon` 是未结算记录的窗口，不会重算已有结果。
总体统计对带判断编号的新记录只取每只股票、每日、每个来源的首次判断；策略版本分组
各取该版本的首次判断，避免同日反复运行扩大样本数。旧台账保持原统计口径，缺少版本时标为未记录。

### 维护交易日历

```bash
ashare-ds calendar-refresh --year 2026
```

刷新仅更新源数据首末交易日之间、且属于目标年份的日期。缺少目标年份或存在无效日期时保留旧表；

## 常见结果与处理

| 输出 | 含义与下一步 |
|---|---|
| 没有待核对的建议 | 当前范围没有到期且未结算的记录；不是接口失败 |
| 兑现窗口未满 | 等待后续日线；先检查缓存截止日期 |
| 建议日收盘缺失或无效 | 需要补齐建议当日数据，不能用更早收盘价替代 |
| 兑现窗口价格无效 | 检查相关标的日线，修复后再次核对；其他正常标的可继续 |
| 时点未知 / 未来数据 | 查事实包的日期和时区，重新采集；不要将该块当成当前证据 |
| 参数错误，退出码 2 | 使用子命令 `--help` 查看参数；持仓校验失败不会改写原记录 |
| 文件操作失败，退出码 2 | 根据错误路径检查目录权限与磁盘空间，修复后重试 |
| 告警或调度状态落盘失败 | 当前进程继续保留告警和执行进度；修复存储故障，重启后可能重复提醒或执行 |

## 约束

- 系统不下单、不撤单、不接管账户。
- 价格、趋势、成交量和买卖点都必须带数据时点。
- LLM 只负责组织语言和取舍，数字还是来自规则层；系统不生成或执行订单。
