# 同类项目机制对照：daily_stock_analysis（DSA）

> 对照对象：`/root/daily_stock_analysis-main`（ZhuLinsen/daily_stock_analysis，MIT）。
> 30 万行、覆盖 A股/港股/美股/日韩台，Web 工作台 + Bot + FastAPI + Docker + Actions，
> 每日给自选股产出一份「决策仪表盘」推到微信/飞书/TG/Discord/Slack/邮件。
>
> 许可证是 MIT，**代码可以借**。但本文仍然只做机制对照——两边的定位差得足够远，
> 直接搬运的收益低于按同一个道理在本仓库重写一遍。本轮实装的三处都是重写，
> 不含拷贝代码。

## 1. 定位差异（决定了什么能借）

| | DSA | 本系统 |
|---|---|---|
| 任务 | **自选股每日报告**：给定名单，逐只产出评分、结论、风险、催化 | **全市场日周期**：盘前筛选 → 盘中监控 → 盘后台账 |
| 周期 | 通用，日频报告 | 超短（隔夜至 3 日） |
| 谁产出数字 | **LLM**：报告的评分、结论、买卖点位由模型读数据后写出 | **确定性层**；模型只能引用与取舍，越界整段丢弃 |
| 部署面 | Web/Bot/API/Docker/Actions/桌面端 | 一个 CLI + 一个 MCP server |
| 用户 | 公开项目，成千上万个部署 | **一个人**（作者自己做超短） |

这两条差异合起来解释了本文后面所有的取舍：DSA 的大部分工程量花在**多市场覆盖、
多渠道触达和多用户配置**上，而这三样在本系统里的正确值都是「不做」。剩下能借的
是它在**同一个问题上比本系统想得更细**的那几处。

---

## 2. 三处值得借的，本轮已实装

### 2.1 模型输出的护栏不能只查数字 ★

**DSA 的做法**：`src/daily_market_context_guardrail.py` 与 `src/phase_decision_guardrail.py`
两个模块，专门在拿到模型输出之后做两件事——

- 大盘上下文偏保守时，把「立即买入」这类激进措辞**降级**成观望，并给
  `confidence_level` 封顶；
- 时段不对时（盘前、非交易时段）拦下「立即买入 / 马上卖出」这类即时动作指令，
  因为那一刻根本没有可执行的对象。

两个模块都带**否定词回看**（`_NEGATION_LOOKBACK = 16`），避免把「不建议追高」
判成主张追高。

**本系统当时的状态**：闸门只有一道，查数字（`writer/llm.py:unverified_numbers`，
本轮已搬进 `factcheck.py`）。
而六份提示词里另外写着两类约束，**一条都没有人查**：

| 提示词里写的 | 写在哪 | 谁在查 |
|---|---|---|
| 不得给概率 / 胜率 / 预期收益率 | writer、ask、chat、debate、adjudicate 五处 | 没有人 |
| 不得改变已经算好的结论 | `writer/llm.py` 第 1 条 | 没有人 |

这正是本仓库反复用审计脚本得出过的同一个结论：**一条写在文档里、没人执行的口径，
和没有这条口径是一回事**。提示词不该是例外——尤其「不产出概率/胜率/预期收益率」
是 `DECISIONS.md` §七 的固化决定，还同时印在给用户看的纪律段里。

**本轮实装**（`factcheck.py:prose_violations` + `OutputGuard`）：

- **措辞**：`CLAIM_MARKERS` 命中且不是被否定着说的 → 越界。
- **立场**：确定性层给出的仓位上限为 0（冰点档：不出手）时，任何买入措辞都是在
  改结论；上限已经算出来时，「满仓 / 重仓 / 梭哈」同样是。
- **时段**：不是盘中时，「立即买入」这类即时动作没有可执行的对象。

接线点是全部六个出文字的地方：简报改写、`ask`（含分步深挖）、`chat`、多空辩论、
舆情通读、价位裁决。六处走同一个入口 `factcheck.py:review_output`——**这一条本身
也有一道结构用例**（`tests/test_output_gate.py`），`factcheck.py` 之外任何直接调用
子闸门的地方都会让它变红，否则下一个调用点仍然可以只查一件。

**两处和 DSA 不一样，是有意的**：

1. **越界整段丢弃，不做降级改写。** DSA 会把 `decision_type` 从 buy 改成 hold、
   把措辞替换掉再发出去。本系统回落到模板体——一段被系统改写过的模型文字，读的人
   分不清哪一句是模型的、哪一句是护栏补的，而**能被降级的东西本来就不该是结论**。
2. **判不了的时候不判。** `OutputGuard` 的三个读数都可能是 None（那一项今天没算
   出来），此时不判立场，同 §七「没数据 ≠ 中性」。给一个默认上限会让闸门凭空拦下
   正常文字。

否定词那一条借得最直接，但**没有照抄单字匹配**：中文里「不」在形容词前面根本不是
否定，「行情不错，可以满仓」按单字回看会被整句放行——而那正是最该拦的一句。所以
否定词是逐个列出来的封闭词表，并额外加了一条 DSA 没有的**风险语境前瞻**：空头
角色的正事就是提示风险，「追高风险极大」「重仓需谨慎」用的正是主张重仓时的那几个
词，而否定在这类句子里出现在词的**后面**。

### 2.2 运行诊断要是读数，不是散文 ★

**DSA 的做法**：`docs/run-diagnostics-p0.md` 定义 `RunDiagnosticSummary` ——
`trace_id` + `status`（ok/degraded/failed）+ 关键链路逐段状态（行情、日线、LLM
调用、报告落盘、通知投递）+ 脱敏后的原因，并写死三条边界：**fail-open**（诊断
写失败不能拖垮主流程）、**脱敏**、**retention**。

**本系统当时的状态**：降级信息全部是散文。`jobs/sources.py` 九路可选源、
`ask/context.py` 每一块落盘产出，缺了、旧了、关掉了，都只落一条中文 note。人读
没问题，但这份事实包**主要读者是另一个模型**，对它来说那句话和正文里任何一句没有
区别。最常见的错法长这样：

> 周一早上问「今天板块怎么排」，上一次跑 `morning` 是上周五。事实包照常给出完整
> 排序，模型照常按它回答，**两边都没有说错任何一句话**，只是那份排序描述的是三个
> 交易日之前的盘面。

**本轮实装**（`runhealth.py` + `ask/context.py`）：事实包多一个 `数据健康` 块，
逐块给出数据日期、落后了几个**交易日**、判定（当日 / 上一交易日 / 陈旧 / 缺失 /
读取失败），以及整体的正常 / 降级 / 未记录。

一处比 DSA 严的地方：**落后按交易日数，不按自然日**。按自然日会在每个周一早上误
报——上周五的数据到周一是 3 个自然日，但它就是上一个交易日的数据。节假日表缺失时
只排除周末，长假会被算多，那时读数里带一句「未经节假日校验」：说不准就说不准。

一处刻意不学的：**没有 `trace_id`**。DSA 要串起 Web 任务、后台 worker、通知重试
三条异步链路，本系统是单进程顺序跑批，一次跑批的 ID 就是那份产出的文件名。

### 2.3 组合层要有一层，单笔判断补不上它 ★

**DSA 的做法**：`src/services/portfolio_service.py`（1749 行）有完整的账户、
FIFO 成本、汇率、快照、持仓风险。本系统不接管账户，这一层的绝大部分不适用——但
它提醒了一件本系统真的缺的事：**只有单笔判断，没有把几笔加起来的那一层**。

**本系统当时的状态**：`monitor/holdings.py` 判止损 / 目标 / 结构破坏 / 时间止损 /
浮盈回吐，`strategy/positioning.py` 收口「单笔该给多少仓位」——每一笔都判得很细，
而「这三笔合起来是什么」没有任何地方回答。超短线里这恰恰最容易出事：三只票分属
三个代码，看起来是三笔分散的仓位，但它们可能挂在同一个题材上。那时它不是三笔，
是一笔重仓，回调来的时候三个止损会在同一根 K 线上一起触发。

**本轮实装**（`strategy/portfolio.py`）：权重（按金额，缺股数就退回按只数并说明
口径）、按行业与题材归并后的最大一块、计划完整度（哪几笔没有止损——那不是「还没
想好」，是**这笔仓位今天没有失效条件**）。接线点是 `position list` 与事实包的
持仓块。

三处边界写在模块 docstring 里，这里只提最重要的一条：**不报总仓位**。「仓位上限
0.30」说的是占账户总资金的比例，而这套系统只知道持仓表，不知道账户里还有多少钱，
也永远不该知道。拿持仓内部的权重去和周期上限比是个看起来对、实际错的数。

题材归并有一处是直接借 DSA 那边踩过的坑的反面：题材必须用
`SecurityMaster.themes()` 过滤后的那份。不过滤的话最大的一块永远是「融资融券」
（覆盖 69% 的市场，那是可交易属性不是题材）。

## 3. 值得记下、这轮没做的三处

| 机制 | DSA 在哪 | 为什么记下来 | 为什么这轮不做 |
|---|---|---|---|
| **跑批期的源级降级读数** | `src/services/run_diagnostics.py` 逐段记录成功/失败/降级 | 本轮只做了「事实包里每一块是哪天的」，**跑批当时哪一路源没答**仍然只有散文（`jobs/sources.py` 九路） | 主链路正在被另一轮改造拆分（`jobs/morning_*.py`），这一处要等那边落定再动，否则两边都改不干净 |
| **通知降噪** | `src/notification_noise.py`：去重 TTL、冷却、静默时段、最低严重级别，全部 fail-open | 本系统已有按标的×触发类型的冷却与板块噪声预算，但**没有静默时段与严重级别**——凌晨的非关键推送目前照发 | 本系统的推送只在盘中，且量级是每天几条；先补这个不如先看台账里有没有「被静音」的证据 |
| **无效观点必须单独收纳** | `docs/multi-strategy-contract.md`：Invalid Opinion 落 Diagnostics，**不得静默转成 hold 混进 Evidence Chain** | 同一个道理本系统已经在做（越界论证整段丢弃并留 note），但**没有写成契约**——将来 debate 加角色时容易漏 | 属于文档层面的固化，随下一次动 `agents/` 一起做 |

## 4. 不建议借的

- **让 LLM 产出数字。** DSA 的评分、目标价、买卖点位都由模型写出（`src/analyzer.py`
  20 万行的相当一部分在处理它写坏的情况）。本系统的分界线画在「谁能产生数字」和
  「谁能做取舍」之间（`DECISIONS.md` §六），往它那边走是退步。
- **多市场。** 港股/美股/日韩台的行情源、时区、交易日历、涨跌停规则各不相同，而
  超短这套打法（涨停池情绪周期、封板质量、连板高度）**只在 A 股成立**。加一个市场
  等于把主链路的每一个判据都变成带 if 的。
- **Web 工作台与桌面端。** 一个人用的系统，CLI + MCP 已经覆盖全部入口；Web 会带来
  认证、会话、CSRF、部署面这一整串本来不存在的问题。
- **社交舆情（Reddit/X/Polymarket）。** 超短周期里它的噪声远大于信号，和基本面
  权重同一个理由（见 `PEER_TRADINGAGENTS.md` §4）。
- **五百多项配置。** DSA 的 `.env.example` 有 5 万字符、`config_registry.py` 5087
  行——那是公开项目为覆盖成千上万种部署付的税。本系统的等价物是**把默认值定对**。

---

## 5. 一句话总结

DSA 值得借的是**「护栏要管措辞与立场，不能只管数字」**、**「降级要是读数，不是
散文」**和**「组合层要单独有一层」**这三条；不值得借的仍然是它把数字生产交给 LLM
的做法，以及为公开分发付出的那一整套工程税。三条本轮都已实装，实现按本系统的口径
重写——最明显的两处分歧是：越界**整段丢弃**而不是降级改写，陈旧**按交易日**判而
不是按自然日。
